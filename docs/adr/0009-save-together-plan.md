# ADR 0009: 같이 모으기와 둘의 월급 계획으로 방향 바꾸기(확인 한 번, 공개 단계, 내 데이터 남기기)

- 날짜: 2026-11-13
- 상태: 확정(2026-11-13 사용자 결정, 기획 v2.2 설계안 확정). ADR 0003, 0006, 0007의 일부를 고침(아래 ‘되돌리거나 고치는 이전 결정’). 고친 ADR에는 그 자리에 짧은 표시만 두고 원래 기록은 그대로 둠

## 맥락

- 페르소나 검증에서 줄마다 체크는 가치로 남지 않았다(필요도 3.2, 3개월 유지 약 19%). 남는 가치는 같이 모으는 저금 진행, 경조사 알림, 둘이 정한 월급 계획 한 장이었다.
- 고친 설계를 세 번 다시 검증했다. v2 재검증 필요도 5.5, 유지 약 44%(수정 F1~F12, 결정 R1~R4), v2.1 재검증 6.4, 약 53%(수정·결정 G1~G13). 이 ADR은 v2.2 설계안의 결정만 적는다. 화면·문구·계산의 정본은 `docs/spec`.
- 근거가 아직 시뮬레이션뿐이라 실제 휴대폰 빌드로 6~8쌍 사용성 테스트를 한다(→ `docs/spec/35-usability-test.md` V1~V10).

## 결정

1. 홈 주인공은 같이 모으는 저금(H-10 ‘같이 모으기’), 이번 달은 한 줄(H-11). H-02, H-03은 없앰(번호 다시 쓰지 않음). 날짜 없는 사람의 H-11 자리는 H-13, 결혼 준비 중이면 H-12 타일. → `19-this-month.md`
2. 월급날 확인은 한 번: 줄마다 ‘체크리스트에 넣기’(생활비·용돈 기본 끔)와 자동 줄(‘은행에서 자동으로 나가요’, 나가는 날 기본 월급날). 자동 줄은 그날 자동 확인, 손 줄만 “모두 계획대로 됐어요”. 손 줄이 없으면 월급날·월급 전 확인 알림 없음. → `07-month-cycle.md`, `20-salary-plan.md` W-02
3. 첫 확인 목록은 소급하지 않고 다음 월급날. 월급날이 정해지지 않은 사람은 확인 목록 없이 “돈 들어왔어요”와 30일 기간(직전 돈 들어온 날 기준) 막대(들어온 돈 / 필요한 돈, 생활비·용돈 포함, 16일째부터, 판정 문장 없음). → `07` 6장
   - 3-1. 손 줄이 없는 달은 월급날 ‘진행 소식’ 1회(금액 없음, 끌 수 있음). 저금이나 고정 줄을 만들 때 자동인지 한 번 묻는다(W-11e, W-01d).
4. 모은 금액 = 이미 모은 금액 + 확인한 저금(자동 확인 포함) + 돈 들어왔어요로 넣은 금액 ± 바로잡기. 바로잡기 사유는 본인만, 같이 모으는 것(묶음, 공동 저금)은 상대에게 사람·금액·사유 없이 한 줄. 지난 달 줄은 다음 달 끝까지 늦게 확인. 쓸 곳 메모 ‘냈어요’는 한 번 물어 바로잡기 −. 석 달에 한 번 실제 잔액과 맞추기를 권함(W-10c). → `06` 4장
   - 4-1. 다 모았거나 기한이 지나면 다음 저금을 권하고(W-12b), 기한이 있으면 남은 금액을 보여 준다(“…까지 n원 더 필요해요”).
5. 각자 엔진에서 같이 모으기 묶음(W-15): 합계만 기본, 각자 금액은 두 사람 모두 켰을 때, 선택 ‘퍼센트만 보여 주기’(하나라도 켜면 둘 다 %). 합계로 상대 몫을 짐작할 수 있음을 숨기지 않고 알린다. 합쳐서 엔진에는 묶음이 없다(저금이 이미 공동).
6. 관리 형태는 세 질문(같이 쓰는 생활비 O-30, 같이 모으는 저금 O-30b, 누가 관리 O-30c)으로 묻고 엔진(각자/합쳐서 + 관리하는 사람 `manager_user_id`)으로 옮긴다(`08` 2장 표, core `resolveManageStyle`). 미리 고른 값 없음(‘기본 각자’ 없앰).
7. 각자 계열의 내 월급 계획 공개 3단계(모두 / 저금만(기본) / 했어요만), 공개 설정은 S-13 한 곳, 상대에게 보이는 모습 미리 보기(S-13p). 저금마다 공개 설정은 없앰. 월급 없이 합류 가능.
8. 한 사람 관리형에서는 관리하는 사람도 관리하지 않는 쪽 용돈을 고치고 주인에게 알린다(합류 때 P-05c에서 고지). ‘보내기’는 월급 − 용돈으로 자동이고 직접 고치지 않는다.
   - 8-1. **‘제안·승인 없음’의 예외 둘**(이름으로 못 박음): (가) 각자 → 합쳐서가 되는 관리 형태 변경(관리하는 사람을 상대로 넘기는 것 포함)은 상대 수락(S-11j), 거절·7일 만료면 그대로. (나) 분담 도우미(W-01b → W-01c)는 한 사람 제안 → 상대 ‘좋아요’로 정함. 그 밖은 모두 ‘바로 고치고 알림 + 되돌리기’. 순위 같이 보기 동의(결정 11)는 고치기 승인이 아니라 개인정보 사용 동의라 이 예외에 넣지 않는다.
9. 해제·탈퇴: 내 명의 자산·부채, 내 저금과 내역, 내 월급(각자 계열 월급 계획)은 남기고 같이 쓰던 것만 지움. 요청 즉시 요청한 사람의 개인 데이터는 상대에게서 가림. 30일 재연결 복구는 미루고 ‘다시 연결하기’는 복구 없는 새 연결 요청(7일에 1번, ‘다시 받지 않을게요’). → `08` 7·8장
10. 알림 프라이버시: 각자 계열의 월급 계획·월급 변경은 상대에게 알리지 않음, 잠금 화면에 금액·관계 상태 없음, 알림 종류를 처음부터 골라 켬(P-11, S-14). → `14-notifications.md`
11. 보상형 광고는 출시와 함께. 첫 순위 결과 무료, ‘새로 확인하기’만 광고, 금융 광고 카테고리 차단, 비맞춤형만(ATT 묻지 않음), 홈 순위 배지 기본 끔. 순위는 두 사람 모두 동의할 때만 ‘둘의 합’을 연령대 가구 통계와 비교, 아니면 “또래 가구 중간값은 …이에요” 한 줄. ‘내 몫’ 비교는 없음. → `23-assets.md` F-08, F-08c
    - 11-1. 자산 공개 범위는 처음 한 번 직접 고른다(미리 고른 값 없음). 그 답이 내 새 항목 기본값.
12. 앱 잠금 PIN은 권장하되 건너뛸 수 있다(기기 잠금 전제, A-06은 O-60 흐름 뒤). → `15`, `31`
13. 결혼 준비(H-12, 쓸 곳 메모 W-14), 관계 4지선다(O-11)와 사귄 날, 분담 제안, 날짜를 정한 월급 변경(S-11c “언제부터”, 선택 “언제까지”), 자산 빠르게 적기(F-03q)와 평가금액 기준, 위젯(WG-01, WG-04)과 초대 코드 자동 입력(L-07)을 v1에 넣는다.
14. 사용자 화면에는 ‘약속’을 쓰지 않고 ‘월급 계획’. ‘약속’, ‘자동 줄’, ‘손 줄’, ‘묶음’, ‘공개 단계’, ‘관리 형태’는 기획서 안 말.
15. 북극성은 ‘이번 달 같이 모은 커플 수’(→ `32-success-metrics.md`).

## 고른 대안

- 순위 ‘내 몫’ 비교(v2.1): 개인 몫을 가구 통계와 비교해 믿기 어려움(G3-B)
- 날짜 없음 ‘모자라요’ 한 줄(v2.1): 생활비가 빠지고 달 끝에야 보임(G8-B)
- 잔액 맞추기 없음(G7-B), 월급 변경 출시 후(G12-B)
- 체크리스트 중심 유지, 결혼 준비 특화 앱, 실제 공동 저금(D4-B)
- O-30 생활 방식 3지선다 한 질문(v2): 실제 형태와 안 맞아 버림(F4)
- 묶음 각자 금액 기본 공개(v2): 비교 부담(F5)
- 분담 즉시 적용(v2): 소득 노출과 일방성(F6)
