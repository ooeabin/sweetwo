# 보안·개인정보

입력 데이터는 모두 수기, 계좌·카드 연동 없음. 다루는 것은 부부가 직접 적은 금액·메모·가족 정보뿐이고, 원칙은 ‘적게 받고, 서버에서 거르고, 나갈 때 깨끗이’임. 이 탭은 지켜야 할 기준만 정함: 구현은 → 기술·운영, 출시 전 할 일은 → 출시 준비. 공개 범위·권한은 → 핵심 규칙 › 부부·권한, 수집 항목은 → 핵심 규칙 › 데이터 항목.

## 1. 다루는 데이터와 민감도

| 데이터 | 민감도 | 보관 | 공개 범위 |
| --- | --- | --- | --- |
| 계정 (로그인 수단·소셜 계정 식별자, 알림 이메일, 이름이나 애칭, 결혼 상태) | 중 | 서버. 탈퇴 후 3장 기준 | 배우자에게 이름(애칭)만. 생년월일(월·일)은 받지 않음(나이 확인은 5-1) |
| 출생연도 (O-13, 합류 P-03a) | 중 | 서버. 탈퇴 후 3장 기준 | 본인만 [확인 필요]. 비슷한 부부와 비교의 연령대 계산에만 씀(통계 참여를 켰을 때만 통계에 들어감), 나이 확인에는 쓰지 않음 |
| 결혼한 날·예정일 (O-12) | 중 | 서버 | 부부 공유(부부 공간 값). 결혼기념일 챙길 날 자동 등록, 비슷한 부부와 비교의 결혼 단계 계산에 씀 |
| 프로필 사진 | 중 | 서버 Storage 서울(저장 시 암호화). 정사각 512px로 줄이고 EXIF 위치 정보 제거 후 저장, 원본 보관 안 함 | 같은 부부 공간 2명만. 바꾸기·지우기는 본인만 |
| 수입 (월 실수령, 매달 다른지 여부, 월급날, 기간 수입 변경 [확인 필요]) | 높음 | 서버 + 기기, DB 전체 암호화 + RLS | 부부 공유 (합쳐서 관리는 분배표 수입, 각자 관리는 배우자 분배표 보기에 필요) [확인 필요]. 바뀌면 상대에게 알림 |
| 자산·부채 (금액, 잔액, 금리, 만기, 이력) | 높음 | 서버 + 기기, DB 전체 암호화 + RLS | 항목별: 공동 = 모두 보여 주기, 개인 = 금액만 보여 주기 기본 |
| 월급 분배표·체크리스트 (용돈 줄 포함) | 높음 | 서버 + 기기, DB 전체 암호화 + RLS | 부부 공유. 각자 관리여도 배우자 것은 보기만 + ‘대신 체크’(→ 월급 체크리스트) |
| 목표 (모은 돈 포함) | 중 | 서버 + 기기 | 모두 보여 주기 (공동 항목) |
| 챙길 날·메모·사진 | 중 | 메모 서버(필드 암호화), 사진 서버 Storage(저장 시 암호화, 부부 공간 권한으로 두 사람만 열람) | 모두 보여 주기 |
| 양가 가족 정보 (호칭, 생일, 태어난 해, 메모) | 높음 (제3자) | 서버 + 기기, 필드 암호화(생일 포함). 부부 공간 밖 반출 금지 | 모두 보여 주기 (부부 공간 안). 챙길 날을 한 종류로 합치며 가족 등록을 남길지 [확인 필요] |
| 배우자 정보 (합류 전 내가 적은 배우자 명의 자산·부채) | 높음 (제3자) | 서버, ‘추정’ 표시 | 합류 시 배우자 본인 확인·동의 후 확정 (5장) |
| 결제 기록 (구독) | 중 | 결제대행사 + 서버 (카드번호 미보관) | 결제한 사람만 |
| 접속 기록 (로그인 기기, IP, 시각) | 중 | 서버 | 본인만 (S-15 로그인된 기기 목록) |
| 분석 이벤트 | 낮음 | 분석 도구, 금액 원값 없음 (6장) | 해당 없음 |

- 수집 안 함: 계좌번호, 카드번호, 주민등록번호, 공인인증서·금융사 비밀번호
- 공개 범위 필터는 서버에서 적용, 배우자 기기로는 공개 범위에 맞는 값만 내려감

## 2. 보안 기본

| 영역 | 기준 |
| --- | --- |
| 전송 | TLS 1.2 이상(가능하면 1.3), HSTS. 데스크톱 앱은 서버 인증서 고정(pinning) 검토 |
| 서버 저장 | DB·백업 전체 암호화 + 메모·가족 정보만 필드 단위 암호화(범위는 아래 행). 키는 부부 공간별 데이터 키, 키 관리 서비스에 분리 보관 |
| 필드 암호화 범위 | 종단간 암호화 안 함(서버가 공개 범위 필터·합계·알림 계산). DB·백업은 전체 암호화. 금액은 DB 암호화 + 행 단위 권한(RLS)으로 보호하고 합계·배분은 DB가 계산. 필드 암호화는 메모·가족 정보(생일 포함)만. 항목명·날짜는 DB 암호화만 |
| 기기 저장 | 로컬 DB 암호화, 키는 OS 키 저장소(Windows 자격 증명 관리자, macOS·iOS 키체인, Android Keystore). 로그아웃 시 로컬 데이터 삭제 |
| 로그인 | 소셜 로그인만: 카카오·구글·애플(네이버는 이후 검토). 비밀번호를 받거나 저장하지 않음. 데스크톱은 기본 브라우저, 모바일은 시스템 로그인 창(ASWebAuthenticationSession, Custom Tabs)에서 로그인 후 딥링크·앱 링크로 앱 복귀(앱 안 웹뷰로 로그인하지 않음). 인가 코드 교환은 PKCE + state 검증, 딥링크 결과는 그 기기가 시작한 요청일 때만 처리. 같은 이메일이라도 다른 소셜 수단 계정은 자동으로 합치지 않음 |
| 토큰·세션 | 제공자 토큰은 로그인 확인에만 쓰고 보관 안 함. sweeTwo 세션 = 짧은 접근 토큰 + 기기별 갱신 토큰. 데스크톱·모바일 모두 OS 키 저장소에 보관, 갱신 토큰 30일(쓸 때마다 연장). 앱 화면은 강한 CSP(인라인 스크립트 금지, 허용한 출처만). 로그아웃·기기 로그아웃·계정 삭제 시 갱신 토큰 즉시 폐기 |
| 계정 복구 | 같은 소셜 계정으로 다시 로그인. 소셜 계정을 잃은 경우 고객 문의 → 어드민 본인 확인 후 로그인 수단 이전(→ 어드민 화면 AD-05) |
| 앱 잠금 | S-15: PIN 6자리, 생체 인증(macOS Touch ID, iPhone Face ID·Touch ID, Android 지문·얼굴. Windows Hello는 네이티브 모듈이 필요해 출시 뒤), 자동 잠금 1·5·15분·사용 안 함. 기본 5분. PIN 5회 실패 시 재로그인. PIN 설정: 이 기기에 PIN이 없으면 첫 로그인 직후 1회(A-06, 신규 가입·새 기기 동일), ‘나중에 할게요’면 할 일 |
| 화면 금액 가리기 | 눈 아이콘으로 모든 금액 “•••”, 앱 잠금·앱 전환 미리보기는 자동 가림(→ 화면 설계 › 공통) |
| 위젯 | 금액 기본 가림, 위젯 캐시는 기기에 암호화 저장·로그아웃 시 삭제 → 화면 설계 › 위젯 |
| 모바일 앱 보호 | 앱 전환 화면(최근 앱)에서 금액 가림, 루팅·탈옥 기기는 막지 않고 S-15에 안내 1줄 [확인 필요]. 스크린숏은 막지 않음. 화면 코드는 앱 안에 묶어 넣고 원격 코드를 내려받아 실행하지 않음 |
| 새 기기 로그인 알림 | 새 기기 로그인 시 이메일 + 기존 기기 푸시(모바일 푸시, OS 알림): “새 기기에서 로그인했어요. 본인이 아니면 바로 로그아웃해 주세요”. 메일 상한(월 6회) 밖 |
| 기기 관리 | S-15 로그인된 기기 목록에서 기기별 로그아웃, ‘모든 기기에서 로그아웃’ |
| 관리자 접근 | 운영자는 기본적으로 금액·메모 열람 불가. 문의 처리 시 문의한 본인 동의 + 기한 있는 권한만(배우자에게는 열람 사실 알림), 모든 열람은 접근 로그(누가·언제·무엇) 남기고 1년 보관 |
| 백업 | 서버 일 1회 암호화 백업, 30일 보관, 복구 훈련 분기 1회. 사용자 쪽은 내보내기(CSV/PDF, S-18)만, 백업 파일·불러오기 없음 |
| 앱 무결성 | 코드 서명·공증(→ 기술·운영 5장), 자동 업데이트는 서명 검증 후 설치, 오류 리포트에 금액·메모 제외 |

## 3. 계정·데이터 권리

### 3-1. 데이터 내보내기 (S-18)

| 형식 | 내용 | 범위 |
| --- | --- | --- |
| 엑셀(CSV) | 항목별 시트(시트·컨럼 → 화면 설계 › 설정 S-18 ‘내보내기 명세’). 사진은 빠짐 | ‘내 데이터’ = 내 명의 항목 + 내가 쓴 메모·기록 / ‘공동 데이터’ = 공동 항목·목표·분배표·체크리스트 |
| PDF 요약 | 연간 요약(목표, 월급 체크리스트, 순자산) [확인 필요] | 같은 범위 선택 |

- 배우자 개인 항목은 공개 범위대로만 포함 (금액만 보여 주기 → 합계 한 줄, 숨기기 → 없음)
- 내보내기 전 본인 확인(PIN 또는 재로그인), 파일에 생성일 표시
- 연결 해제(S-12a·S-12d ‘먼저 내보내기’)·계정 삭제 흐름의 ‘내보내기 권장’ 버튼은 이 화면으로 연결

### 3-2. 계정 삭제 (S-18 계정 삭제 흐름 기준)

- 유예 30일: 삭제 요청 즉시 로그아웃·이용 중지, 30일 안에 다시 로그인하면 “계정 삭제를 취소할까요?”로 복구. 복구하면 ‘혼자 쓰기’로 돌아오고 30일 안 재연결 가능, 상대에게 ‘계정 복구’ 알림. 30일 후 서버 완전 삭제 (기기 로컬 데이터는 요청 즉시 삭제)
- 프로필 사진은 삭제 요청 즉시 서버에서도 삭제(30일 유예 대상 아님)
- 구독 중이면 해지 안내 먼저 (S-18 흐름 2단계)

| 부부 상태 | 처리 |
| --- | --- |
| 미합류 / 혼자 쓰기 | 부부 공간 전체 삭제. 미합류 상태에서 미리 적은 배우자 관련 입력도 함께 삭제, 미사용 초대 코드 만료 |
| 연결 | 내 명의 항목만 삭제, 공동 항목은 상대 공간에 남음(S-18). 상대는 ‘혼자 쓰기’로 전환 + 알림 “{이름}님이 계정을 삭제했어요. 이제 혼자 쓰기로 이어져요” |
| 해제 대기 | 해제가 확정된 것과 같게 처리: 같이 쓰던 데이터 모두 지움(30일 복구용 보관 없음), 상대는 혼자 쓰기로. 삭제 전 “같이 쓰던 데이터도 모두 지워져요” [확인 필요] 확인 |

### 3-3. 탈퇴 후 보관

- 원칙: 30일 후 완전 삭제(합류하며 기록을 옮긴 혼자 공간도 같음, 그동안 내보내기 가능), 백업은 백업 보관 기간(30일) 지나면 자연 소멸
- 법정 보관 (분리 보관, 이용 불가, 출시 전 법률 검토):

| 항목 | 근거 | 기간 |
| --- | --- | --- |
| 계약·청약철회 기록, 대금 결제 기록 (구독) | 전자상거래법 | 5년 |
| 소비자 불만·분쟁 처리 기록 | 전자상거래법 | 3년 |

## 4. 연결 해제 시 데이터 처리

해제 절차·혼자 쓰기 전환은 → 핵심 규칙 › 부부·권한 7장, 설정 S-12 그대로. 2026-10-26 결정: 같이 쓰던 데이터는 나누지 않고 모두 지움. 여기서는 무엇이 남고 얼마나 보관하는지만 정함.

| 데이터 | 해제 확정 뒤 |
| --- | --- |
| 계정 (로그인 수단, 이름, 알림 이메일, 알림 설정, 동의 기록) | 두 사람 모두 남음 |
| 프로필 사진 | 본인 계정에 남음 [확인 필요]. 상대 화면에서는 해제 확정 시 사라짐(해제 대기 중에는 그대로) |
| 부부 공간 데이터: 목표(우리 목표, 내 목표), 분배표, 체크리스트, 자산·부채(내 명의, 상대 명의, 공동 명의 모두), 챙길 날, 가족 정보, 사진, 활동 기록·변경 이력, 알림 기록, 휴지통 | 모두 지움. 나누거나 한쪽에 사본을 남기지 않음. 확정 순간부터 두 사람 모두 볼 수 없음 |
| 복구용 보관 | 지운 부부 공간 데이터는 서버에 확정 후 30일만 보관(사용자·운영자 열람 불가, 다시 연결할 때만 씀). 30일이 지나면 영구 삭제, 백업은 백업 보관 기간(30일) 지나면 자연 소멸 [확인 필요] |
| 구독·결제 기록 | 결제한 사람 계정에 남음(법정 보관 → 3-3) |

- 해제 대기 중(요청\~확정): 공개 범위는 그대로. 할 수 있는 것 → 핵심 규칙 › 부부·권한 1장 ‘해제 대기’
- 지우기 전 내보내기: S-12a·S-12d의 ‘먼저 내보내기’ → S-18(3-1). 확정 뒤에는 내보낼 수 없음
- 서버가 확정 순간 부부 공간 접근 권한을 즉시 회수, 다음 동기화 때 두 사람 기기 로컬 데이터·위젯 캐시 삭제(오프라인 기기는 다시 연결되는 즉시)
- 30일 안 재연결(S-12 “다시 연결하기” → 상대 S-12g 수락) 시 보관한 해제 전 데이터 복구, 30일 지나면 복구 불가(→ 핵심 규칙 › 부부·권한 8장)

## 5. 법·고지

### 5-1. 수집·이용 동의 (개인정보 보호법 기준)

동의 종류는 8종: 이용약관, 개인정보 처리(아래 필수 항목 묶음), 배우자와 부부 공간 공유, 가족 정보, 사진(챙길 날), 마케팅 수신, 분석 수집, 통계 참여. 프로필 사진은 별도 동의 없음(5-3 고지). 같은 8종을 로그인·가입 A-05, 데이터 항목 ‘동의 기록’, 기술·운영 consent 표가 씀

### 5-2. 배우자 정보 = 제3자 정보

- 미합류 상태에서 내가 적은 배우자 명의 항목(자산·부채)은 배우자 본인 동의 전 정보. 배우자 월급은 합류할 때 본인이 직접 넣음
- 합류 시 P-02b(사전 입력 확인·동의)에서 배우자 본인이 확인
  - “{이름}님이 미리 적어 둔 내 정보가 있어요” + 항목 목록
  - 선택: “확인하고 이어 쓸게요” → 본인 항목 확인 후 그대로 사용 / “지우고 새로 입력할게요” → 해당 항목 삭제 후 본인 입력
- 상대 명의 대신 입력은 합류 전에만(‘대신 입력’ 표시). 합류하면 P-02b 확인 후 소유가 배우자에게 넘어가고, 합류 뒤에는 상대 명의 새로 만들기 불가(→ 핵심 규칙 › 부부·권한)
- 초대 7일 만료 후에도 합류 안 하면 미리 적은 배우자 정보는 계속 ‘추정’ 표시, 공간 삭제 시 함께 삭제
- 양가 가족 정보: 부부 공간 밖 반출 금지, 처리방침에 명시

### 5-4. 규제 판단 (출시 전 법률 검토)

- 계좌·카드 연동 없음, 금융사 데이터 수집 없음 → 마이데이터(본인신용정보관리업) 대상 아닌 것으로 판단
- 금융상품 추천·중개·자문 없음 → 금융소비자보호법상 판매·자문업 해당 없음으로 판단. 전문가 연결(→ 사업 계획 4장 ‘이후’)은 예약 중개만, 상담 내용 관여 없음
- 수입·자산 정보가 신용정보법상 신용정보에 해당하는지, 결혼 정보가 민감정보에 해당하는지 확인
- 비슷한 부부와 비교(출시 후): ‘통계 참여’ 동의 문구, 그룹별 백분위 표가 가명·익명 처리에 해당하는지, 위 신용정보·민감정보 해당 여부와 함께 확인
- 프로필 사진 고지 방식: 별도 동의 없이 처리방침 선택 수집 항목 + S-11e 고지 한 줄로 충분한지 확인
- 분석 수집 기본 켜짐(설정에서 끄는 방식): 가명 처리·금액 원값 없음 조건으로 별도 동의 없이 고지만으로 충분한지 확인
- 개인정보 보호책임자 지정, 처리방침 공개

## 6. 분석 이벤트 원칙

- 금액 원값 수집 안 함, 구간만: 예) 월 실수령 ‘300\~400만 원’, 목표 금액 ‘1천만\~3천만 원’
- 항목명·메모·가족 호칭·사진 수집 안 함. 이벤트에는 화면 ID·선택지 ID·소요 시간만
- 사용자 식별자는 가명 ID, 부부 공간 ID도 가명 처리
- 분석 수집은 처리방침 위탁 항목에 명시. 기본 켜짐, 설정 S-18(데이터) 토글 하나로 끄기 가능
- 비슷한 부부와 비교 통계는 분석 도구가 아니라 서버 배치로 계산. 그룹별 백분위 표만 저장, 개별 부부 값은 통계 테이블에 넣지 않음, 100쌍 미만 그룹은 표시 안 함(→ 핵심 규칙 › 계산·배분 7장)
- 웹사이트(sweetwo.kr)는 쿠키 없는 측정이라 동의 배너 없음. 법무 확인 필요(→ 성공 지표 4-8)
- 지표·이벤트 정의 → 성공 지표
