### 구현 메모 (PR 11, 2026-11-13)

- 주소: S-11f `/settings/couple/style`(서버 알림 링크와 같음), S-11j `/settings/couple/style/request/{요청 id}`, S-13p `/settings/visibility/preview`. S-11 ‘월급 관리 방식’ 줄 값은 짧게 “같이 써요” / “각자 써요” / “{이름}님이 관리해요”, 내가 관리하면 “내가 관리해요”(2026-11-23, 엔진 값만 봄)
- S-11f: 세 질문의 처음 값은 지금 답(옛 공간은 엔진 값에서). 바뀐 게 없으면 저장 비활성 + “지금과 같아요”. 상대 ‘좋아요’가 필요하면 저장 버튼 위 “{이름}님이 ‘좋아요’를 누르면 바뀌어요”, 저장 → Toast “{이름}님에게 물어봤어요” → S-11. 바로 적용이면 Toast “월급 관리 방식을 바꿨어요” + ‘되돌리기’(되돌리는 쪽도 상대 답이 필요하면 ‘되돌리기’ 없음) → W-01. 상대가 보낸 요청이 있으면 맨 위 회색 “{이름}님이 보낸 요청이 있어요” + ‘확인하기’ → S-11j. 요청 취소 Toast “요청을 취소했어요”
- S-11j: 관리하는 사람을 상대에게 넘기는 요청(S-11f, 이미 합쳐서)의 제목은 기획 문구가 없어 “{이름}님이 월급 관리를 {나}님에게 맡기고 싶어 해요”, 바뀌는 것 “{나}님이 월급 계획을 관리해요”. 둘이 같이 합치기면 둘째 줄 “용돈은 사람마다 한 줄씩 남아요”. 만료면 “요청 기한이 지났어요”, 없거나 이미 답한 요청이면 “지금은 받은 요청이 없어요” + ‘확인’ → 홈. ‘좋아요’ → Toast “월급 관리 방식을 바꿨어요” → W-01, ‘지금처럼 할게요’ → 홈
- S-11c: 공개 고지는 지금 공개 단계대로 “파트너에게는 저축·투자만 보여요” / “파트너에게는 월급 계획이 모두 보여요” [확인 필요] / “파트너에게는 이번 달 했는지만 보여요”, 같이 계열 “월급을 합쳐서 쓰면 파트너도 이 금액을 봐요”(‘바꾸기’ 없음). 합류 전이면 고지 없음. 금액이 바뀌었을 때만 2단계(주 버튼 ‘다음’), 월급날·매달 달라요만 바뀌면 바로 저장. ‘지금은 월급이 없어요’도 0원 금액 변경으로 같은 2단계. 시작 달 오류 “이번 달부터 고를 수 있어요” [확인 필요], 끝 달 오류 “시작하는 달부터 고를 수 있어요” [확인 필요]. 미래 예약 Toast “2027년 3월부터 바꿀게요” [확인 필요] + ‘되돌리기’(예약 취소), 이번 달은 그 달 월급날 전이어도 바로 적용(2026-11-13 사용자 결정 P2 = A, 07 5장) + “월급을 바꿨어요” + ‘되돌리기’(옛 금액으로 이번 달 다시). S-11 예약 줄에 끝 달이 있으면 “… 2027년 6월까지” [확인 필요], 취소 Toast “월급 변경을 취소했어요” [확인 필요]
- S-13: ③ 기본값이 아직 없으면 줄 오른쪽 “아직 안 골랐어요”(고르는 곳은 F-03e). ④ 보조 “두 분 모두 켜면 둘의 합으로 순위를 봐요”, 켜면 F-08c(동의 보내기, `/assets/rank/consent`), 끄면 바로 `set_rank_consent(false)`, 요청 중 보조 “{이름}님 답을 기다려요”. 맨 아래 회색 “경조사, 공동 명의, 합쳐서 쓰는 월급 계획과 저축·투자는 늘 같이 봐요”. S-10 공개 범위 줄 값 = ① 단계 이름(같이 계열은 “모두”, 2026-11-16 이름표와 붙던 긴 글을 줄임. 이 화면 S-13 안 안내는 “월급을 합쳐서 쓰고 있어 모두 보여요” 그대로)
- S-13p(사실대로): 월급 계획은 서버 필터 그대로. 같이 모으기·자산은 상대가 실제로 받는 값. 저금: ‘모두’·‘저축·투자만’이면 저금 이름·목표 금액·모은 금액이 상대에게 보임, ‘했어요만’이면 서버가 이름·금액을 주지 않아(2026-11-13 사용자 결정 P1 = A, 08 6장) 줄마다 “개인 저축·투자” + “이번 달 했어요” / “아직이에요”. 묶음에 넣은 내 저금 금액은 두 사람 모두 ‘각자 모은 금액 보여 주기’이고 둘 다 ‘했어요만’이 아닐 때만. 자산 ‘총액만’은 종류별 “{종류} {n}개” 합계(partner_asset_sums). 섹션 이름 ‘같이 모으기’ / ‘월급 계획’ / ‘자산 관리’, 비면 “보이는 게 없어요”, 해제 대기면 “연결 해제 대기 중이라 지금은 아무것도 보이지 않아요”, ‘했어요만’ 회색 “{나}님은 이번 달 했는지만 보여 줘요”, 확인 안 한 저금 줄 “아직이에요” [확인 필요]

## 규칙

- 가이드는 별도 메뉴 없음: 설정 › 가이드 모아보기(S-01)와 각 화면 ‘알아보기’ 링크로 진입

- 불러오는 동안(2026-11-04): 하위 화면은 빈 화면 대신 맨 위 “‹ 제목” 자리 뼈대 + 카드 뼈대(0.3초 넘게 걸릴 때만) → 공통 › 공통 상태 5번

- 좁은 창 설정 하위 화면(S-01~S-03, S-11~S-22 중 질문 화면이 아닌 것): 2026-11-04 앱 머리 없이 맨 위 “‹ 제목” 한 줄(제목 가운데). 설정 홈(S-10)은 2026-11-09부터 홈 밖 메뉴 첫 화면과 같은 좁은 창 머리: 왼쪽 ‹(홈으로) + 가운데 제목 “설정”(2026-11-17), 오른쪽 버튼 없음. 좁은 창에서 설정은 홈 머리 설정 톱니(S-10, 2026-11-16 서랍에서 머리로 되돌림. ‘내 정보’(S-11)는 설정 홈 맨 위 줄로 들어옴)와 ☰ 메뉴 서랍의 ‘초대하기’(S-12, 합류 전·혼자 쓰기만), ‘도움말’(S-20, 2026-11-16 서랍 ‘문의’를 없애 문의 S-19a는 도움말 안에서)로 들어옴. 서랍에 ‘설정’·‘내 정보’·‘우리 둘’ 줄은 없음(‘우리 둘’은 2026-11-16부터 설정 홈 S-10 줄, 넓은 창 사이드바에는 처음부터 ‘우리 둘’ 탭이 없어 같은 길). 하단 탭 막대는 앱 전체에서 없앰(2026-11-09). 넓은 창은 큰 “설정” 제목 없이 ‘‹ 설정’ + 제목(상세 화면과 같음). 설정 홈(S-10)은 앱 머리와 탭 막대 그대로

- 소셜 계정 프로필 사진은 **그 계정에서 사용자가 직접 지정한 사진일 때만** 가져옴. 구글의 글자 원(기본 이미지), 카카오 기본 이미지처럼 제공자가 기본으로 주는 이미지는 가져오지 않고 우리 글자 아바타(닉네임 앞 최대 3자, 공통 Avatar)를 씀. 계정이 준 사진 주소(`user_metadata.avatar_url`·`picture`)는 화면에서 직접 쓰지 않음. 앱이 보여 주는 사진은 우리 저장소 `avatars/` 사진뿐(없으면 글자 아바타, 외부 이미지 출처 없음)
- 구분 방법: 주소 모양만으로는 구분할 수 없어, 로그인 직후 세션의 제공자 토큰(`provider_token`, 구글·카카오만, 앱 메모리에만 두고 한 번 쓰면 지움)을 Edge Function `social-avatar`에 넘김. 함수가 그 사용자 토큰으로만 제공자 API를 불러 확인(함수 비밀 값 없음): 구글 People API `people/me?personFields=photos`의 대표 사진(`metadata.primary`)의 `default`가 `true`이면 기본 이미지, 카카오 `/v2/user/me`의 `kakao_account.profile.is_default_image`가 `true`이면 기본 이미지(응답 필드는 구글 People API `Photo.default`, 카카오 사용자 정보 문서 기준). 직접 지정한 사진이면 허용한 주소(`*.googleusercontent.com`, `*.kakaocdn.net`, https)에서만 받아 돌려줌
- 가져오는 때: 우리 둘 공간이 생긴 뒤(혼자 쓰기 포함) 앱 틀이 처음 열릴 때 **한 번만**, 아바타가 비어 있고 앱에서 사진을 바꾼 적이 없고(올림·지움 포함) 아직 시도하지 않았을 때(`app_user.avatar_path` 비어 있음, `avatar_social_checked_at` 비어 있음, 서버 함수도 같은 조건을 다시 확인). 직접 올린 사진과 똑같이 정사각 512px로 가운데를 잘라 줄이고 다시 그려(EXIF 위치 정보 없음) `avatars/{공간}/{사람}.jpg`로 저장. 원본 주소와 제공자 토큰은 저장하지 않음
- 가져오지 않는 경우(글자 아바타 그대로): 애플 로그인(사진을 주지 않음), 소셜 계정에 사진이 없음, 기본 이미지, 제공자 토큰이 없음(앱을 다시 실행해 로그인 직후가 아님), 제공자 API 호출 실패, 동의하지 않음, 이미 사진이 있음, 사진을 불러오지 못함. 오류는 사용자에게 보이지 않음
- 한 번 시도하면(가져왔든 못 가져왔든) 다시 시도하지 않음. 사진을 지우거나 바꿔도 소셜 사진으로 되돌아가지 않고, 소셜 계정 사진을 바꿔도 따라 바뀌지 않음 [확인 필요]
- 가져올 때 알림, 파트너 활동, Toast 없음
- 이미 예전 방식으로 가져와 저장된 소셜 사진(기본 이미지 포함)은 직접 올린 사진과 구분할 수 없어 그대로 둠(데이터를 지우지 않음). 본인이 ‘사진 지우기’로 글자 아바타로 바꿀 수 있음
- 카카오 동의 항목: ‘프로필 사진’ 선택 동의(동의하지 않으면 가져오지 않음), 동의 목적 “내 프로필 사진으로 쓰기”(2026-11-06)

## S-21 휴지통

‘삭제’로 보낸 항목(자산·부채 F-04, 저금 항목 W-10 등)을 30일 보관하는 화면. 보내기는 묻지 않고 바로 + Toast “되돌리기”, 영구 삭제만 Modal 확인.

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 안내 | “지운 항목은 30일 뒤 완전히 지워져요” | 목록 위 1줄 |
| 2 | 항목 줄 | “청약 통장” + 작은 이름표 ‘자산’ / “10월 3일에 지웠어요” + 작은 흐린 “22일 남음” + 지운 사람 Avatar | 최근 지운 순. 휴지통 항목은 합계·순자산·월급 계획 계산에서 빠짐 |
| 3 | 되살리기 | “되살리기” | 묻지 않고 원래 자리로 + Toast “되살렸어요”, “되돌리기”. 같이 지워진 항목도 함께, 연결 대상이 없으면 연결 없이 되살리고 “원래 함께 있던 항목이 없어 이것만 되살렸어요”(→ 데이터 항목 ‘삭제 연결 처리’). 저금 항목을 되살리면 월급 계획 저금 줄도 다시 생김(금액은 지우기 전 금액인지 0원인지 [확인 필요]), 파트너와 연결된 상태면 상대 알림(→ 핵심 규칙 › 커플·권한 4장) |
| 4 | 영구 삭제 | ⋯ → “영구 삭제”(맨 아래 빨간 글자) | Modal “완전히 지울까요?” / “되돌릴 수 없어요” + “지울게요”, “취소” |
| 5 | 비우기 | “휴지통 비우기” | Modal “{n}개를 완전히 지울까요?” + “지울게요”, “취소” |

- 30일 지나면 자동 영구 삭제, 알림 없음
- 내 명의·공동 항목만 보임. 파트너 명의 항목은 파트너 휴지통에만
- 저장 필드(삭제 시각·지운 사람) → 핵심 규칙 › 데이터 항목

예외·오류

- 빈 상태: “휴지통이 비어 있어요”
- 오프라인: 영구 삭제(⋯)·비우기 비활성 + 비우기 위 “인터넷에 연결되면 할 수 있어요”(2026-11-12)

## S-22 위젯

위젯 설정. 2026-11-10 데스크톱 앱과 함께 화면을 없앰(ADR 0008). 모바일 홈 화면 위젯(26 WG-01~05)이 나오면 2·3번으로 다시 만듦. 예전 진입: S-10 ‘위젯’ 줄, 트레이 아이콘 오른쪽 클릭 ‘위젯 설정’. 위젯 규칙·화면 → 화면 설계 › 위젯.

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 트레이 아이콘 (없앰 2026-11-10, ADR 0008) | “트레이 아이콘” / “앱 창을 닫아도 트레이에 남아요”, 기본 켜짐 | 데스크톱만. 끄면 트레이 위젯 창도 없음 |
| 2 | 위젯에 금액 보이기 | “위젯에 금액 보이기”, 기본 꺼짐 | 기기마다 따로. 가림 규칙 → 화면 설계 › 위젯 |
| 3 | 저금 항목 고르기 | “위젯에 보일 저축·투자” / 오른쪽 “제주 여행” | 누르면 목표 금액이 있는 저금 항목 목록(좁은 창은 BottomSheet)에서 1개. 기본 = 홈 H-02 순서 첫 항목. WG-02·WG-04에 반영 |

예외·오류

- 목표 금액이 있는 저금 항목이 없으면 3번 오른쪽 회색 “저축·투자가 없어요”, 누르면 → W-11
- 고른 저금 항목이 휴지통·그만 모음으로 가면 첫 항목으로 바뀜
