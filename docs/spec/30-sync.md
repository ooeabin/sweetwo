# 동기화

서버가 유일한 원본, 기기(데스크톱 앱·모바일 앱)는 캐시. 충돌은 데이터 유형별 규칙 하나로 자동 처리하고, 사용자에게는 결과만 해요체 한 줄로 알림. 누가 무엇을 고칠 수 있는지는 → 핵심 규칙 › 부부·권한을 따르고 이 탭은 동시에 일어날 때의 처리만 정함. 제안·승인과 월말 정리는 없앰(2026-10-25, `docs/adr/0003-replan-goal-checklist.md`): 두 사람 모두 바로 고치고 상대에게 알림.

## 1. 원칙

- 단일 원본: 확정 값·계산 결과(남는 돈, 목표 모은 돈, 목표 진행)는 서버 값이 기준. 앱의 계산(공용 계산 패키지)은 입력 중 미리보기용
- 기기 = 캐시: 데스크톱·모바일 앱 모두 암호화 로컬 저장소에 마지막으로 받은 데이터 보관(모바일 키는 Keychain·Keystore)
- 저장 흐름: 입력 → 화면에 바로 반영(저장 중 표시) → 서버 확정 → 모두 저장됨. 서버가 거절하면 원래 값으로 되돌리고 이유 한 줄 표시
- 실시간 반영: 앱이 열려 있는 동안(모바일은 화면에 떠 있는 동안, 뒤로 가면 끊고 돌아오면 재연결) 서버와 웹소켓 연결 유지, 상대 변경을 1\~2초 안에 받음. 연결이 안 되면 30초 간격 확인(폴링)으로 대체
- 재연결: 마지막으로 받은 변경 번호 이후 변경만 받아 반영(전체 다시 받기 없음)
- 상대 변경 표시: 보고 있는 화면의 값이 바뀌면 바로 교체 + 바뀐 칸 2초 강조. 입력 흐름 중이면 지금 질문의 값은 그대로 두고 관련 값만 갱신
- 버전: 모든 레코드에 버전 번호. 저장 요청은 ‘화면을 열 때의 버전’을 함께 보내 서버가 충돌 여부 판정
- 저장 상태 표시(→ 화면 설계 › 홈 › 앱 기본 틀): 두 사람 아바타에 마우스를 올리면 툴팁 “모두 저장됨” / “저장 중”, 오프라인은 Banner(기기에 저장됨) + 보낼 입력이 있으면 ‘대기 {n}건’

## 2. 데이터 유형별 충돌 규칙

실시간 반영으로 대부분 충돌은 생기지 않음. 서버 판정 기준은 필드 단위: 다른 필드끼리는 자동 합침, 같은 필드만 아래 규칙. 상대가 고치면 알림 + 변경 기록, 고친 사람에게는 Toast ‘되돌리기’(→ 핵심 규칙 › 부부·권한).

| 유형 | 예 | 동시에 바뀌면 | 사용자에게 보이는 것 |
| --- | --- | --- | --- |
| 사실값 | 내 수입, 월급날, 자산·부채 금액·잔액 | 마지막 저장 우선. 단, 상대가 1분 안에 같은 필드를 다른 값으로 바꿨으면 나중 저장한 사람에게 선택 화면. 수입이 바뀌면 저장 즉시 남는 돈 재계산 | 덮인 쪽에 토스트 “{이름}님이 방금 {항목}을 바꿨어요”. 선택 화면 “{이름}님이 방금 이 값을 바꿨어요. 어느 쪽으로 할까요?” |
| 사실값 중 수입 | 월 실수령, 기간 수입 변경 | 내 소유라 상대와는 충돌 없음, 내 기기 둘(데스크톱·모바일) 사이만. 저장 직전 서버 최신 값 재확인, 화면을 연 뒤 바뀌었으면 저장 전 확인(수입 변경은 즉시 알림이라 잘못 저장 방지) | “다른 기기에서 월 수입이 {금액}으로 바뀌었어요. 이 값으로 바꿀까요?” |
| 분배표·목표 | W-01 분배표 줄 금액·이름, 월급 관리 방식, 목표 이름·금액·기한·우선순위 | 누구나 바로 고침(제안 없음). 같은 필드는 마지막 저장 우선, 상대가 1분 안에 같은 필드를 다른 값으로 바꿨으면 나중 저장한 사람에게 선택 화면(사실값과 같음). 분배표가 바뀌면 이번 달 체크 안 한 줄만 새 금액(→ 월급 체크리스트 ‘다시 계산되는 때’) | 상대에게 알림. 덮인 쪽에 토스트 “{이름}님이 방금 {항목}을 바꿨어요” [확인 필요] |
| 월급 체크 | W-02·W-05 줄 체크·풀기, W-02a 다른 금액, ‘이번 달은 못 했어요’ | 줄 단위 합치기(다른 줄 체크는 서로 영향 없음). 체크는 그 체크리스트 주인, 합쳐서면 누구나, 각자면 배우자 ‘대신 체크’. 같은 줄을 둘이 거의 동시에 체크하면 먼저 저장된 체크 유지. 금액이 다르면 마지막 저장 우선 + 이력. 저금 줄 체크·풀기는 목표 모은 돈에 바로 반영 | “{이름}님이 먼저 체크했어요”(→ 월급 체크리스트 W-02) / 금액이 덮인 쪽에 토스트 “{이름}님이 방금 금액을 바꿨어요” [확인 필요] |
| 기록 | 챙길 날 기록(Y-08), 목표 직접 넣기·꺼내 쓰기, 메모·사진 | 추가형이라 새 기록끼리는 충돌 없음(둘 다 저장). 같은 기록을 동시에 고치면 필드 단위 마지막 저장 우선 + 변경 이력 | 덮인 쪽에 토스트 “{이름}님이 방금 {기록}을 고쳤어요” |
| 삭제 vs 수정 | 한 사람이 삭제, 다른 사람이 같은 항목 수정 | 삭제 우선. 삭제 항목은 휴지통에 30일 보관(→ 화면 설계 › 설정 ‘휴지통’), 늦게 도착한 수정은 휴지통 항목에 반영해 복구 시 살아남음 | 수정한 쪽: “{이름}님이 방금 {항목}을 지웠어요” + ‘되살리기’ 버튼(되살리면 상대에게 배우자 활동 표시) |

- 권한 밖 저장(상대 명의 항목, 해제 대기 중 분배표 고치기 등)은 서버가 거절 → “{배우자}님 항목이라 볼 수만 있어요” 등(문구 → 화면 설계 › 공통 상태)

## 3. 지난 체크리스트와 동시 편집

예전 ‘월말 정리 동시 진입’(정리자 잠금, 함께 모드, 보기만)은 월말 정리를 없애며 함께 없앰. 월말 확인(W-05)은 체크리스트 줄 체크와 같은 규칙(2장 ‘월급 체크’)이라 잠금이 없음.

- 다음 기준일 0시에 새 체크리스트가 생기면 지난 체크리스트는 읽기 전용. 그 뒤 도착한 지난 체크리스트 체크는 서버가 거절 → ‘보내지 못한 입력’(4장). 잘못 체크했으면 목표 상세에서 모은 돈을 직접 고침(→ 핵심 규칙 › 월 사이클 4장)
- 한 사람이 W-05를 열어 둔 채 상대가 같은 줄을 체크하거나 ‘이번 달은 못 했어요’로 닫으면 화면의 그 줄을 바로 바꿈 + 2초 강조

## 4. 오프라인

데스크톱 앱과 모바일 앱 모두 오프라인 입력 지원(같은 규칙). 여기서는 동작만 정하고, 사용자에게 보이는 상태 문구는 → 화면 설계 › 공통 상태.

| 구분 | 데스크톱·모바일 앱 |
| --- | --- |
| 조회 | 마지막으로 받은 데이터 전체 조회 + 마지막 저장 시각 표시 |
| 입력 가능 | 사실값 수정, 월급 체크(W-02·W-05), 분배표·목표 고치기, 기록 추가·수정 |
| 입력 불가(비활성 + 안내) | 초대·연결 해제, 공개 범위 변경, 월급 관리 방식 변경 [확인 필요], 구독 결제 |

- 대기열: 입력은 기기에 순서대로 저장(암호화), 연결되면 순서대로 전송. 저장 상태에 대기 건수 표시
- 전송 시 충돌은 2장 규칙. 단, 대기 중 입력이 상대가 그 뒤에 바꾼 값을 덮게 되면 자동으로 덮지 않고 어느 값으로 할지 확인(문구 → 화면 설계 › 공통 상태)
- 서버가 거절한 입력(항목 삭제됨, 권한 바뀜, 읽기 전용이 된 지난 체크리스트)은 ‘보내지 못한 입력 {n}건’ 목록 → 다시 하기 / 버리기
- 7일 넘게 오프라인이면 재연결 때 대기 목록을 먼저 보여주고 한 번에 보내기
- 입력 시각은 기기 시각이 아니라 서버 도착 시각으로 처리(사이클·기준일 판단 포함), 이력에는 기기 입력 시각도 함께 저장

## 5. 서버 작업과 사용자 편집이 겹칠 때

서버 작업은 시작 시각의 스냅샷으로 계산, 그 뒤 도착한 편집은 작업이 끝난 결과 위에 반영하고 남는 돈 재계산.

| 서버 작업 | 스냅샷 기준 | 작업 중·후 편집 처리 |
| --- | --- | --- |
| 기준일 0시 체크리스트 생성 | 0시 직전까지 서버에 도착한 분배표 | 작업 중(수 초) 도착한 분배표 편집은 대기 후 새 체크리스트의 체크 안 한 줄에 반영. 지난 체크리스트는 읽기 전용이라 반영 안 함, 체크 안 한 줄은 ‘못 함’으로 닫힘. 입력은 막지 않음 |
| 첫 체크리스트 생성(O-60 직후, 배우자 합류 직후) | 그 시점 분배표 | 기준일 0시와 같은 처리(→ 핵심 규칙 › 월 사이클 3장) |
| 다음 기준일 3일 전 오후 8시 월말 확인 알림 | 그 시각 체크 안 한 줄 수 | 알림 예약 뒤 모두 체크되면 보내지 않음 [확인 필요] |
| 연결 해제 대기 중 기준일 | 지난 분배표 그대로 체크리스트 생성 | 체크는 계속 가능, 분배표 고치기 비활성(→ 핵심 규칙 › 부부·권한), 해제 확정 시 각자 혼자 쓰기로 다음 사이클부터 |

- 서버 작업은 부부 공간 단위로 한 번에 하나만 실행(겹치면 대기)
- 작업이 실패하면 지난 값 유지 + 재시도, 사용자 화면은 “잠시 문제가 생겼어요” 대신 지난 체크리스트를 그대로 표시

## 6. 버전·호환

- 데스크톱 앱: 자동 업데이트(→ 기술·운영 5장). 서버가 ‘최소 지원 버전’ 관리(데스크톱·모바일 따로)
  - 최소 지원 버전 이상: 백그라운드 다운로드 후 다음 실행 때 적용, “새 버전이 준비됐어요” + 지금 다시 시작
  - 최소 지원 버전 미만: 동기화 중단, 업데이트 화면만 표시(조회는 가능, 대기열은 보존했다가 업데이트 뒤 전송)
  - 최소 지원 버전은 데이터 구조·계산 규칙이 호환되지 않게 바뀔 때만 올림
- 모바일 앱: 스토어 업데이트. 최소 지원 버전 미만이면 동기화 중단 + 업데이트 화면(‘지금 업데이트’ → 스토어), 대기열 보존. 스토어 심사 기간이 있어 최소 지원 버전은 새 버전이 스토어에 나온 뒤에 올림
- 데이터 구조 변경: 추가형 우선(필드 추가, 구버전은 모르는 필드를 지우지 않고 보존). 이름 변경·삭제는 2단계(새 필드에 같이 쓰기 → 지원 버전이 모두 새 필드를 읽은 뒤 옛 필드 제거)
- 이전(마이그레이션)은 서버에서 실행. 기기 캐시는 앱 업데이트 때 변환, 실패하면 대기열을 먼저 보낸 뒤 캐시를 지우고 서버에서 다시 받음
- 계산 규칙이 바뀌면 서버 값이 기준, 이미 끝난 사이클의 체크리스트는 다시 계산하지 않음

## 7. 변경 이력

- 대상: 모든 항목의 필드 변경. 기록 = 항목, 필드, 전·후 값, 바꾼 사람, 서버 저장 시각(+ 오프라인이면 기기 입력 시각), 기기 종류(데스크톱/iOS/Android), 출처(직접 수정 / 체크 / 대신 체크 / 되돌리기 / 서버 작업 / 오프라인 대기열 / 충돌 선택)
- 배우자 활동(알림 센터, → 홈): 이 이력에서 상대가 바꾼 것만 표시. 공개 범위 따름: ‘합계만’ 항목은 이름 없이 “개인 자산 금액이 바뀌었어요”, ‘비공개’·서프라이즈 항목은 표시 안 함
- 항목 상세의 ‘변경 기록’: 누가·언제 바꿨는지 목록(“{이름}님이 3일 전 바꿨어요”), 이전 값으로 되돌리기(즉시 적용, 상대에게 알림)
- 보관 기간
  - 금액 이력(그래프용): 계정 유지 동안
  - 변경 이력 상세(전·후 값·출처): 13개월(작년 같은 달과 비교 가능), 지나면 금액 이력만 남김
  - 배우자 활동 화면 표시: 최근 90일
  - 삭제 항목: 휴지통 30일 뒤 완전 삭제
- 연결 해제·탈퇴 시 이력 처리는 → 보안·개인정보 3·4장
