# 사용성 테스트

MVP 개발 전, 클릭형 프로토타입으로 예비·신혼 커플 6쌍이 온보딩 → 합류 → 첫 월말 정리까지 막힘없이 가는지와 수동 입력을 계속할 의향을 확인함.

## 1. 목적·핵심 가설

- 목적: 출시 전 가장 큰 위험(입력 지속·월말 정리·제안 구조) 검증, 치명 이슈를 MVP 전에 수정
- 기준 인원: 6쌍 12명 (온보딩은 주도자 6명, 합류는 상대 6명)

| # | 가설 | 성공 기준 |
| --- | --- | --- |
| H1 | 수동 입력이어도 매달 쓸 만함 | “다음 달에도 직접 입력해 쓸까요” 5점 척도 4점 이상 9/12명 |
| H2 | 온보딩 필수 경로를 8분 안에 끝냄 | 도움 없이 O-66 ‘시작하기’ 5/6명, 소요 중앙값 8분 이하 (상한 10분) |
| H3 | 월말 정리를 5\~10분에 끝냄 | 도움 없이 W-04 완료 5/6쌍, 소요 중앙값 10분 이하 |
| H4 | 제안·좋아요 구조를 이해함 | “반대 안 하면 언제 바뀌나요” 등 3문항 정답 10/12명, G-08 응답 오조작 0건 |
| H5 | 배우자가 초대 링크로 혼자 합류함 | 도움 없이 P-11 도달 5/6명, 3분 이하. “실제로도 합류할 것” 4점 이상 9/12명 |
| H6 | 순자산과 예상 순자산 차이를 앎 | F-01에서 두 값 차이를 자기 말로 설명 8/12명 |

## 2. 프로토타입 범위

- 도구: Figma 프로토타입 (데스크톱 창 1100px 기준), 합류(P-)만 좁은 창 웹 프레임 추가
- 가짜 데이터: 찬우·예빈 맞벌이 신혼 1년 차. 참가자는 실제 금액 대신 이 데이터로 진행 (주도자 = 찬우 역, 상대 = 예빈 역)
- 금액·텍스트 입력: 칸을 누르면 정해진 값 채움. 실제 입력 부담은 사후 질문으로 보완

| 묶음 | 클릭 가능 화면 | 시작 상태 |
| --- | --- | --- |
| 1. 로그인·가입 | A-01·A-02·A-05 (소셜 로그인은 클릭 1번으로 통과) | 신규 |
| 2. 온보딩 | 필수 경로 O-01\~O-66 (첫 주 할 일 화면 제외) | 신규 |
| 3. 이번 달·월급 플랜 | H-01·H-04, W-01·W-02, W-04a·j·k·h·g | 첫 플랜 직후 / 정리 기간(한 달 뒤) |
| 4. 목표·우리 자산 | G-01·G-03a\~f·G-08, F-01·F-02 | 정리 기간 |
| 5. 배우자 합류 | A-07(P-01)\~P-11 | 초대 링크 받은 상태 |

- 제외: 설정·어드민·캘린더·놓친 달·연결 해제 (위험 낮음 또는 2차 테스트)

## 3. 참가자

| 구성 | 쌍 | 기준 |
| --- | --- | --- |
| 맞벌이 신혼 (결혼 1\~3년 차) | 2 | 공동 통장 운영 중 1쌍, 아직 각자 1쌍 |
| 예비부부 (각자 관리) | 2 | 예식 6개월\~1년 이내, 결혼 준비 통장 유무 섞음 |
| 한쪽 프리랜서·변동 수입 | 1 | 월 수입 편차 큰 쪽 포함 |
| 신혼 첫해, 돈 관리 시작 전 | 1 | 가계부·자산 앱 사용 경험 없음 |

- 공통: 둘이 함께 90분 참여, 데스크톱(Windows·macOS) 사용 가능, 돈 관리 주도자·덜 적극적인 쪽이 섞이게
- 제외: UX·핀테크 종사자, 최근 6개월 내 유사 테스트 참여자
- 앱 경험: 자산·가계부 앱 사용 중 3쌍 이하
- 모집 채널: 결혼 준비 온라인 카페·웨딩 커뮤니티, 지인 추천, 리서치 패널 (스크리너 설문)
- 사례비: 커플당 10만 원 (1인 5만 원 상품권), 예비 1쌍 추가 모집

## 4. 세션 구성 (90분)

- 진행자 1 + 관찰자 1, 대면 우선(방 2개), 화면·음성 녹화 동의
- 따로 과제 중 상대는 옆방에서 사전 설문(지금 돈 관리 방식)

| 시간 | 단계 | 참여 | 내용 |
| --- | --- | --- | --- |
| 0\~5분 | 안내·동의 | 같이 | 녹화·가짜 데이터·소리 내어 생각하기 안내 |
| 5\~15분 | 사전 인터뷰 | 같이 | 지금 돈 관리 방식, 누가 주도, 앱·엑셀 사용 경험과 그만둔 이유 |
| 15\~40분 | 과제 T1·T2 | 따로 (주도자) | 온보딩, 결과 이해 |
| 40\~52분 | 과제 T3·T4 | 따로 (상대) | 합류, 제안 응답 |
| 52\~77분 | 과제 T5\~T7 | 같이 | 월급 나누기, 월말 정리, 자산 |
| 77\~90분 | 사후 질문 | 각자 설문 → 같이 인터뷰 | SUS, 지속 의향, 이해도 3문항, 가장 헷갈린 화면 |

## 5. 과제

| # | 과제 | 참여 | 시작 화면 | 성공 조건 | 관찰 포인트 |
| --- | --- | --- | --- | --- | --- |
| T1 | 처음 설치하고 월급 플랜 받기 | 주도자 | A-01 | O-66 ‘시작하기’ 도달 | 멈춘 화면, ‘잘 모르겠어요’·‘나중에’ 사용, 금액 질문(O-31·O-33·O-36·O-39) 망설임 |
| T2 | “이번 달 누가 어느 통장에 얼마 옮기나요?” 답하기 | 주도자 | O-62 | 찬우·예빈 나눌 금액과 통장 3개를 맞게 말함 | 임시·추정 표시 이해, O-63 통장 선택 혼동 |
| T3 | 초대 링크로 합류하기 | 상대 | A-07(P-01) | P-11 도달 | 찬우가 적은 값 확인(P-02b) 반응, 용돈 다를 때 제안 인지 |
| T4 | 찬우가 보낸 목표 변경 제안에 답하기 | 상대 | H-04 | G-08에서 좋아요·반대·다르게 해볼래요 중 의도대로 응답 | 전·후 값 읽기, “반대 없으면 적용” 이해 |
| T5 | 이번 달 월급 나누고 체크하기 | 같이 | W-01 | W-02 나누기 줄 모두 체크 | 담당자 구분, 체크와 은행 앱에서 실제로 옮기는 일의 관계 이해 |
| T6 | 한 달 지난 뒤 월말 정리 같이 하기 | 같이 | H-01 (정리 알림) | W-04g 완료 | 단계별 시간, W-04j 항목별 입력·W-04k 저축 확인 이해, ‘더 꼼꼼히 정리하기’ 선택 여부, 누가 조작하는지 |
| T7 | 우리 순자산과 예상 순자산 차이 설명하기 | 같이 | F-01 | F-01에서 원금·평가금액 차이 설명 | 두 값 혼동, 목표 계산이 어느 값을 쓰는지 오해 |

## 6. 측정 지표

| 지표 | 측정 | 대상 과제 |
| --- | --- | --- |
| 완료율 | 도움 없이 완료 / 힌트 1회 후 완료 / 실패 | 전체 |
| 소요 시간 | 시작 화면 → 성공 조건, 중앙값 | T1·T3·T6 (H2·H3·H5) |
| 오류 | 잘못 누름·뒤로 가기·잘못된 답 횟수 | 전체 |
| SEQ | 과제 직후 “얼마나 쉬웠나요” 7점 | 과제마다 |
| SUS | 사후 10문항, 각자 응답 (목표 평균 70 이상) | 세션 끝 |
| 지속 의향 | “다음 달에도 직접 입력해 쓸까요” 5점 + 이유 | 세션 끝 (H1) |
| 이해도 | 제안 적용 시점·임시 플랜·예상 순자산 3문항 | 세션 끝 (H4·H6) |

## 7. 결과 정리

| 심각도 | 기준 | 처리 |
| --- | --- | --- |
| 치명 | 과제 실패, 또는 돈 판단을 틀리게 함(나눌 금액·적용 시점 오해) | MVP 전 반드시 수정 |
