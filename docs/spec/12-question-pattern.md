# 질문 화면 패턴

‘한 화면 한 질문’ 화면의 공통 틀과 입력 패턴 7가지, 금액·목록 입력 규칙의 정본(질문 화면 밖 금액 칸도 같은 규칙). 화면 탭은 ‘패턴’ 칸에 Q1\~Q7만 적고 다른 점만 정의함.

| 패턴 | 이름 | 쓰는 곳 (예) | 넘어가는 방식 |
| --- | --- | --- | --- |
| Q1 | 단일 선택 | O-06·O-11·O-30, W-12a | 고르면 0.3초 뒤 자동 다음. O-06(초대하기·나중에 할게요)과 O-30(주 버튼 ‘다음’)은 화면별 정의를 따름 |
| Q2 | 다중 선택 칩 | 지금 쓰는 화면 없음(예전 O-21, 2026-11-08 없앰) | 주 버튼 ‘다음’ |
| Q3 | 금액 입력 | O-31, W-02a, W-11b·W-11c, 월급 계획 줄 금액(O-50·W-01) | 주 버튼 ‘다음’ |
| Q4 | 날짜·월 선택 | S-11h 결혼한 날, S-11i 출생연도(연도 휠), O-32 월급날(일 휠), W-11d 기한(연·월) | 주 버튼 ‘다음’ (연도만 받으면 4자리 입력 시 자동). 월급날(O-31)은 숫자 판 |
| Q5 | 짧은 텍스트 | O-03, W-11a 저금 항목 이름 | 주 버튼 ‘다음’ |
| Q6 | 목록 입력 | 지금 쓰는 화면 없음(예전 O-23 연간 고정 지출) | 주 버튼 ‘다음’ |
| Q7 | 안내·확인 | 온보딩 준비 끝(O-60), W-12 달성 축하, 파트너 합류 확인 화면(W-02 끝은 2026-11-12 없앰) | 주 버튼 |

## 공통 틀

> 화면 그림: 질문 화면 공통 틀 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 진행 표시 | 온보딩: 질문 화면 맨 위 얇은 막대 하나(브랜드 오렌지, 글자 없음). 그 밖: 칸 막대(숫자·이름 없음) | 온보딩은 챕터 구분 없이 막대 하나가 O-03부터 O-32까지 차 감(→ 온보딩 ① 흐름 요약). 답에 따라 화면 수가 달라지면(O-07, 파트너가 이미 합류해 O-06·O-07이 빠짐) 막대 길이를 다시 맞춤. O-60(준비 끝)에는 막대 없음(2026-11-10 O-10 없앰). 파트너 합류는 칸 막대(끝난 칸 채움, 지금 칸 옅게). 단독 질문은 숨김 |
| 2 | 뒤로 | 좁은 창: < (꺾쇠, 왼쪽 위) / 넓은 창(태블릿): 아래 바 왼쪽 “‹ 이전” | 직전 화면을 저장된 답과 함께 열기. 온보딩 첫 화면 O-03(연결 해제 뒤 O-11)에서는 없음(제목 위치 → QuestionLayout). O-11의 뒤로는 O-07 시트가 아니라 O-06. 넓은 창(마우스·트랙패드)은 위 바 왼쪽에 워드마크, 가운데 진행 칸 막대(질문마다 1칸, → QuestionLayout·ChapterBar) |
| 3 | 나중에 할게요 | “나중에 할게요” | 온보딩은 O-06(초대)에만 표시, 누르면 → O-11, 홈 할 일 한 줄 ‘초대하기’(→ 홈 H-06). 그 밖의 온보딩 질문은 넘기지 않음(O-31은 ‘지금은 월급이 없어요’). 단독 질문은 질문 단위: 오른쪽 ‘닫기’(답 저장) |
| 4 | 제목 | 질문 1줄, 해요체 | 22px(title-1, 2026-11-10) 굵게. {나}는 O-03 이름, {파트너}는 파트너가 합류할 때 적은 이름. 최대 2줄 |
| 5 | 보조 설명 | ‘왜 묻는지’ 1줄 | 꼭 필요할 때만. 회색 작은 글씨 |
| 6 | 입력 영역 | 패턴 Q1\~Q6 | 열리면 첫 입력에 자동 포커스(O-31 금액 칸도, 2026-11-10). Q1 선택지는 넓은 창(마우스)만 |
| 7 | 보조 링크 | “잘 모르겠어요” / “해당 없어요” / “없어요” | 화면당 0\~1개. 잘 모르겠어요 = 추정값 + ‘추정’ 배지. 해당 없어요·없어요 = 빈 답 저장 |
| 8 | 주 버튼 | “다음” | 좁은 창과 태블릿(터치)은 폭 가득·화면 아래 끝(2026-11-10 태블릿도 휴대폰처럼 가운데 열), 마우스·트랙패드(하드웨어 키보드)가 있는 넓은 화면만 아래 바 오른쪽(글자 길이만큼) + 왼쪽에 회색 “Enter 키를 눌러도 돼요” [확인 필요]. 입력 전·오류면 비활성. Q1에는 없음 |
| 9 | 자동 저장 표시 | “저장했어요” | 화면을 넘길 때마다 저장, 1.5초 표시. 오프라인이면 저장하지 않고 “인터넷에 연결되면 할 수 있어요”(→ 공통 상태 9번) |

키보드 (키보드를 붙인 태블릿 등)

| 키 | 동작 |
| --- | --- |
| Enter | 주 버튼(비활성이면 무시). 입력 칸이 없는 화면(휠, 안내 Q7)이나 포커스가 없어도 주 버튼(2026-11-10). 다른 버튼·링크·선택지에 포커스면 그것. 한글 조합 중, 시트·대화상자가 열려 있으면 무시 |
| Esc / Alt+← | 뒤로. 달력·드롭다운이 열려 있으면 그것만 닫음 |
| 1\~9 | Q1 n번째 선택, Q2 n번째 칩 켜기·끄기(입력 칸 포커스 없을 때) |
| 숫자 키 | Q3·Q4 칸에 바로 입력 |
| Tab / Shift+Tab | 입력 → 보조 링크 → 주 버튼. Q6은 행 안 칸 순서 |
| ↑ ↓ ← → | Q1 선택지, Q4 달력 날짜 이동 |

자동 저장·이어하기

- 화면을 넘길 때마다 저장. 다시 열면 묻지 않고 가장 멀리 간 화면부터(2026-11-10 “이어서 할까요?” 질문 화면은 없앰, → 온보딩 ①)
- 온보딩 밖 흐름은 첫 화면 Esc = 닫기 + “작성 중인 내용은 저장돼요”

입력 칸 상태 (화면 전체 상태는 → 공통 › 공통 상태)

| 상태 | 표시 |
| --- | --- |
| 빈 값 | 자리표시 회색, 주 버튼 비활성 |
| 입력 중 | 칸 테두리 진하게, 유효하면 주 버튼 활성 |
| 오류 | 칸 테두리 + 칸 아래 1줄 문구(빨강), 주 버튼 비활성. 입력을 멈춘 뒤 표시 |
| 비활성 | 주 버튼(빈 값·오류), 한도에 닿은 추가 버튼·칩만 |
| 이상값 | “입력한 값이 맞나요?” 1회 확인, 막지 않음(기준은 화면별). 입력 아래 확인 띠(`hg-banner--check`: 회색 판 + 앞 ⚠ 원 아이콘 + ink 15px 600, 2026-11-11) |

## Q1 단일 선택

카드 2\~5개 세로 나열. 고르면 0.3초 뒤 자동 다음(주 버튼 없음).

> 화면 그림: Q1 단일 선택 (그림은 기획서 페이지 사본에 있는 재기획 전 예시예요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | “두 사람은 어떤 사이예요?” | O-11 |
| 2 | 선택지 카드 | “했어요” / “준비 중이에요” | 2\~5개, 세로 1열. 문구 12자 이내, 필요하면 카드 안 회색 1줄(예: O-30 “월급 계획과 체크리스트가 사람마다 있어요”) |
| 3 | 선택됨 | 오른쪽 원이 브랜드 오렌지 체크로(2026-11-09 브랜드 색 규칙, → Selection) + 굵은 테두리(안 고른 카드는 옅은 회색 바탕, 빈 원). 바로 넘어가는 카드(O-06, O-11)는 원 대신 › | 0.3초 뒤 다음. 그 사이 다른 카드를 누르면 바꾸고 다시 셈 |

상태

- 빈 값: 선택 없음, 첫 카드에 포커스(넓은 창만. 좁은 창은 포커스 없음, 2026-11-03)
- 입력 중: 같은 카드 연타는 1회로 처리
- 비활성: 조건에 안 맞는 선택지는 숨김

예외·오류

- 추가 입력이 붙는 선택지(화면별): 카드 아래 입력 펼침 + 주 버튼 표시
- 답을 바꿔 분기가 달라지면 “앞에서 적은 답 {n}개가 지워져요. 바꿀까요?” 확인

## Q2 다중 선택 칩

칩 여러 개를 고른 뒤 주 버튼 ‘다음’.

> 화면 그림: Q2 다중 선택 칩 (그림은 기획서 페이지 사본에 있는 재기획 전 예시예요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | 질문 1줄 | 지금 쓰는 화면 없음(예전 O-21 목표 고르기, 2026-11-08 없앰) |
| 2 | 칩 | 이름 칩 | 누를 때마다 켜기·끄기. 한도는 화면별 |
| 3 | 선택된 칩 | 굵은 테두리 + 옅은 채움 | 순서가 뜻이 있는 화면만 순번 표시 |
| 4 | 주 버튼 | “다음” | 1개 이상이면 활성. 0개를 허용하는 화면은 화면별 |

- 배타 칩 ‘없어요’(화면별): 누르면 다른 칩 해제, 다른 칩을 누르면 ‘없어요’ 해제
- 그룹 칩(화면별): 다음 화면에서 고른 그룹의 세부 항목을 Q2로 물음
- 칩이 3줄을 넘으면 나머지는 ‘더 보기’
- 앞 답으로 정해지는 칩은 켜진 채 시작(화면별)

상태

- 빈 값: 모두 꺼짐, 주 버튼 비활성
- 비활성: 한도에 닿으면 꺼진 칩 비활성 + “{n}개까지 고를 수 있어요”

예외·오류

- 적은 내용이 있는 칩을 끄면 “{그룹}에 적은 내용도 지워져요” 확인

## Q3 금액 입력

큰 숫자 칸 하나, 아래에 만 원 단위로 읽어 줌.

> 화면 그림: Q3 금액 입력, 넓은 창과 좁은 창 (그림은 기획서 페이지 사본에 있는 재기획 전 예시예요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | “한 달 실수령액은 얼마예요?” / 보조 “세금 떼고 통장에 들어오는 금액이에요” [확인 필요](2026-11-09 ‘들어오는 돈’ 대신) | O-31 |
| 2 | 금액 칸 | 큰 숫자 + “원” | 3자리마다 쉼표. 자리표시 “0”(예시값이 있으면 “예: 50만 원”) |
| 3 | 만 원 단위 읽기 | “130만 원” | 입력할 때마다 갱신 |
| 4 | 빠른 금액 칩 | “+1만” “+10만” “+50만” “+100만” | 누를 때마다 현재 값에 더함. W-11c 목표 금액은 “+100만” “+1,000만” “+1억” [확인 필요]. O-31은 “+10만” “+50만” “+100만” |
| 5 | 잘 모르겠어요 | 지금은 없음(2026-11-08 목표 템플릿 질문을 없앰) | O-31은 ‘지금은 월급이 없어요’ = 0원, 월급날 없음. W-11c는 ‘목표 금액 없이 모을게요’ |
| 6 | 좁은 창 하단 고정 | 빠른 금액 칩 + 주 버튼 | 앱 숫자 키패드 바로 위, 금액 칸은 계속 보이게 |
| 7 | 좁은 창 숫자 키패드 | 3×4, 마지막 줄 “00” “0” 지우기 | OS 키패드 대신 앱 자체 키패드. 화면이 열리면 바로 펼침, 누른 숫자는 끝에 붙음. 예외: 한 화면에 다른 입력이 같이 있는 화면(O-31 ‘매달 금액이 달라요’, F-04 등)은 앱 키패드 없이 기기 숫자 자판, O-31은 금액 칸에 처음 포커스(2026-11-10, → AmountInput `embedded`·`autoFocus`) |

금액 입력 규칙

- 입력: 숫자만, 맨 앞 0 지움, 커서는 항상 끝. 저장은 정수(원). 소수점을 치면 뒤는 버림, 12자리(999억을 한 자리 넘는 값)까지만 받음(2026-11-10)
- 읽기 형식: “5,000원” / “320만 원” / “320만 5,000원” / “1억 2,000만 원” / “2억 원”
- 최대 999억 원(99,999,999,999원, 입력 검증). 내부 저장과 계산은 정수 원 단위. 넘으면 칸 아래 “999억 원까지 넣을 수 있어요”
- 0원 불가: “0원보다 큰 금액을 넣어 주세요”. 0이 답이면 ‘없어요’ 링크(화면별). 예외: 월급 계획 줄 금액(O-50, W-01)은 0원 가능, 1만 원 단위
- 붙여넣기: 숫자 외 문자 제거, “320만”·“1억 2천만” 단위 환산. 해석 불가면 “숫자만 붙여넣을 수 있어요”
- 단위 실수 힌트: 월 금액에 1\~9,999원이면 “{n}만 원인가요?” 링크(누르면 ×10,000)
- 비율·금리(자산 관리 대출 금리 등): 단위 ‘%’, 소수점 1자리, 읽기·빠른 칩 없음. 자산 금리는 0~30%(2026-11-12 D5 = A, F-03g·F-04 같은 core 규칙 `parseRate`, 서버 check는 0~100 그대로)

상태

- 빈 값: 자리표시 “0” 회색, 주 버튼 비활성
- 입력 중: 읽기 표시 갱신, 1원 이상이면 주 버튼 활성
- 오류: 최대값 초과·0원 → 칸·문구 빨강, 주 버튼 비활성

예외·오류

- 뒤로 와서 금액을 바꾸면 그 금액을 쓰는 계산만 다시 함

| 3 | 달력 | 달력 버튼, 칸 포커스 시 펼침 | 고르면 칸 채움. 범위 밖 날짜 비활성, Esc = 달력만 닫기 |
| 4 | 대안 링크 | “아직 미정이에요” | 문구는 화면별. 결혼 예정일(S-11h)은 ‘아직 미정이에요’ → 예정 연·월. W-11d는 ‘기한 없이 모을게요’ |

- 연도 휠(출생연도 S-11i, 2026-11-11 합류 P-03a 뺌): 연도 1열 휠(DateWheel의 연도 열만) [확인 필요]. 범위 1950~(올해 − 18)년, 처음 위치 올해 − 30, ↑↓ 1년. 월·일은 받지 않음. 나이 확인은 A-05 “만 18세 이상이에요” 체크(출생연도는 확인용이 아님)
- 처음 묻는 날짜·연도(설정 S-11i 출생연도, S-11h 결혼한 날을 아직 적지 않았을 때): 처음 위치는 보이기만 하고 답이 아님. 휠을 움직여야 주 버튼 활성(2026-11-10, 처음 값이 그대로 저장되지 않게)
- 월급날(O-32, 파트너 합류 P-05b, 설정 S-11 월급날): 1열 휠 1일\~31일 + 맨 아래 ‘말일’(2026-11-03 숫자 판 대신). ↑↓ 하루, Home·End 처음·말일
- 범위는 화면별(기한 W-11d는 이번 달 이전 불가, 결혼한 날 S-11h는 오늘까지, 예정일은 내일부터)
- 붙여넣기: “2027-05-15”·“2027.5.15”·“20270515” 해석
- 생일 등 경조사: 양력/음력 토글

상태

- 빈 값: “0000” “00” “00” 회색(2026-11-03 영어 YYYY·MM·DD 대신), 주 버튼 비활성
- 입력 중: 칸 자동 이동, 달력도 같은 날짜로 이동
- 오류: “없는 날짜예요”, 범위 밖은 화면별 문구

예외·오류

- 월급날(O-32) 29\~31일: 없는 달은 말일로 계산, 고르면 휠 아래 보조가 “짧은 달은 말일로 계산해요”로 바뀜

## Q5 짧은 텍스트

이름·별칭 등 한 칸.

> 화면 그림: Q5 짧은 텍스트, O-03 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | “내 이름이나 애칭을 알려 주세요” | O-03 |
| 2 | 입력 칸 | 미리 채운 값 “찬우” + 지우기 × | O-03은 로그인 이름을 미리 채움. ×는 값이 있을 때만 |
| 3 | 글자 수 | “8/10” | 한도의 80%부터만 보임(2026-11-02). 최대 글자 수는 화면별(O-03 10자), 한도에서 입력 멈춤. 보이는 글자 단위로 셈(커플 이모지 👩‍❤️‍👨 하나 = 1자, 2026-11-10). 서버 한도는 코드 포인트라 화면별로 따로(O-03 이름 40), 그 안에서도 멈춤 |
| 4 | 주 버튼 | “다음” | 앞뒤 공백 뺀 1자 이상이면 활성 |

- 앞뒤 공백 제거, 연속 공백 1칸, 줄바꿈·탭 지움. 이모지·특수문자 허용

상태

- 빈 값: 자리표시 “이름이나 애칭” 회색(사람 이름 예시는 쓰지 않음), 주 버튼 비활성
- 오류: 공백만 입력 → “이름을 넣어 주세요”

예외·오류

- 붙여넣기가 한도를 넘으면 한도까지만 넣고 “10자까지만 넣었어요”
- 합류한 사람 이름이 시작한 사람 이름과 같으면 “두 분 이름이 같아요. 그대로 쓸까요?” [확인 필요] 확인

## Q6 목록 입력

한 화면에 여러 항목(한 화면 한 질문의 예외). 항목 추가·삭제, 합계 바로 표시.

> 화면 그림: Q6 목록 입력, 넓은 창과 좁은 창 (그림은 기획서 페이지 사본에 있는 재기획 전 예시예요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | 질문 1줄 | 지금 쓰는 화면 없음(예전 O-23 연간 고정 지출) |
| 2 | 항목 앞 칸 | 이름 + “3월 ▾” | 화면별(월·이름). 월은 1\~12월 드롭다운 |
| 3 | 금액 칸 | “2,000,000원” | Q3 금액 입력 규칙 그대로. 포커스 행만 만 원 단위 읽기 |
| 4 | 삭제 | × | 묻지 않고 바로 삭제 + Toast “삭제했어요”, “되돌리기” 6초. 행이 1개면 비우기 |
| 5 | 빈 항목 | 회색 “월 ▾” “0원” | 처음 열면 빈 행 1개 |
| 6 | 항목 추가 | “+ 항목 추가” | 빈 행 추가 후 첫 칸 포커스(빈 행이 있으면 그 행으로) |
| 7 | 합계 | “1년에 모두 700만 원” | 완성 행만 더해 바로 갱신, 없으면 “—”. 문구는 화면별 |
| 8 | 주 버튼 | “다음” | 완성 행 1개 이상, 미완성 행 없을 때 활성 |
| 9 | 좁은 창 하단 고정 | 합계 줄 + 주 버튼 | 목록만 스크롤, 키패드가 열리면 그 바로 위로 |

목록 규칙

- 항목 한도 기본 10개. 닿으면 ‘항목 추가’ 비활성 + “10개까지 넣을 수 있어요”
- 빈 행은 저장 안 함. 일부만 채운 행·0원 행은 빈 칸 빨강 + “금액을 넣어 주세요”
- 행이 정해진 화면(화면별)은 추가·삭제 없음
- 중복 허용. 저장 뒤 다시 열면 월 순 정렬
- 합계는 미완성 행 제외. 이상값 확인은 합계 기준
- 키보드: Tab = 행 안 칸 → 다음 행 → ‘항목 추가’. ‘항목 추가’에서 Enter = 추가, 그 외 Enter = 다음

상태

- 빈 값: 빈 행 1개, 합계 “—”, 주 버튼 비활성
- 입력 중: 포커스 행 강조, 합계 바로 갱신
- 오류: 미완성 행·금액 오류 칸만 빨강, 주 버튼 비활성

예외·오류

- 행이 많으면 목록만 스크롤, 질문·합계·주 버튼 고정
- 뒤로 갔다 오면 저장된 행만 열림
- 파트너가 같은 목록을 고치면 행 단위로 합침, 같은 행이면 충돌 선택(→ 공통 › 공통 상태)
