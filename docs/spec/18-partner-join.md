# 파트너 합류

## 흐름 요약

휴대폰으로 초대 링크를 받은 예빈이 모바일 앱으로(앱이 없으면 스토어 → 설치 → P-01 코드 입력) 들어와 로그인한 뒤 이름, 관리 방식 확인, 내 월급, 월급날만 답하고 홈으로 감. 월급 계획은 추천값으로 만들어 두고 홈 H-03 ‘월급 계획 고치기’에서 고침(할 일 ‘월급 계획 확인’은 2026-11-03 없앰)(2026-11-03, 온보딩 ADR 0005와 같게)(설치 뒤 약 1~2분, 휴대폰이나 태블릿 앱에서 끝까지). 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`, 관리 방식·권한 → 핵심 규칙 › 커플·권한.

| 경우 | 경로 |
| --- | --- |
| 기본 | P-01 → P-02 로그인(A-02 → (A-04) → A-05) → (P-02b) → P-03 → P-04 → P-05 → P-05b → 홈 |
| 로그인됨, 우리 둘 공간 없음 | P-01 → (P-02b) → P-03 … |
| 혼자 쓰던 기록 있음 (A-07 6번) | P-01 → P-02a → (P-02b: 겹치는 항목 고르기) → P-03 … |
| 찬우가 대신 입력한 예빈 명의 자산·부채 없음 | P-02b 생략 |
| 찬우가 아직 온보딩 중 (월급 계획이 없음) | P-03 → P-05 → P-05b → 홈 대기(→ 홈 상태 변형 4). 찬우가 온보딩을 마치면 P-04 → 홈(아래 ‘시작한 사람이 아직 온보딩 중’) |
| 월급이 없음 | P-05 ‘지금은 월급이 없어요’ → P-05b 없이 합류 완료 → 홈 |

- 진행 막대: P-03~P-05b(P-03, P-04, P-05, P-05b, 2026-11-11 P-03a를 빼서 4칸), 온보딩과 같은 얇은 브랜드 오렌지 막대 하나(ChapterBar, 2026-11-03, 칸 막대에서 바꿈). 칸 수는 그 흐름의 화면 수: 시작한 사람이 아직 온보딩 중이면 P-03, P-05, P-05b 세 칸(2026-11-11 S3-24). 예전 P-06은 끝까지(S3-23). P-01·P-02는 없음
- ‘나중에 할게요’ 없음
- 결혼 상태(O-11)는 우리 둘 공간에 하나라 다시 묻지 않음(결혼한 날·예정일은 2026-11-10부터 온보딩에서 묻지 않고 설정 S-11h). 출생연도도 합류에서 묻지 않음(2026-11-11 P-03a 출생연도를 뺌, 시작한 사람의 온보딩 O-13과 같게): 자산 순위 F-08을 처음 열 때 내 출생연도가 없으면 ‘출생연도 알려 주기’ → 설정 S-11i → F-08
- 뺀 화면에 멈춰 있던 사람(예전 P-03a): 다시 열면 그 흐름의 다음 화면으로(기본 P-04, 찬우가 아직 온보딩 중이면 P-05). P-03a 번호는 다시 쓰지 않음
- 합류 완료는 P-05b 저장 순간이고 그 뒤 합류 축하 P-10(2026-11-11, 예전에는 따로 화면이 없었음): P-05b 저장 순간(월급 없음이면 P-05 저장 순간). 이때 우리 둘 공간에 들어감(그 전에는 코드만 잡아 둠, 아래 P-01 ‘합류 잡아 두기’). 이때 월급 계획을 P-06 추천값 규칙대로 저장하고 첫 체크리스트를 만듦(2026-11-13 없앰: 첫 확인 목록은 다음 월급날)(월급 계획 확인 할 일은 2026-11-03 없앰. 내 저금이 없으면 홈·체크리스트 저금 묶음에 빈 줄 ‘+ 저금 추가’, → 월급 탭 ‘첫 저금’). 이때 초대 코드 ‘사용됨’, 찬우에게 알림 “예빈님이 합류했어요”(→ 화면 설계 › 알림)
- 좁은 창(768px 미만): 1열, 주 버튼 화면 아래 고정(→ 화면 설계 › 공통).
- 합류 축하 P-10(2026-11-11 QA 3구간 D7): 합류를 마친 순간 한 번. 축하 배경(`hg-celebrate-bg`, DESIGN.md ‘색’ 예외) + 96px 움직이는 그림 자리(`scene-clap`, 그림이 들어올 때까지 회색 빈 자리) + “{시작한 사람}님과 연결됐어요”(호칭이 없으면 “파트너와 연결됐어요”) / “이제 월급과 저금을 같이 봐요”(시작한 사람이 아직 온보딩 중이면 “{시작한 사람}님이 월급 계획을 만들면 알려 드릴게요”) [확인 필요]. 주 버튼: 푸시 허용을 아직 안 물은 모바일 앱이면 ‘다음’ → P-11, 아니면 ‘홈으로 가기’. 대기 뒤 이어서(P-04)는 축하 없이 홈
- P-11 푸시 허용(모바일 앱, 1회, P-10 다음): 96px 그림 자리(`status-push`) + “알림을 받을까요?” / “파트너가 체크하거나 바꾸면 바로 알려 드려요” + ‘알림 받기’(OS 허용 창) / ‘나중에 할게요’ → 홈 [확인 필요]. 축하 배경은 P-10에만
- 예시값: 찬우 실수령 350만 원, 월급날 25일, ‘각자’, 찬우 저금 항목 내 집 마련(목표 1억 5,000만 원, 기한 2031년 10월 → 월 필요액 246만 원, 찬우 월급 계획 95만) → 예빈 실수령 270만 원, 월급날 10일

## 파트너 합류 v2.2 (2026-11-13, ADR 0009)

이 장이 2026-11-13부터 정본. 아래 예전 장(P-04 관리 방식 확인, P-05, P-06 첫 체크리스트, P-10 문구, P-11)은 이 장에서 고친 점 말고 그대로.

순서: 링크 → (앱 없음) L-07 → 스토어 → 설치 → 코드 자동 입력 → P-01 → P-02 → (P-02b) → P-03 → P-04 → P-05 → P-05b → (P-05c) → P-10 → P-11 → 홈

| --- | --- | --- | --- | --- |
| P-01 | 합류 시작 | 고유 | 필수 | 같은 칸에서 제휴 코드(`partner_code`)도 받음. 첫 실행에 복사된 코드가 있으면 자동 입력(Android 설치 리퍼러, iOS 클립보드 붙여 넣기 제안 “받은 초대 코드로 합류할까요?” [확인 필요]) |

- 구현 메모(PR 8, 2026-11-13):
  - P-04 형태 이름은 `join_context`의 `style`(서버 20261206090000). 시작한 사람이 형태를 아직 안 골랐으면(`shared_living` null) P-04를 건너뜀. 같이 계열은 주 버튼 ‘좋아요’만, 각자 계열은 선택지 둘(미리 고른 값 없음)
  - ‘보내요’ 요청은 합류를 마치기 전에는 공간 구성원이 아니라 보낼 수 없어 기기에 기억했다가 합류를 마친 순간 `request_mode_change(p04_send)`. 요청이 열려 있는 동안 합류한 사람 월급 계획(각자)은 용돈 자동 줄 하나뿐: 각자 월급 계획에는 보내기 줄을 둘 수 없어(서버 `send_locked`) 수락되면 서버가 공동 월급 계획에 보내기 줄을 만듦. ‘지금처럼 할게요’면 보내기 줄 없이 용돈 줄만 남음 [확인 필요: 위 ‘보내기 + 용돈 그대로 남음’과 다름, 서버 보완 필요]
  - 합류 전 시작한 사람이 ‘파트너가 주로 해요’를 골랐으면 합류를 마칠 때 합류한 사람이 관리하는 사람(P-05c 없음, 시작한 사람 줄이 보내기 + 용돈)
  - P-05c 용돈이 월급보다 크면 확인 띠 “월급보다 많이 정할 수 없어요” [확인 필요] + 다음 비활성
  - P-05b도 ‘매달 금액이 달라요’면 ‘날짜가 정해져 있지 않아요’(O-32와 같음)
  - ‘월급 없이 합류할게요’ = `finish_join`(월급 계획 없음). 같이 계열(관리하지 않는 쪽 포함)은 예전 ‘지금은 월급이 없어요’(0원으로 합류)
  - P-11은 이 기기에서 이 계정에 아직 안 물었으면 한 번(브리지가 없어도 종류는 저장). P-11 뒤(또는 대기 뒤 이어서 P-04 뒤) 모바일 앱이면 A-06 권장(건너뛸 수 있음) → 홈
  - 대기 ‘알려 주기’(`nudge_starter`) 뒤 Toast “{시작한 사람}님에게 알렸어요” / 24시간 안 다시 누르면 “내일 다시 알릴 수 있어요” [확인 필요]
  - 생활비 ‘네’ + 각자 관리면 합류한 사람 월급 계획에도 ‘같이 쓰는 통장’ 0원 줄(06 3-1, core `sharedAccountSeed`)
- 화면 파일(PR 8): `p-04-style-confirm.tsx`, `p-05-salary.tsx`, `p-05c-allowance.tsx`, `p-11-push-kinds.tsx`
- 시작한 사람이 아직 온보딩 중(월급 계획 없음): 각자 계열이면 기다리지 않고 자기 월급 계획을 만들고 홈(대기 없음). 같이 계열이면 대기 화면(홈 상태 변형) + 글자 버튼 ‘알려 주기’ [확인 필요](시작한 사람에게 푸시, 24시간에 1번, “{이름}님이 기다리고 있어요. 월급 계획을 마쳐 주세요” [확인 필요]). 시작한 사람이 형태를 아직 안 골랐으면 각자 계열로 보고 진행 [확인 필요]
- 첫 확인 목록은 만들지 않음(소급 없음, 다음 월급날)

### P-04 형태 확인

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | “{시작한 사람}님이 이렇게 골랐어요” [확인 필요] + 형태 이름(“생활비와 저금을 같이 해요” 등, 08 2장) + 바뀌는 것 한두 줄 | — |
| 2 | 그대로 | “좋아요” [확인 필요] | → P-05 |
| 3 | 보내요(각자 계열만) | “월급은 대부분 {시작한 사람}님에게 보내요” [확인 필요] | 시작한 사람이 관리하는 같이 계열로 바꾸자는 요청(`request_mode_change`, phrase p04_send). 합류는 그대로 진행하고 이 사람은 관리하지 않는 쪽 흐름(P-05c)을 탐. 시작한 사람 홈 띠 3번 → S-11j |
| 4 | 같이 계열 + 관리하는 사람이 시작한 사람 | 확인만(“좋아요”) | 바로 관리하지 않는 쪽 |

- 요청 결과: ‘좋아요’ → 같이 계열, 합류한 사람의 ‘보내기’ + ‘용돈’ 줄이 공동 월급 계획으로 옮겨감. ‘지금처럼 할게요’·7일 만료 → 각자 그대로, 합류한 사람 월급 계획의 ‘보내기’ + ‘용돈’ 줄은 그대로 남음(각자에서도 뜻이 통함). 합류한 사람에게 결과 인앱 “지금처럼 각자 관리해요” [확인 필요]

### P-05 고친 점

- 공개 고지 한 줄: 각자 계열 “파트너에게는 저금만 보여요” + ‘바꾸기’ / 같이 계열 “같이 관리하면 파트너도 이 금액을 봐요” [확인 필요](O-31과 같음)

### 합류 잡아 두기 (2026-11-11 QA 3구간 D1)

- ‘합류하기’ = 그 코드를 내 몫으로 24시간 잡아 두기만 함. 우리 둘 공간에는 합류를 마치는 순간(P-05b 저장, 월급 없음이면 P-05 저장) 들어감. 그 전에는 공간 구성원이 아니라서 공간 데이터를 읽지 못함(RLS). 합류 화면은 필요한 것만 받음(초대한 사람 호칭, 관리 방식, 초대한 사람 월급 계획이 있는지, 대신 입력한 내 명의 항목, 합쳐서면 다시 채울 공동 월급 계획 → 보안 2장 ‘초대 코드 보호’)
- 잡아 둔 동안 다른 사람은 그 코드를 못 씀(“이미 합류가 끝난 초대예요”). 24시간이 지나면 다른 사람이 잡을 수 있음
- 시작한 사람은 S-12에서 ‘합류하는 중’을 보고 ‘초대 취소’로 풀 수 있음(코드도 못 쓰게 됨, → 설정 S-12). ‘새 코드 받기’도 잡아 둔 것을 풂. 잡아 둔 동안 초대 리마인드·만료 알림은 보내지 않음
- 우리 둘 공간은 늘 2명까지(서버 검사 + 트리거). 세 번째 사람은 어떤 길로도 못 들어옴
- P-02a(혼자 쓰던 기록 옮기기)에서 고른 공개 범위도 기억만 하고, 옮기기는 합류를 마칠 때 함. 마치기 전에 풀리면 아무것도 옮기지 않음
- 잡아 둔 것이 풀린 뒤(취소, 기한 지남) 합류 화면을 열면 → 아래 ‘합류가 끝난 초대’
- 예전 방식(‘합류하기’ 때 바로 공간에 들어감)으로 들어와 합류를 마치지 않은 사람: 배포 때부터 24시간 잡아 둔 것으로 봄. 그 안에 마치면 그대로 합류, 시작한 사람이 ‘초대 취소’나 새 코드를 받으면 내 명의 항목과 함께 혼자 공간으로 빠짐

## P-06 월급 계획

2026-11-03부터 합류 흐름에서 이 화면은 보이지 않음(온보딩 O-50과 같게). 아래 추천값과 다시 채우는 규칙으로 합류 완료 때 자동 저장하고, 예빈은 홈 H-03 ‘월급 계획 고치기’ → W-01에서 고침(2026-11-03 할 일 ‘월급 계획 확인’은 없앰). 합쳐서면 찬우 알림은 그대로. 저장하는 사이 찬우가 공동 월급 계획을 고쳤으면 새 값으로 다시 계산해 저장. 아래 표는 예전 화면(이 화면에서 멈춘 사람만 봄)과 추천값 기준.

O-50과 같은 틀(수입 줄, 저금 묶음, 지출 묶음, 줄 추가, 여유 자금). 관리 방식에 따라 내용이 다름. 금액은 모두 1만 원 단위 반올림, 여유 자금이 음수일 때 표시는 O-50과 같음.

### 각자: 예빈 월급 계획 만들기

### 합쳐서: 공동 월급 계획 확인

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 진행 표시 | 막대 끝까지 | — |
| 2 | 제목·보조 | “같이 쓰는 월급 계획이에요” [확인 필요] / “예빈님 월급을 더해 다시 채웠어요” [확인 필요] | — |
| 3 | 수입 줄 | “월급 620만 원” + 아래 회색 “찬우 350만 원, 예빈 270만 원” [확인 필요] | 두 사람 실수령 합 |
| 4 | 저금 묶음 | 줄마다 새 금액 + 바뀐 줄은 회색 이전 값(“95만 원 → 246만 원”) | 아래 다시 채우는 규칙 |
| 5 | 지출 묶음 | 찬우가 정한 고정지출·생활비·찬우 용돈 그대로 + “예빈 용돈” 줄 추가 | 예빈 용돈 추천값 = 예빈 실수령 × 10% |
| 6 | 줄 추가, 금액 | O-50과 같음 | 예빈도 모든 줄을 고칠 수 있음 |
| 7 | 여유 자금 | “여유 자금 88만 원” | 자동 |
| 8 | 주 버튼 | “이대로 저장하기” | 저장 = 합류 완료 → 홈. 공동 월급 계획이 바뀜, 찬우 알림. 이번 사이클 체크리스트에 예빈 용돈 줄과 늘어난 저금 금액을 바로 더함(체크한 줄은 그대로, → 핵심 규칙 › 월 사이클 3장) |

다시 채우는 규칙 [확인 필요]

- 찬우가 정한 줄(고정지출, 생활비, 찬우 용돈, 저금 금액)은 줄이지 않음
- 늘어난 수입에서 예빈 용돈을 빼고 남은 금액을 저금 묶음 순서대로, 목표 금액과 기한이 있는 저금 항목의 월 필요액까지 저금 줄에 더함. 그래도 남으면 여유 자금
- 찬우가 각자일 때 만든 저금 항목 줄은 “찬우 {이름}”으로 공동 월급 계획에 그대로 있음(→ 월급 탭 ‘저금 항목’)
- 예시(620만 원): 고정지출 88만, 생활비 88만, 찬우 용돈 35만, 예빈 용돈 27만, 내 집 마련 95만 → 246만, 여유 자금 136만

## 시작한 사람이 아직 온보딩 중

찬우가 초대만 보내고 온보딩을 마치기 전(월급 계획이 없음)에 예빈이 합류한 경우.
