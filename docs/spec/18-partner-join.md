# 배우자 합류

## 흐름 요약

휴대폰으로 초대 링크를 받은 예빈이 모바일 앱으로(앱이 없으면 스토어 → 설치 → P-01 코드 입력) 들어와 로그인한 뒤 이름, 출생연도, 관리 방식 확인, 내 월급, 분배표만 답하고 홈으로 감(설치 뒤 약 1~2분, 모바일 앱이나 데스크톱 앱에서 끝까지). 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`, 관리 방식·권한 → 핵심 규칙 › 부부·권한.

| 경우 | 경로 |
| --- | --- |
| 기본 | P-01 → P-02 로그인(A-02 → (A-04) → A-05) → (P-02b) → P-03 → P-03a → P-04 → P-05 → P-06 → 홈 |
| 로그인됨, 부부 공간 없음 | P-01 → (P-02b) → P-03 … |
| 혼자 쓰던 기록 있음 (A-07 6번) | P-01 → P-02a → (P-02b: 겹치는 항목 고르기) → P-03 … |
| 찬우가 대신 입력한 예빈 명의 자산·부채 없음 | P-02b 생략 |
| 찬우가 아직 온보딩 중 (목표·분배표가 없음) | P-03 → P-03a → P-05 → 홈 대기(→ 홈 상태 변형 4). 찬우가 온보딩을 마치면 P-04 → P-06(아래 ‘시작한 사람이 아직 온보딩 중’) |

- 진행 막대: P-03~P-06에 5칸(P-03, P-03a, P-04, P-05, P-06), 막대만(브랜드 오렌지). P-01·P-02는 없음
- ‘나중에 할게요’ 없음
- 결혼 상태, 결혼한 날·예정일(O-11, O-12)은 부부 공간에 하나라 다시 묻지 않음. 출생연도는 사람마다라 P-03a에서 물음
- 합류 완료(P-11)는 따로 화면이 없음: P-06 저장 순간(대기 경우는 P-05 저장 순간). 이때 초대 코드 ‘사용됨’, 찬우에게 알림 “예빈님이 합류했어요”(→ 화면 설계 › 알림)
- 좁은 창(768px 미만): 1열, 주 버튼 화면 아래 고정(→ 화면 설계 › 공통). 모바일 앱이면 합류 완료 직후 푸시 알림 허용을 1회 물음 [확인 필요]
- 예시값: 찬우 실수령 350만 원, 월급날 25일, ‘각자’, 1순위 내 집 마련(월 필요액 250만 원, 찬우 분배표 95만), 비상금(월 필요액 44만, 찬우 분배표 44만), 2순위 여행(금액 미정) → 예빈 실수령 270만 원, 월급날 10일

## P-01 합류 시작

A-07(로그인·가입)의 진입 화면. 링크 분기·합류 불가 안내는 A-07 그대로.

> 화면 그림: P-01 합류 시작, 데스크톱 앱과 모바일 앱 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 그림 | 창으로 타르트가 보이는 크라프트 디저트 상자, 세로 3:4. 열린 상자에 타르트가 들어가고 뚜껑이 닫히고 리본이 묶인 뒤 한 바퀴 돎 | 한 번 재생 후 멈춤. 세로 그림은 이 화면만. 규칙 → 제품 개요 › 브랜드 3장 그림 움직임 규칙 |
| 2 | 제목 | “{나}님이 초대했어요” / 보조 “둘이 같이 쓰는 공간에 합류해요” | {나} = 찬우가 O-03에 적은 이름 |
| 3 | 코드 | 영문 대문자와 숫자 6자(헷갈리는 I, O, 0, 1은 안 씀) | 링크면 자동 입력, 앱 ‘초대받았어요’면 아래 ‘코드 직접 입력’ 먼저 |
| 4 | 로그인된 계정 | “카카오 계정으로 합류해요” + ‘다른 계정’ | 이 기기에 로그인돼 있을 때만. 다른 계정 → 로그아웃 후 A-02 |
| 5 | 주 버튼 | “합류하기” | 코드 확인 → 로그인 전이면 P-02, 로그인됨이면 P-02b 또는 P-03 |

코드 직접 입력 (O-01 ‘초대받았어요’로 들어왔을 때, 주소 `/i`)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 그림 | 위 1번과 같음 | |
| 2 | 뒤로 | < (꺾쇠) | O-01로 |
| 3 | 제목 | “받은 초대 코드를 넣어 주세요” / 보조 “배우자가 보낸 6자리 코드예요” | |
| 4 | 코드 입력 | 이름 “초대 코드”, 한 칸에 6자 | 소문자는 대문자로 바꾸고 영문, 숫자가 아닌 글자는 빼고 받음. 6자인데 쓸 수 없는 글자가 있으면 칸 빨강 + “코드를 다시 확인해 주세요” |
| 5 | 주 버튼 | “다음” | 올바른 6자일 때만 누를 수 있음. Enter도 같음. 누르면 위 표(초대한 사람 확인)로 |

- 코드가 있는지, 만료됐는지는 다음 화면에서 확인(A-07 예외 문구 그대로)
- 로그인 전 ‘합류하기’ → A-02는 초대 문구로 바뀜(→ 로그인·가입 A-02 1, 3번)

예외·오류

- 만료·잘못된 코드·이미 연결됨: A-07 예외 문구 그대로
- 합류 도중 이탈: 같은 링크로 다시 열면 멈춘 화면부터(코드 7일 안). 답은 화면마다 저장

## P-02b 사전 입력 확인·동의

찬우가 합류 전에 우리 자산 탭에서 대신 입력한 예빈 명의 자산·부채(→ 우리 자산 F-03d)를 예빈이 처음 보는 화면. 로그인·약관(A-05) 직후, 이 선택이 동의 기록이 됨.

> 화면 그림: P-02b 사전 입력 확인·동의, 데스크톱 앱과 모바일 앱 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 제목 | “찬우님이 미리 적어 둔 내 정보가 있어요” | — |
| 2 | 항목 목록 | 항목명 + 금액, 추정값은 ‘추정’ | 대상 = 예빈 명의 자산·부채만. 혼자 쓰던 기록과 겹치는 항목은 “내 기록 1,200만 원 / 찬우님 값 1,000만 원” 중 고름 |
| 3 | 주 버튼 | “확인하고 이어 쓸게요” | 동의 기록(항목·시각) → 소유가 예빈에게 넘어가고 ‘대신 입력’ 알약 없어짐. 공개 범위 기본 ‘합계만’ |
| 4 | 보조 링크 | “지우고 새로 입력할게요” | 목록 항목 삭제. 필요하면 나중에 우리 자산 탭에서 직접 추가 |

예외·오류

- 찬우가 대신 입력한 항목이 없으면 화면 생략
- 동의 전에 이탈: 항목은 ‘대신 입력’ 그대로, 다음 접속 때 이 화면부터

## P-02a 혼자 쓰던 기록 옮기기

A-07 6번(혼자 시작한 기록 있음)에서 ‘합류하기’를 누른 사람만. 내 명의 사실값만 옮기고 공개 범위를 한 번 정함.

> 화면 그림: P-02a 혼자 쓰던 기록 옮기기 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 제목 | “내 정보만 옮겨요” | — |
| 2 | 옮길 항목 | 월급·월급날, 내 명의 자산·부채 + 공개 범위 “전체” / “합계만” | 월급은 공개 범위 없음(분배표에 씀, → 핵심 규칙 › 부부·권한 6장). 자산·부채 기본 ‘합계만’ |
| 3 | 안 옮기는 기록 | “안 옮겨요” + 목표·분배표·체크리스트 개수 + “30일 보관 후 지워져요” / ‘사본 내려받기’ | 원래 공간은 30일 보관 후 삭제, 그동안 사본(S-18 ‘내 데이터’ 엑셀) 내려받기 가능 |
| 4 | 주 버튼 | “다음” | 옮긴 월급·월급날은 P-05 초기값. 찬우가 대신 입력한 값과 겹치면 P-02b로 |

예외·오류

- 옮길 내 명의 값이 없으면 2번 대신 “옮길 정보가 없어요”, 3번만 표시

## P-04 관리 방식 확인

찬우가 O-30에서 고른 답을 보여 주고 확인만 받음. 질문 틀은 O-30과 같음.

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 진행 표시 | 막대 5칸 중 3칸 | — |
| 2 | 질문 | “찬우님이 고른 월급 관리 방식이에요” [확인 필요] / 보조 “바꾸면 두 분 모두에게 적용돼요” [확인 필요] | — |
| 3 | 각자 | “각자 월급을 따로 관리해요” + “분배표와 체크리스트가 사람마다 있어요” [확인 필요] | 찬우 답이 선택된 채 열림 |
| 4 | 합쳐서 | “합쳐서 같이 관리해요” + “둘의 월급을 한 분배표로 나눠요” [확인 필요] | — |
| 5 | 주 버튼 | “다음” | → P-05. 바꿨으면 둘 다에게 적용 + 찬우 알림 “예빈님이 월급 관리 방식을 바꿨어요” [확인 필요] |

- 합류 중에 바꾸면 바로 적용(설정에서 바꿀 때처럼 다음 월급날을 기다리지 않음). 예빈 분배표·체크리스트가 아직 없어 합치거나 나눌 것이 없기 때문 [확인 필요]
  - 각자 → 합쳐서: 찬우 분배표가 공동 분배표가 되고 P-06 합쳐서 규칙으로 다시 채움. 찬우 이번 사이클 체크리스트가 공동 체크리스트가 됨
  - 합쳐서 → 각자: 찬우 분배표·체크리스트는 찬우 것으로 남고 예빈은 P-06 각자 규칙으로 자기 분배표를 만듦
- 합류 뒤에는 두 사람 모두 설정 S-11에서 언제든 바꿈(→ 핵심 규칙 › 부부·권한 2장)

## P-05 내 월급

O-31(온보딩 ②)과 같은 화면. 다른 점만 적음.

> 화면 그림: P-05 내 월급 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 진행 표시 | 막대 5칸 중 4칸 | — |
| 2 | 질문 | “한 달에 월급이 얼마 들어와요?” / 보조 “세금 떼고 통장에 들어오는 돈이에요” | O-31과 같음. P-02a에서 옮긴 값이 있으면 채워진 채 열림 |

- ‘지금은 월급이 없어요’: O-31과 같음. 각자면 P-06 저금 줄 0원, 합쳐서면 수입이 늘지 않아 저금은 그대로 두고 예빈 용돈 줄만 0원으로 더함 [확인 필요]

## P-06 월급 분배표

| 생활비 | 예빈 실수령 × 25% |

| 남는 돈 | 저금까지 채우고 남은 금액 |

### 합쳐서: 공동 분배표 확인

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 진행 표시 | 막대 5칸 모두 | — |
| 2 | 제목·보조 | “같이 쓰는 분배표예요” [확인 필요] / “예빈님 월급을 더해 다시 채웠어요” [확인 필요] | — |
| 3 | 수입 줄 | “월급 620만 원” + 아래 회색 “찬우 350만 원, 예빈 270만 원” [확인 필요] | 두 사람 실수령 합 |
| 4 | 저금 묶음 | 줄마다 새 금액 + 바뀐 줄은 회색 이전 값(“95만 원 → 250만 원”) | 아래 다시 채우는 규칙 |
| 5 | 쓰는 돈 묶음 | 찬우가 정한 고정지출·생활비·찬우 용돈 그대로 + “예빈 용돈” 줄 추가 | 예빈 용돈 추천값 = 예빈 실수령 × 10% |
| 6 | 줄 추가, 금액 | O-50과 같음 | 예빈도 모든 줄을 고칠 수 있음 |
| 7 | 남는 돈 | “남는 돈 88만 원” | 자동 |
| 8 | 주 버튼 | “이대로 할게요” | 저장 = 합류 완료 → 홈. 공동 분배표가 바뀜, 찬우 알림. 이번 사이클 체크리스트에 예빈 용돈 줄과 늘어난 저금 금액을 바로 더함(체크한 줄은 그대로, → 핵심 규칙 › 월 사이클 3장) |

다시 채우는 규칙 [확인 필요]

- 찬우가 정한 줄(고정지출, 생활비, 찬우 용돈, 저금 금액)은 줄이지 않음
- 늘어난 수입에서 예빈 용돈을 빼고 남은 금액을 우선순위 순서대로(비상금 → 우리 목표 → 내 목표 [확인 필요]) 각 목표의 월 필요액까지 저금 줄에 더함. 그래도 남으면 남는 돈
- 찬우의 내 목표 줄은 “찬우 {목표 이름}”으로 공동 분배표에 그대로 있음(→ 목표 ‘목표 종류’)
- 예시(620만 원): 고정지출 88만, 생활비 88만, 찬우 용돈 35만, 예빈 용돈 27만, 비상금 44만(그대로), 내 집 마련 95만 → 250만, 여행 0원, 남는 돈 88만

## 시작한 사람이 아직 온보딩 중

찬우가 초대만 보내고 온보딩을 마치기 전(목표·분배표가 없음)에 예빈이 합류한 경우.

| 번호 | 단계 | 내용 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 합류 | P-03 → P-03a → P-05 | P-04·P-06은 건너뜀. P-05 저장 = 합류 완료(초대 코드 ‘사용됨’, 찬우 알림) |
| 2 | 홈 대기 | 인사 “{나}님이 시작하고 있어요” / 카드 “{나}님이 첫 목표를 정하면 알려 드릴게요” | → 홈 상태 변형 4. {나} = 찬우 이름 |
| 3 | 찬우 온보딩 | 찬우 O-30·O-31·O-50 | 합쳐서면 O-50 수입 = 두 사람 합, 예빈 용돈 줄 포함(→ 온보딩 ② O-50 2번, 4번). 각자면 찬우 월급만 |
| 4 | 알림 | 찬우가 O-60을 마치면 예빈에게 “찬우님이 첫 목표를 정했어요” [확인 필요] | 알림 종류 → 화면 설계 › 알림 |
| 5 | 이어서 | 예빈이 다음에 앱을 열면 P-04 → P-06 → 홈 [확인 필요] | 각자: 예빈 분배표 만들기. 합쳐서: 찬우가 이미 두 사람 합으로 만든 공동 분배표를 확인만 |

- 예빈이 답한 이름, 출생연도, 월급, 월급날, 내 명의 항목은 바로 저장
- 찬우 온보딩에는 예빈 월급을 묻는 화면이 없음(합쳐서면 예빈이 넣은 값을 씀)

## 합류 뒤

- 찬우에게 알림 “예빈님이 합류했어요”(→ 화면 설계 › 알림)
- 찬우가 대신 입력한 예빈 명의 자산·부채는 P-02b 확인 뒤 소유가 예빈으로 넘어가 예빈이 수정·삭제(→ 핵심 규칙 › 부부·권한 3장)
- 홈: 각자 방식이면 찬우 홈 체크리스트 카드 아래 “예빈님 3개 중 0개”(→ 홈 H-03)
- 모바일 앱이면 첫 홈 상단에 1회 “PC에서도 같은 계정으로 쓸 수 있어요” + ‘데스크톱 앱 받기 링크 보내기’(알림 이메일로 L-02 주소) / 닫기 [확인 필요]

예외·오류

- 합류 도중 찬우가 분배표를 고침: 합쳐서면 P-06을 열 때의 공동 분배표 기준으로 다시 채움. 저장 직전 바뀌었으면 “찬우님이 방금 분배표를 바꿨어요” [확인 필요] 후 다시 계산한 값으로 보여 줌
- 남는 돈이 음수: O-50과 같이 “{n}만 원이 모자라요” + 안내, 주 버튼은 막지 않음
