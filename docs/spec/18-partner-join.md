# 배우자 합류

## 흐름 요약

초대 링크(웹)로 들어온 예빈이 로그인 후 찬우가 미리 적은 내 정보를 확인하고, 본인 항목만 답한 뒤 찬우가 정한 분담·목표에 응답해 다시 계산된 결과로 합류(약 2\~3분, 설치 없이 웹으로 끝까지).

| 경우 | 경로 |
| --- | --- |
| 기본 | P-01 → P-02 로그인(A-02 → (A-04) → A-05) → (P-02b) → P-03 → P-04 → P-05 → P-06 → P-07 → P-08 → P-09 → P-10 → P-11 → O-63\~65 → 이번 달 |
| 로그인됨, 부부 공간 없음 | P-01 → (P-02b) → P-03 … |
| 혼자 쓰던 기록 있음 (A-07 6번) | P-01 → P-02a → (P-02b: 겹치는 항목 고르기) → P-03 … |
| 찬우가 적은 예빈 정보 없음 | P-02b 생략, P-06은 추가 질문만 |
| ‘각자 관리’ 예비부부 (O-19e) | P-06 → P-09, P-07 용돈·P-08 분담 건너뜀. 두 가지는 결혼일 전환(H-T)에서 물음 |
| 찬우가 아직 온보딩 중 (공간에 플랜이 하나도 없음) | P-03 → P-04 → P-05 → P-06 → P-07 → P-09 → P-11 대기 → 이번 달 대기. P-08 분담, P-10 바뀐 것, O-63\~65 다시 보기 없음(찬우가 온보딩 ② 결과에서 두 사람 값으로 정함). 찬우가 첫 플랜을 만들면 예빈에게 알림 |

- 진행 막대: P-03\~P-10에 4칸, 막대만(P-03·04 / P-05 / P-06·07 / P-08\~10). P-01·P-02는 없음, P-11은 모두 채움
- ‘나중에 할게요’ 없음. P-09만 ‘건너뛰기’, P-06 추가 질문은 ‘없어요’
- 좁은 창(768px 미만): 1열, 주 버튼 화면 아래 고정(→ 화면 설계 › 공통). 웹 알림은 이메일
- 예시값: 찬우 실수령 350만 원·월급날 25일·용돈 50만, 찬우가 적은 예빈 추정 수입 250만 → 예빈 입력 270만 원·월급날 10일·용돈 60만, 분담 ‘직접 정할게요’ 60 : 40, 공동자금 500만 → 520만 원

## P-01 합류 시작

A-07(로그인·가입)의 진입 화면. 링크 분기·합류 불가 안내는 A-07 그대로.

> 화면 그림: P-01 합류 시작, 데스크톱 웹과 좁은 창 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 그림 | 창으로 타르트가 보이는 크라프트 디저트 상자, 세로 3:4. 열린 상자에 타르트가 들어가고 뚜껑이 닫히고 리본이 묶인 뒤 한 바퀴 돎 | 한 번 재생 후 멈춤. 세로 그림은 이 화면만. 규칙 → 제품 개요 › 브랜드 3장 그림 움직임 규칙 |
| 2 | 제목 | “{나}님이 초대했어요” / 보조 “둘이 같이 쓰는 공간에 합류해요” | {나} = 찬우가 정한 자기 호칭 |
| 3 | 코드 | 영문 대문자와 숫자 6자(헷갈리는 I, O, 0, 1은 안 씀) | 링크면 자동 입력, 앱 ‘초대받았어요’면 아래 ‘코드 직접 입력’ 먼저 |
| 4 | 로그인된 계정 | “카카오 계정으로 합류해요” + ‘다른 계정’ | 이 브라우저에 로그인돼 있을 때만. 다른 계정 → 로그아웃 후 A-02 |
| 5 | 주 버튼 | “합류하기” | 코드 확인 → 로그인 전이면 P-02, 로그인됨이면 P-02b 또는 P-03 |

코드 직접 입력 (O-01 ‘초대받았어요’로 들어왔을 때, 주소 `/i`)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 그림 | 위 1번과 같음 | |
| 2 | 뒤로 | < (꺾쇠) | O-01로 |
| 3 | 제목 | “받은 초대 코드를 넣어 주세요” / 보조 “배우자가 보낸 6자리 코드예요” | |
| 4 | 코드 입력 | 이름 “초대 코드”, 한 칸에 6자 | 소문자는 대문자로 바꾸고 영문, 숫자가 아닌 글자는 빼고 받음. 6자인데 쓸 수 없는 글자가 있으면 칸 빨강 + “코드를 다시 확인해 주세요” |

- 합류 도중 이탈: 같은 링크로 다시 열면 멈춘 화면부터(코드 7일 안)

## P-02b 사전 입력 확인·동의

찬우가 미리 적은 예빈 정보(보안·개인정보)를 예빈이 처음 보는 화면. 로그인·약관(A-05) 직후, 이 선택이 동의 기록이 됨.

> 화면 그림: P-02b 사전 입력 확인·동의, 데스크톱 웹과 좁은 창 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 제목 | “찬우님이 미리 적어 둔 내 정보가 있어요” | — |
| 2 | 항목 목록 | 항목명 + 금액, 추정값은 ‘추정’ | 대상 = 예빈 수입(O-33), 예빈 명의 자산·부채, 대신 입력한 출생연도·일하는 방식·용돈. 혼자 쓰던 기록과 겹치는 항목은 “내 기록 270만 원 / 찬우님 값 250만 원” 중 고름 |
| 3 | 주 버튼 | “확인하고 이어 쓸게요” | 동의 기록(항목·시각) → 값이 P-04\~P-07 초기값으로. 추정 표시는 예빈이 확인할 때까지 유지 |
| 4 | 보조 링크 | “지우고 새로 입력할게요” | 목록 항목 삭제 → P-04\~P-07 빈 칸, P-06은 추가 질문만 |

예외·오류

- 찬우가 적은 값이 없으면 화면 생략
- 동의 전에 이탈: 찬우 쪽 값은 ‘추정’ 그대로, 다음 접속 때 이 화면부터

> 화면 그림: P-02a 혼자 쓰던 기록 옮기기 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 5 | 주 버튼 | “다음” | 다르면 찬우에게 용돈 제안. 찬우 응답은 ‘좋아요’ / ‘반대’만(다르게 해볼래요 없음) |
| 6 | 질문 | “같이 쓰는 돈 나누는 방식, 괜찮아요?” | — |
| 7 | 방식 카드 | 찬우가 고른 방식 + 예빈 실제 수입으로 다시 계산한 두 사람 금액 | 찬우가 ‘나중에 할게요’였으면 “반반” |
| 8 | 좋아요 | “좋아요” | 즉시 확정, 안 나눈 돈 재계산 → P-09 |
| 9 | 다르게 해볼래요 | “다르게 해볼래요” | O-52 화면(선택지·슬라이더)에서 고른 안을 찬우에게 제안. 찬우 응답 ‘좋아요’ / ‘다르게 해볼래요’ / ‘반대’, 적용일 표시는 4번과 같음 |

예외·오류

- 찬우가 반대: 보류, 기본값 유지. 다음 월말 정리 W-04h에서 다룸
- 분담 ‘다르게 해볼래요’ 2회 왕복: 함께 정하기(→ 핵심 규칙 › 부부·제안·권한)

## P-11 합류 완료

O-62 형식으로 다시 계산한 결과. 사이클 중간 합류면 이번 플랜은 그대로, 안 나눈 돈만 재계산.

규칙 확정 전 기본값·사실값 즉시 반영 → 핵심 규칙 › 부부·제안·권한, 기준일 변경·사이클 조정 → 핵심 규칙 › 월 사이클

> 화면 그림: P-11 합류 완료, 데스크톱 웹과 좁은 창 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 그림 | 지금은 없음(장면 그림을 정하면 결과 카드 위에) | — |
| 2 | 결론 | “두 분은 한 달에 {저축 가능 금액}을 모을 수 있어요” | ‘임시 플랜’ 배지 없음(추정값이 남았을 때만 O-66 표대로) |
| 3 | 결과 카드(ResultCard) | “한 달에 모을 수 있는 돈” / 큰 금액 + 취소선 이전 값 / 체크 줄 “월 수입” 새 값 + 이전 값, “나누는 방식”, “{나}님이 매달 넣을 돈”, “{배우자}님이 매달 넣을 돈” [확인 필요] | 바뀐 값만 이전 값 표시. 분담 확정 전이면 찬우가 고른 방식 유지(없으면 반반). 그림 자리 없음 |
| 4 | 답 기다리는 제안 | 항목 전 → 후 + 적용일 | P-07·P-08·P-10에서 보낸 제안이 있을 때만. 확정 전 플랜은 3번 분담 + 예빈 용돈 = 찬우 용돈 |
| 5 | 플랜 상태 | “{월}월 월급 플랜은 그대로, 안 나눈 돈만 다시 계산했어요” | 새 플랜은 다음 기준일부터. 합류 완료 순간 초대 코드는 ‘사용됨’(다시 쓸 수 없음) |
| 6 | 주 버튼 | “다음” | O-63 → O-64 → O-65(바뀐 값 강조), O-65 버튼 “이번 달로” |

- 합류하면 찬우에게 알림 “예빈님이 합류했어요”(→ 화면 설계 › 알림) + 받은 제안이 있으면 할 일(H-04). 찬우가 대신 입력한 예빈 명의 자산·부채는 소유가 예빈으로 넘어가 예빈이 수정·삭제(→ 핵심 규칙 › 부부·제안·권한)
- 웹이면 첫 이번 달 화면 상단에 1회 “데스크톱 앱을 설치하면 앱 알림도 받을 수 있어요” + ‘설치하기’(→ 웹사이트 L-02, OS에 맞는 파일 받기 바로 시작) / 닫기

P-11 대기 (찬우가 아직 온보딩 중일 때)

찬우가 초대만 보내고 온보딩을 마치기 전(공간에 플랜이 하나도 없음)에 예빈이 합류한 경우. 찬우 수입, 지출, 분담이 없어 두 사람 결과를 계산하지 않음.

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 결론 | “{나}님 공간에 합류했어요” / 보조 “{나}님이 플랜을 마치면 같이 볼 수 있어요” | {나} = 찬우 호칭. 진행 막대 모두 채움 |
| 1a | 완료 표시, 요약 | 큰 체크(DoneMark) + 회색 판 “내가 답한 것” [확인 필요] / “월 수입” / “월급날” / “내 용돈” | P-05, P-07에서 답한 값 |
| 2 | 주 버튼 | “이번 달로” | 이번 달 대기(→ 이번 달 H-01). 합류 완료와 초대 코드 ‘사용됨’은 위 표와 같음 |

- 예빈이 답한 수입, 월급날, 용돈, 내 명의 항목은 바로 저장. 찬우 온보딩은 예빈 수입을 묻지 않고(O-33 건너뜀) 예빈 값으로 계산(→ 온보딩 ② O-33)
- P-07 초기값: 찬우 용돈이 아직 없으면 빈 칸, 제안 없이 예빈 용돈으로 바로 저장
- 찬우가 첫 플랜을 만들면(O-66) 예빈에게 알림 “찬우님이 첫 플랜을 만들었어요” / “이번 달 월급 플랜을 같이 볼 수 있어요”(→ 화면 설계 › 알림). 분담을 다르게 하고 싶으면 그 뒤 제안으로

예외·오류

- 예빈 월급날이 더 늦어 기준일이 바뀜: 이번 사이클을 새 기준일 전날까지로 줄임, 15일 미만이면 다음 사이클과 합치고 7번 대신 “이번 달은 기간이 짧아서 다음 달과 합쳐 정리해요”
- 모을 돈 0 이하: O-62 예외와 같음(지출 점검 카드)
