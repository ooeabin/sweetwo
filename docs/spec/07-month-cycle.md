# 월 사이클

월급날 0시에 그달 확인 목록(월급 체크리스트)이 생기고, 월급날에 한 번 “모두 계획대로 됐어요”로 확인하면 끝. 자동으로 나가는 줄은 나가는 날에 앱이 알아서 확인하고, 손으로 확인할 줄이 남았을 때만 다음 월급날 3일 전에 한 번 더 알려요. 매일 기록 없음. 화면 → 월급 체크리스트, 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`, 2026-11-13 확인 한 번·자동 줄·날짜 없음 → `docs/adr/0009-save-together-plan.md`(결정 2·3·3-1·4).

용어(2026-11-13): 기획서 안에서 ‘손 줄’ = 체크리스트에 넣었고 자동 줄이 아닌 줄(사람이 확인), ‘자동 줄’ = ‘은행에서 자동으로 나가요’를 켠 줄(`split_line.auto_pay`). 사용자에게는 ‘확인할 것’, ‘자동으로 나가는 것’. ‘못 함’은 사용자에게 ‘건너뜀’(“이번 달은 건너뛸게요”, DB 상태 값은 그대로).

## 1. 월급날과 사이클

- 월급날: 사람마다 등록(O-32, 설정 S-11). 그 달에 없는 날(29~31일)이면 말일
- 월급날이 정해져 있지 않은 사람(O-32 ‘날짜가 정해져 있지 않아요’, `app_user.payday_none`, 2026-11-13): 사이클과 확인 목록이 없고 6장 ‘기간’으로 봐요
- 체크리스트를 만드는 날(기준일)
  - 각자: 사람마다 자기 월급날
  - 합쳐서: 두 사람 월급날 중 늦은 날(설정 S-11에서 바꿈). 파트너 합류 전에는 내 월급날. 한 사람이 날짜 없음이면 다른 사람 월급날, 둘 다 없으면 확인 목록 없음
- 월급날이 주말·공휴일이면 직전 영업일로 앞당겨 표시(체크리스트 제목, 캘린더). 표시만 바뀌고 사이클은 그대로. 설정에서 끌 수 있음. 공휴일은 특일 API holiday 표
- 모든 날짜·사이클 경계·알림 시각·방해 금지 시간은 한국 시간(KST) 기준, 기기 시간대는 무시
- 사이클 = 기준일 0시 ~ 다음 기준일 전날 자정
- 이름(2026-11-13): ‘{월} {일}일 월급’(“10월 25일 월급”) [확인 필요]. 예전 ‘{월}월 월급’ + 기간 표기는 바꿈

## 3. 체크리스트 생성

- 기준일 0시에 그 시점 월급 계획을 복사. 따로 확인하는 단계 없음
- 넣는 줄(2026-11-13): `split_line.in_checklist`가 켜진 줄만. 기본값은 저금·고정지출·같이 쓰는 통장·보내기 켬, 생활비·용돈 끔(→ 06 3-1). 여유 자금 줄은 넣지 않음
- 자동 줄: `auto_pay`가 켜진 줄은 `pay_check_line.auto = true`, `auto_due` = 그 사이클의 나가는 날(`auto_day`, null = 월급날, 31 = 말일, 그 달에 없는 날이면 말일). 사이클 시작일보다 앞선 날이면 다음 달의 그날. 상태는 ‘대기’
- 월급 계획이 바뀌면 이번 사이클의 체크 안 한 줄만 새 금액으로, 체크한 줄(자동 확인 포함)은 그대로(→ 월급 체크리스트 ‘다시 계산되는 때’)
- 파트너 합류
  - 각자: 파트너 월급 계획은 파트너가 합류할 때 만들고(P 화면), 파트너 첫 확인 목록은 다음 월급날에 만듦(소급 없음, 2026-11-13)
  - 합쳐서: 이번 사이클 확인 목록에 파트너 용돈·보내기 줄과 늘어난 저금 금액을 바로 더함(체크한 줄은 그대로). 다음 사이클부터 두 사람 합 기준
- 기준일이 바뀌면(월급날 변경, 관리 방식 변경, 합쳐서 기준일 변경) 이번 사이클 끝 = 새 기준일 전날, 다음 확인 목록은 새 기준일에

### 3-1. 첫 사이클 (2026-11-13 고침: 소급 없음)

- 온보딩(O-60)이나 합류에서 확인 목록을 만들지 않음. 첫 확인 목록은 다음 월급날 0시에 만듦(`onboarding_reset_plan`은 월급 계획만 저장)
- 그 전까지 홈 H-11은 “11월 25일 첫 월급날에 확인해요” [확인 필요](→ 19 H-11)
- 첫 월급날 7일 전 ~ 전날, 자동 줄이 0개이고 손 줄이 1개 이상이면 홈 띠 “자동으로 나가는 걸 골라 주세요”(W-01d) [확인 필요]
- 예전 규칙(온보딩 직후 지난 월급날 기준으로 소급해 만듦, “지금부터 체크할 수 있게”)은 없앰

## 4. 월급 전 확인과 늦은 확인

- 기간 = 다음 기준일 3일 전 ~ 기준일 전날. **손 줄**이 남았을 때만 알림 1회 + 홈 H-11 문장. 자동 줄만 남았으면(대기 중) 알림도 문장도 없음. W-05는 알림·H-11이 가리킨 확인 목록의 남은 손 줄만 보여 주고, 기간 밖이거나 사이클이 끝났으면 W-02(2026-11-12 D3, core `inReviewWindow`)
- 합쳐서면 한 사람이 해도 그 확인 목록에 반영(용돈 줄은 주인만, 2026-11-13). 각자면 주인만
- 늦은 확인(2026-11-13): 다음 기준일 0시에 남은 손 줄은 ‘건너뜀’으로 닫히지만, 그 다음 사이클이 끝날 때까지 W-02 지난 달에서 확인할 수 있음(`pay_check_line.late = true`, `check_pay_line`이 허용). 늦게 확인한 저금 줄은 확인한 그때 모은 금액에 더함. 그 기간이 지나면 읽기 전용
- ‘이번 달은 건너뛸게요’로 닫은 저금 줄과 건너뜀으로 닫힌 저금 줄은 저금 모은 금액에 더하지 않음. 예상 달성일이 늦어지고, 기한이 있으면 월 필요액이 늘어남
- 모은 금액이 실제와 다르면 ‘모은 금액 바로잡기’(W-10b)로 고침(ADR 0009 결정 4, 예전 ‘넣기·빼기가 없어 고칠 수 없음’은 바꿈)

## 5. 월급 변경 적용 (2026-11-13, G12)

- 설정 S-11c에서 금액을 바꾸면 “언제부터 이 금액이에요?”(연·월, 처음 값 이번 달) + 선택 “언제까지예요?” [확인 필요]. 저장 = `salary_change`(effective_from = 그 달 1일, until_month, revert_amount)
- 적용 작업 `apply_salary_changes()` 매일 00:01 KST(확인 목록 생성보다 먼저): effective_from이 속한 사이클이 오늘 시작하면 그 금액을 내 월급으로. until이 지난 다음 사이클 시작에 revert_amount로 되돌림
- ‘이번 사이클’이면 저장 즉시 적용(이번 사이클의 체크 안 한 줄은 다시 계산)
- 한 사람 관리형의 관리하지 않는 쪽이면 ‘보내기’ = 월급 − 용돈을 다시 계산(→ 06 3-2, 트리거 `recalc_send_line`)
- 적용된 사이클 첫 7일(또는 W-01을 열 때까지) 홈 띠 “월급이 바뀌었어요. 월급 계획을 다시 맞춰 볼까요?” [확인 필요] → W-01. 푸시 없음

## 6. 월급날이 정해져 있지 않은 사람: 기간 (2026-11-13, G8)

확인 목록, ‘월급날’·‘월급 전 확인’ 알림이 없어요. 대신 ‘기간’으로 들어온 돈과 필요한 돈을 봐요.

- 기간 하나 = 30일. 시작일 S = ‘돈이 들어온 날’(`money_in.received_on`), 끝 E = S + 29일
- 첫 기간: 처음 돈 들어온 날이 S. 그 전(온보딩 직후)에는 기간 없음
- 다음 기간: E가 지난 뒤 처음 돈이 들어온 날이 새 S. E 다음 날부터 새 S 전날까지는 ‘빈 날’로 어느 기간에도 넣지 않음
- 기간 안에 들어온 돈은 종류와 상관없이 모두 그 기간에 더함. 받은 날을 고쳐 기간 밖이 되면 그 기간으로 옮김
- 필요한 돈 = 그 기간 시작 때 월급 계획 모든 줄 합(저금 + 고정지출 + 생활비 + 용돈 + 직접 추가한 줄 + 같이 쓰는 통장 몫, ‘체크리스트에 넣기’와 상관없이). 여유 자금은 넣지 않음
- 상태와 보여 주는 때(H-11 자리 = H-13)
  - 기간 없음(첫 돈 전): “돈이 들어오면 알려 주세요” [확인 필요]
  - 1~15일째(early): “이번 기간 들어온 돈 340만 원” [확인 필요]
  - 16일째(S + 15)부터 E까지(bar): 막대 “들어온 돈 340만 원 / 필요한 돈 380만 원” [확인 필요], 중립 색, 판정 문장 없음. 들어온 돈 ≥ 필요한 돈이면 보조 “남는 돈은 저금에 넣을 수 있어요” [확인 필요]
  - 빈 날(gap): “지난번 돈이 들어온 지 41일 됐어요” [확인 필요]
- 자동 줄: 나가는 날(기본 매달 1일, 줄마다 바꿈)에 자동 확인. 확인 목록이 없으므로 저금 자동 줄은 `goal_move(in, reason_code = auto)`로 모은 금액에 더함. 지출 자동 줄은 기록 없음. 기간과 따로 돎
- 알림: 진행 소식은 매달 1일 오전 9시 1회(끌 수 있음). 기간 막대는 알림 없음
- core `moneyInPeriod(moneyIns, today)`가 S, E, 들어온 돈, 상태(none/early/bar/gap, 빈 날 일수)를 돌려주고 서버 `money_in_period(p_user, p_today)`와 같은 결과(→ 06 2-2 예시)

## 7. 사이클 상태

| 상태 | 바뀌는 조건 |
| --- | --- |
| 진행 중 | 기준일 0시 |
| 확인 끝 | 손 줄이 모두 체크 또는 건너뜀(자동 줄은 따로 요구하지 않음, 2026-11-13). “모두 계획대로 됐어요”를 누르면 남은 손 줄을 계획 금액으로 체크하고 `confirmed_at`, `confirmed_by` 기록(`confirm_payday`). 모두 체크면 “{월} {일}일 월급, 계획대로 됐어요”, 건너뜀이 섞이면 “{월} {일}일 월급, 확인을 마쳤어요” [확인 필요](W-02 한 줄·Toast, 파트너 인앱 알림. 자동 확인만으로는 파트너 알림 없음) |
| 닫힘 | 다음 기준일 0시. 남은 손 줄은 ‘건너뜀’, 다음 사이클 끝까지 늦게 확인 가능, 그 뒤 읽기 전용 |
