# 로그인·가입

## 흐름 요약

로그인은 카카오·구글·애플 소셜만(이메일·비밀번호 없음). 계정 복구 = 같은 소셜 계정으로 재로그인, 소셜 계정 분실은 고객 문의.

| 진입 | 경로 |
| --- | --- |
| 첫 실행 (데스크톱) | A-01 → O-01 ‘시작하기’ → A-02 → A-03 → 신규: (A-04) → A-05 → A-06 설정 → O-03 / 기존 계정: 이번 달 |
| 첫 방문 (웹) | L-01 ‘웹에서 시작하기’ 또는 주소 직접 입력 → O-01 ‘시작하기’ → A-02 → 신규: (A-04) → A-05 → O-03(온보딩 O 전체 웹에서 가능) / 기존 계정: 이번 달 |
| 재방문, 세션 유효 | A-01 → 잠금 켜짐이면 A-06 해제 → 이번 달 (온보딩 미완료면 멈춘 화면부터) |
| 재방문, 세션 없음 | A-01 → A-02 (최근 사용 방법 표시) → 데스크톱에 PIN이 없으면 A-06 |
| 초대 링크 (웹) | A-07 → P-01 → A-02(P-02) → 신규면 (A-04) → A-05 → P-03 |
| 앱에서 ‘초대받았어요’ | O-01 → P-01 코드 직접 입력 → A-02 → A-03 → 신규면 (A-04) → A-05 → P-03 |
| 세션 만료, 웹 무활동 잠금 | A-08 → A-02 → 하던 화면으로 복귀 |
| 메일 링크, 세션 없음 | A-02 → 로그인 뒤 링크가 가리키는 원래 화면으로. 대상이 없거나 상대 소유 비공개 항목이면 이번 달 + 토스트 “열 수 없는 항목이라 이번 달로 왔어요” |

## A-01 실행·자동 로그인 판단

> 화면 그림: A-01 실행, 스플래시와 강제 업데이트 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 로고 | sweeTwo 워드마크 | 판단 끝나면 바로 다음 화면(최소 표시 시간 없음) |
| 2 | 진행 표시 | 막대 | 0.3초 미만이면 숨김. 판단 순서: 최소 지원 버전 → 세션 → 앱 잠금 |
| 3 | 업데이트 안내 | “새 버전으로 업데이트해 주세요” / 보조 “지금 버전으로는 저장할 수 없어요” | 최소 지원 버전 미만일 때만. 오프라인 대기열 보존 |
| 4 | 주 버튼 | “지금 업데이트” | 다운로드 → 서명 검증 → 설치 → 재시작 |
| 5 | 보조 링크 | “업데이트 없이 보기만 할게요” | 조회만, 입력 비활성 |

- 최소 지원 버전 이상 새 버전: 백그라운드 다운로드 후 이번 달에 “새 버전이 준비됐어요” + ‘지금 다시 시작’
- 업데이트 뒤 첫 실행: 이번 달에 토스트 1회 “새 버전으로 업데이트했어요” + 링크 “새 버전에서 달라진 점”(→ 웹사이트 L-03, 그 버전 위치)

예외·오류

- 오프라인 + 세션 있음: 마지막으로 받은 데이터로 이번 달
- 오프라인 + 세션 없음: “인터넷에 연결하면 로그인할 수 있어요” + ‘다시 시도’
- 다운로드·서명 검증 실패: “업데이트를 받지 못했어요” + ‘다시 시도’(서명 실패는 ‘문의하기’ S-19)
- 기기 저장소 열기 실패: 캐시 삭제 후 서버에서 다시 받음
- 웹: 스플래시 없이 스켈레톤. 새 배포는 “새 버전이 있어요” + 새로고침

## A-02 로그인 방법 선택

로그인·가입 한 화면(새 계정이면 바로 가입). 온보딩 O-02·합류 P-02의 상세.

> 화면 그림: A-02 로그인 방법 선택, 데스크톱과 좁은 창 웹 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 로고 | 영어 워드마크(sweeTwo, 높이 56px 히어로). 장면 그림·영상은 없앰(2026-10-19). 초대로 들어왔을 때(P-01 ‘합류하기’)는 워드마크 대신 초대한 사람 아바타(72px, 글자 아바타 `person-1`) | 움직임 없음. 규칙 → 제품 개요 › 브랜드 3장 장면 자리 규칙 |
| 2 | 뒤로 | ← | O-01 또는 P-01로. 재방문 직행이면 숨김 |
| 3 | 캐치프레이즈 | “함께 구워 더 달콤한 자산파이”(→ 브랜드 4장 슬로건, 하나만 씀). 보조문구 없음. 초대로 들어왔을 때는 “{나}님 공간에 합류할 계정을 골라요”({나} = 초대한 사람 호칭) | 워드마크 히어로 아래 큰 제목(`hg-auth__title`). 초대 문구는 히어로 크기가 아닌 기본 제목 크기. 움직임 없음 |
| 4 | 최근 사용 말풍선 | “최근 사용” | 이 기기에서 마지막으로 쓴 방법 하나만. 해당 버튼 위 오른쪽에 말풍선(꼬리 아래 방향, `hg-auth__recent`)으로 표시 |
| 5 | 소셜 버튼 | 왼쪽 제공자 마크 + “카카오로 3초 만에 시작하기” / “Google로 시작하기” / “Apple로 시작하기” | 제공자 마크는 버튼 왼쪽에 고정, 글자는 가운데, 글자 굵기 700(ZIGZAG식). 카카오는 공식 노란 브랜드 버튼(바탕 노랑 + 어두운 글자·말풍선 심볼). 구글·애플은 테두리 버튼(secondary) + 마크(구글 4색 G, 애플 검정·다크 바탕에선 흰색). 데스크톱: 기본 브라우저 → A-03 → 딥링크 복귀. 웹: 팝업·리다이렉트. 완료 시 신규 A-05(카카오 이메일 미제공이면 A-04 먼저), 기존 이번 달 |
| 6 | 로그인 유지 | “이 기기에서 로그인 유지” | 웹만, 기본 꺼짐. 켜면 최대 14일, 끄면 탭을 닫을 때 로그아웃(sessionStorage). 세션은 브라우저 저장소 기반 + 강한 CSP(→ 보안·개인정보 2장) |

- 웹 소셜 로그인: 넓은 창은 팝업(막히면 리다이렉트), 좁은 창은 리다이렉트
- 이메일: 소셜 계정에서 받아 알림에만 사용. 계정 식별 = 제공자 + 제공자 계정 ID
- 카카오 이메일 제공 거부 시 신규만 A-04. 애플 ‘이메일 가리기’ 주소는 그대로 사용

예외·오류

- 같은 이메일이 다른 소셜로 가입됨: 자동 합치기 없음. “이미 {카카오}로 가입한 이메일이에요” + 해당 버튼 강조
- 제공자 오류: “{제공자} 로그인에 문제가 생겼어요. 다른 방법으로 해볼까요?”
- 오프라인: 버튼 비활성 + “인터넷에 연결되면 할 수 있어요”
- 삭제 요청 30일 안 계정: “계정 삭제를 취소할까요?” → ‘취소하고 계속 쓰기’ / ‘그대로 두기’. 복구하면 ‘혼자 쓰기’ 상태로 돌아오고 30일 안 재연결 가능(S-12 “다시 연결하기”), 상대에게 ‘계정 복구’ 알림 1종

데스크톱 앱만. 기본 브라우저로 소셜 로그인 후 딥링크로 앱 복귀.

> 화면 그림: A-03 브라우저 로그인 대기, 앱과 브라우저 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 제공자 표시 | 로고 + “카카오로 로그인” 등 | A-02에서 누른 제공자 |
| 2 | 안내 | “브라우저에서 로그인 중이에요” / 보조 “로그인을 마치면 앱으로 돌아와요” | A-02 버튼 즉시 브라우저를 열고 표시 |
| 3 | 다시 열기 | “브라우저 다시 열기” | 같은 로그인 요청으로 다시 엶 |

| 5 | 복귀 페이지(브라우저) | “로그인을 마쳤어요” / 보조 “sweeTwo 앱으로 돌아가요” + ‘sweeTwo 열기’ | 딥링크로 자동 복귀, 안 되면 ‘sweeTwo 열기’. 신규 A-05(카카오 이메일 미제공이면 A-04 먼저) / 기존 이번 달 |

- 딥링크 결과는 이 기기가 시작한 요청과 일치할 때만 처리

예외·오류

- 5분 지나도 복귀 없음: “로그인이 끝나지 않았어요. 다시 시도해 주세요”
- 브라우저에서 취소·동의 거부: A-02, “로그인을 취소했어요”
- 요청 불일치·만료: 결과 버림 → A-02, “다시 로그인해 주세요”
- 브라우저 열기 실패: “브라우저를 열지 못했어요” + ‘다시 시도’
- 대기 중 앱 종료: 다음 실행 때 A-02부터
- 이메일 중복·제공자 오류: A-02 예외와 같음

> 화면 그림: A-04 알림 이메일 입력 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 질문 | “알림 받을 이메일을 알려주세요” / 보조 “주간 요약·초대·제안 메일을 보내요” | — |
| 2 | 이메일 입력 | 자리표시 “name@example.com” | 공백 제거·소문자 저장. 형식 검사만, 인증 메일 없음. 다른 계정의 소셜 이메일과 같아도 허용(식별에 안 씀). 변경은 설정 ‘알림 이메일’ |

- 뒤로·앱 종료: 가입 취소(계정 미생성), 다음엔 A-02부터
- 나중에 카카오 이메일 제공에 동의해도 입력한 알림 이메일 유지

## A-05 약관 동의

> 화면 그림: A-05 약관 동의 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 전체 동의 | “모두 동의해요” | 회색 판 위 큰 줄, 동그라미 체크. 켜면 전부 체크, 하나라도 끄면 해제 |
| 1a | 필수 묶음 | “\[필수\] 서비스 이용에 동의해요” [확인 필요] + 펼치기 | 동그라미 체크로 필수 3개를 한 번에. 처음엔 펼쳐 둠, 접으면 묶음 줄만. 하위 약관은 작은 체크 표시(카카오뱅크식) |
| 2 | 필수 약관 | “\[필수\] 이용약관” / “\[필수\] 개인정보 수집·이용” / “\[필수\] 배우자와 부부 공간 공유” | 개인정보 = 소셜 로그인 정보·호칭·입력값·접속 기록. ‘보기’: 웹사이트 L-05 약관 페이지의 해당 항목을 앱 안 보기로 엶(원본은 저장소 마크다운 하나). 동의 기록: 항목·버전·시각 |
| 3 | 선택 | “\[선택\] 마케팅 정보 받기” + ‘보기’ | 선택 동의는 이 1개. 이메일·앱 알림, 광고성 발송은 월 1회까지(→ 화면 설계 › 알림). 2년마다 재확인, S-14에서 변경 |
| 4 | 주 버튼 | “동의하고 계속하기” | 필수 3개 체크 시 활성 → 계정 생성(A-04 이메일 함께) → 데스크톱 A-06 / 웹 O-03 / 합류자 P-03 |

예외·오류

- 가입은 만 18세 이상만. 약관 화면에 나이 확인 항목 없음, O-13 태어난 해로 확인. 만 18세 미만이면 “만 18세부터 쓸 수 있어요” 안내 후 계정 즉시 삭제(→ 온보딩 ① O-13)
- 약관 개정: 다음 실행 때 바뀐 필수 항목만 재동의
- 동의 종류는 8종(→ 보안·개인정보 5-1). 가입 때는 필수 3종과 마케팅 수신만, 가족 정보와 사진(챙길 날)은 처음 등록할 때, 분석 수집은 S-14, 통계 참여는 F-08에서. 프로필 사진은 별도 동의 없음
- 계정 생성 실패: “잠시 문제가 생겼어요. 다시 시도해 주세요” + ‘다시 시도’

## A-06 앱 잠금 설정·해제

데스크톱 앱만. 설정 값 변경은 S-15.

> 화면 그림: A-06 앱 잠금, 설정과 해제 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 설정 질문 | “앱을 열 때 쓸 PIN 6자리를 정해 주세요” / 보조 “자리를 비우면 5분 뒤 잠겨요” | 데스크톱에서 이 기기에 PIN이 없을 때 첫 로그인 직후 1회(신규·새 기기 공통) → “한 번 더 입력해 주세요” → Touch ID 지원 Mac이면 “Touch ID로도 풀까요?” |
| 2 | PIN 입력 | 점 6개 | 6자리면 자동 다음. 같은 숫자 6개·연속 숫자 불가 |
| 3 | 나중에 | “나중에 할게요” | 잠금 꺼진 채 시작, 이번 달 ‘할 일’에 남김 |
| 4 | 해제 PIN | “PIN을 입력해 주세요” | 실행 시·자동 잠금(기본 5분)·Ctrl(⌘)+L 뒤 |
| 5 | 생체 버튼 | “Touch ID로 풀기” | MVP는 macOS Touch ID만(Windows Hello는 네이티브 모듈이 필요해 출시 뒤). 켠 경우 자동 요청, 실패·취소 시 PIN |
| 6 | 잊었어요 | “PIN을 잊었어요” | 재로그인(A-02) 후 PIN 새로 만들기 |

예외·오류

- 확인 PIN 불일치: “PIN이 서로 달라요”, 처음부터 다시
- 해제 PIN 틀림: “PIN이 맞지 않아요”, 3회째부터 “{n}번 더 틀리면 다시 로그인해야 해요”
- 5회 실패: 로그아웃(대기열 전송 시도 후 로컬 데이터 삭제) → A-02
- Windows, Touch ID 미지원·미등록 Mac: 생체 질문·버튼 숨김
- 잠금 화면·앱 전환 미리보기(작업 전환기·Dock 미리보기): 금액 가리기 설정과 상관없이 모든 금액 “•••”로 자동 가림. 해제하면 원래 설정대로 표시(→ 화면 설계 › 공통)
- 웹: PIN 없음. 30분 무활동이면 A-08

## A-07 초대 링크 진입

> 화면 그림: A-07 초대 링크 진입, 네 갈래 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 초대 문구 | “{나}님이 초대했어요” / 보조 “둘이 같이 쓰는 공간에 합류해요” | {나} = 초대한 사람 호칭. 웹에서 설치 없이 끝까지 |
| 2 | 코드 | 영문 대문자와 숫자 6자 | 링크면 자동 입력, 앱 ‘초대받았어요’면 직접 입력(→ 18 배우자 합류 P-01 코드 직접 입력) |
| 3 | 주 버튼 | “합류하기” | 코드 확인 후 4\~7번 분기 |
| 4 | 로그인 전 | — | A-02(P-02) → 신규면 (A-04) → A-05 → P-03. 기존 계정은 로그인 뒤 5·6번 |
| 5 | 로그인됨, 공간 없음 | — | 바로 P-03(온보딩 시작 전 계정 포함) |
| 6 | 혼자 시작한 기록 있음 | “이미 시작한 기록이 있어요” / 보조 “수입·자산 같은 내 정보만 옮겨요” | ‘합류하기’ / ‘취소’. 내 명의 수입·월급날·자산·부채·용돈만 옮김(공개 범위 1회 확인). 목표·플랜·월말 기록은 안 옮김(사본 내보내기 안내). 초대한 사람이 적어 둔 내 값과 겹치면 사전 입력 확인(P-02b)에서 고름 |
| 7 | 합류 불가 | 예외 문구 | 안내 + ‘이번 달로’ |

예외·오류

- 만료(7일): “초대가 만료됐어요. 새 코드를 요청해 주세요”. 초대한 사람에게는 만료 알림과 새 코드 만들기 안내(→ 알림)
- 잘못된 코드: “코드를 다시 확인해 주세요”, 5회 오류 시 10분 제한 “10분 뒤에 다시 입력해 주세요”
- 이미 다른 배우자와 연결됨: “이미 부부 공간이 연결돼 있어요”
- 내가 만든 코드: “내가 만든 초대 코드예요”
- 이미 합류가 끝난 초대: “이미 합류가 끝난 초대예요”(P-11 합류 완료 때 코드는 ‘사용됨’)
- 초대한 사람이 계정 삭제: “사용할 수 없는 초대예요”
- 합류 끝(P-11) 뒤 데스크톱 앱 설치 안내(선택)

## A-08 세션 만료·새 기기 로그인 안내

> 화면 그림: A-08 세션 만료, 새 기기 알림 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 안내 | “다시 로그인해 주세요” / 보조 = 사유 | 웹 14일 경과 “로그인한 지 14일이 지났어요” / 웹 30분 무활동 “오래 자리를 비워서 잠갔어요” / 다른 기기에서 로그아웃 “다른 기기에서 로그아웃했어요” |
| 2 | 주 버튼 | “로그인하기” | A-02 → 같은 계정이면 하던 화면으로 |
| 3 | 다른 계정 | “다른 계정으로 로그인” | 이 기기 로컬 데이터 삭제 후 A-02 |
| 4 | 새 기기 알림 | “새 기기에서 로그인했어요” / 보조 “본인이 아니면 바로 로그아웃해 주세요” + 기기·시각 | 기존 기기 OS 알림 + 이메일(앱이 열려 있으면 토스트). 알림 상한 밖 |
| 5 | 응답 버튼 | “나예요” / “내가 아니에요” | 내가 아니에요 → S-15 기기 목록에서 해당 기기 로그아웃 + “{제공자} 계정 보안도 확인해 주세요” |

예외·오류

- 무활동 잠금 중 입력값: 탭 메모리에 유지, 재로그인 뒤 이어서(탭 닫으면 사라짐)
- 다른 계정으로 재로그인: 이전 계정 데이터 미표시
- 데스크톱 오프라인 중 만료: 조회 유지, 연결되면 A-08
- 같은 기기 재로그인: 새 기기 알림 없음
