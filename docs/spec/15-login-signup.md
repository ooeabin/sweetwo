# 로그인·가입

## 흐름 요약

2026-11-13(ADR 0009 결정 12): 앱 잠금 PIN은 권장하되 건너뛸 수 있고(기기 잠금 전제), 신규 가입은 A-06을 가입 직후가 아니라 온보딩 O-60 흐름(첫 저금, 초대) 뒤에 한 번 물음. O-01 문구와 첫 실행 초대 코드 자동 입력을 바꿈. 아래 표의 A-06 자리는 이 규칙대로 읽음.

로그인은 카카오·구글·애플 소셜만(이메일·비밀번호 없음). 계정 복구 = 같은 소셜 계정으로 재로그인, 소셜 계정 분실은 고객 문의.

| 진입 | 경로 |
| --- | --- |
| 첫 실행 (앱) | A-01 → O-01 ‘시작하기’ → A-02 → A-03 → 신규: (A-04) → A-05 → O-03 … O-60 → (첫 저금, 초대) → A-06 권장(2026-11-13) / 기존 계정: 홈(이 기기에 PIN이 없으면 A-06 권장 한 번) |
| 재방문, 세션 유효 | A-01 → 잠금 켜짐이면 A-06 해제 → 홈 (온보딩 미완료면 멈춘 화면부터) |
| 재방문, 세션 없음 | A-01 → A-02 (최근 사용 방법 표시) → 이 기기에 PIN이 없으면 A-06 |
| 초대 링크, 앱 있음 | 링크가 앱을 엶(앱 링크 sweetwo.kr/i/코드, 2026-11-10 앱이 받아 A-07로. 잠겨 있으면 A-06 해제 뒤) → A-07 → P-01 → A-02(P-02) → A-03 → 신규면 (A-04) → A-05 → (A-06) → P-03 |
| 초대 링크, 앱 없음 (휴대폰) | 링크 → 웹사이트 초대 페이지 L-07(“앱 받고 합류하기” → 코드 클립보드 복사 + 스토어) → 설치 → 첫 실행 코드 자동 입력(Android 설치 리퍼러, iOS O-01 시트 “받은 초대 코드로 합류할까요?” [확인 필요], 2026-11-13) → P-01 → 아래 줄과 같음. 자동 입력이 안 되면 O-01 ‘코드 입력하기’ |
| 앱에서 ‘코드 입력하기’ | O-01 → P-01 코드 직접 입력 → A-02 → A-03 → 신규면 (A-04) → A-05 → (A-06) → P-03 |
| 세션 만료 | A-08 → A-02 → 하던 화면으로 복귀 |
| 메일 링크, 세션 없음 | A-02 → 로그인 뒤 링크가 가리키는 원래 화면으로. 대상이 없거나 상대 소유 비공개 항목이면 홈 + 토스트 “열 수 없는 항목이라 홈으로 왔어요” [확인 필요] |

## A-01 실행·자동 로그인 판단

> 화면 그림: A-01 실행, 스플래시와 강제 업데이트 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 로고 | sweeTwo 워드마크 | 화면 한가운데(가로·세로, 2026-11-10). 판단 끝나면 바로 다음 화면(최소 표시 시간 없음) |
| 2 | 진행 표시 | 막대 | 0.3초 미만이면 숨김. 판단 순서: 최소 지원 버전 → 세션 → 앱 잠금. 설정(최소 지원 버전, 점검) 확인은 3초까지만 기다리고 넘으면 막지 않음. 판단이 10초 넘으면 화면 아래 Banner “연결이 느려요” + ‘다시 시도’(13 공통 상태 5번, 2026-11-10. 워드마크는 가운데 그대로) |
| 3 | 업데이트 안내 | “새 버전으로 업데이트해 주세요” / 보조 “지금 버전으로는 저장할 수 없어요” | 최소 지원 버전 미만일 때만. 오프라인 대기열 보존 |
| 4 | 주 버튼 | “지금 업데이트” | 웹사이트 앱 받기(L-02, 기기에 맞는 스토어 버튼). 2026-11-10 데스크톱 다운로드·서명 검증·설치는 없앰(ADR 0008) |
| 5 | 보조 링크 | “업데이트 없이 보기만 할게요” | 조회만. 저장하려 하면 서버로 보내지 않고 토스트 “지금 버전으로는 저장할 수 없어요” + ‘지금 업데이트’(13 공통 상태 12번, 2026-11-10. 입력 칸은 막지 않고 저장 순간에 안내, 오프라인과 같은 방식) |

- 최소 지원 버전 이상 새 버전: 스토어에 맡김(데스크톱 백그라운드 다운로드와 ‘지금 다시 시작’은 없앰 2026-11-10, ADR 0008)
- 업데이트 뒤 첫 실행: 홈에 토스트 1회 “새 버전으로 업데이트했어요” + 링크 “새 버전에서 달라진 점”(→ 웹사이트 L-03, 그 버전 위치)

예외·오류

- 오프라인 + 세션 있음: 마지막으로 받은 데이터로 홈
- 오프라인 + 세션 없음: “인터넷에 연결하면 로그인할 수 있어요” + ‘다시 시도’. 다시 연결되면 저절로 다시 판단(2026-11-10)
- 웹사이트를 열지 못함: ‘지금 업데이트’가 ‘다시 시도’로 바뀜(안내 띠는 두지 않음 2026-11-10. 데스크톱 다운로드·서명 검증 실패 안내는 없앰 2026-11-10, ADR 0008)
- 판단 중 예상 못 한 오류: 13 공통 상태 7번 “잠시 문제가 생겼어요” / “다시 시도해 주세요” + ‘다시 시도’(2026-11-10 가입 실패 문구 한 줄 대신). 상태 화면의 ‘다시 시도’는 모두 주 버튼
- 상태 화면(업데이트, 점검, 오프라인, 오류)의 그림 자리: 2D 그림이 들어올 때까지 같은 크기(96px)의 회색 빈 자리(2026-11-10 아이콘 원에서 되돌림 → 디자인 AuthLayout, Illustrations ‘나중 과제’)
- 초대 링크로 실행: 판단이 끝나면 A-07(잠겨 있으면 해제 뒤 보임). 가입·로그인 대기 중이면 끝난 뒤 그리로
- 기기 저장소 열기 실패: 캐시 삭제 후 서버에서 다시 받음
- 업데이트는 스토어. 최소 지원 버전 미만이면 3번 안내 + ‘지금 업데이트’ → 웹사이트 앱 받기(스토어 버튼). 새 버전 안내는 스토어에 맡김

> 화면 그림: A-02 로그인 방법 선택, 넓은 창과 좁은 창 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 6 | (없음) | — | 웹 앱 전용이던 ‘이 기기에서 로그인 유지’는 뺌. 앱은 로그인을 유지하고 앱 잠금(A-06)으로 보호 |

- 소셜 로그인은 A-03(앱 밖 로그인 창 → 앱으로 복귀)
- 이메일: 소셜 계정에서 받아 알림에만 사용. 계정 식별 = 제공자 + 제공자 계정 ID
- 카카오 이메일 제공 거부 시 신규만 A-04. 애플 ‘이메일 가리기’ 주소는 그대로 사용

예외·오류

- 같은 이메일이 다른 소셜로 가입됨: 자동 합치기 없음. “이미 {카카오}로 가입한 이메일이에요”를 그 제공자 버튼 위 가운데 흰 말풍선으로(버튼 색은 그대로, ‘최근 사용’은 숨김)
- 제공자 오류: “{제공자} 로그인에 문제가 생겼어요. 다른 방법으로 해볼까요?”(버튼 위 알약 토스트, 4초)
- 오프라인: 버튼 비활성 + “인터넷에 연결되면 할 수 있어요”
- PIN을 잊어 로그아웃하고 옴(A-06 6번): 버튼 위 남는 띠 “다시 로그인하면 새 PIN을 정할 수 있어요” [확인 필요](2026-11-10)
- 삭제 요청 30일 안 계정: “계정 삭제를 취소할까요?” → ‘취소하고 계속 쓰기’ / ‘그대로 두기’. 복구하면 ‘혼자 쓰기’ 상태로 돌아오고 30일 안 재연결 가능(S-12 “다시 연결하기”), 상대에게 ‘계정 복구’ 알림 1종. 복구나 로그아웃에 실패하면 화면 아래 알림 “잠시 문제가 생겼어요. 다시 시도해 주세요” [확인 필요] 4초, 버튼은 다시 누를 수 있음(2026-11-06)

## A-03 브라우저 로그인 대기

- 확인 PIN 불일치: “PIN이 서로 달라요”, 처음부터 다시
- 해제 PIN 틀림: “PIN이 맞지 않아요”, 3회째부터 “{n}번 더 틀리면 다시 로그인해야 해요”
- 5회 실패: 로그아웃(이 기기 PIN과 로컬 데이터 삭제, 오프라인 중 쓰기는 보내지 않고 막으므로 보낼 대기열은 없음 → 동기화 4장) → A-02
- PIN 저장 실패(기기 보안 저장소 오류): 생체 질문으로 넘어가지 않고 “PIN을 저장하지 못했어요. 처음부터 다시 정해 주세요” [확인 필요] + 처음부터(2026-11-10)
- 잠긴 동안 뒤 화면은 그리지 않은 것처럼 숨김(보이지 않고 Tab·화면 읽기도 닿지 않음, 잠금 상태를 읽는 동안도, 2026-11-10)
- 다른 계정으로 로그인하면 앞 계정이 이 기기에 정한 PIN을 지우고 PIN을 새로 정함(2026-11-10)
- 생체 인증이 없거나 등록하지 않은 기기: 생체 질문·버튼 숨김
- 잠금 화면·앱 전환 미리보기(휴대폰·태블릿 최근 앱 화면): 금액 가리기 설정과 상관없이 모든 금액 “•••”로 자동 가림. 해제하면 원래 설정대로 표시(→ 화면 설계 › 공통)

## A-07 초대 링크 진입

> 화면 그림: A-07 초대 링크 진입, 네 갈래 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

예외·오류

- 만료(7일): “초대가 만료됐어요. 새 코드를 요청해 주세요”. 초대한 사람에게는 만료 알림과 새 코드 만들기 안내(→ 알림)
- 잘못된 코드: “코드를 다시 확인해 주세요”. 시도 제한(2026-11-11 D2): ‘합류하기’는 맞든 틀리든 10분에 10번, 로그인 전 미리보기도 같은 기기·접속 주소에서 너무 많이 물으면 “10분 뒤에 다시 입력해 주세요”(→ 보안 2장 ‘초대 코드 보호’)
- 다른 사람이 합류하는 중(코드를 잡아 둠, 24시간): “이미 합류가 끝난 초대예요”와 같은 문구(D1)
- 이미 다른 파트너와 연결됨: “이미 우리 둘 공간이 연결돼 있어요”
- 내가 만든 코드: “내가 만든 초대 코드예요”
- 이미 합류가 끝난 초대: “이미 합류가 끝난 초대예요”(P-11 합류 완료 때 코드는 ‘사용됨’)
- 초대한 사람이 계정 삭제: “사용할 수 없는 초대예요”
- 초대 정보를 못 불러옴(2026-11-10): 다시 묻기는 1번만(2026-11-11 S3-21, 뼈대가 7초 보이던 것), 인터넷이 없거나 연결 오류면 오프라인 문구. 정상인 척 ‘합류하기’를 보이지 않고 13 공통 상태 6번(오프라인 “연결이 끊겼어요” / “다시 연결되면 이어서 볼 수 있어요”)·7번(“잠시 문제가 생겼어요” / “다시 시도해 주세요”) + ‘다시 시도’(로그인 전이면 ‘처음으로’도)
- 합류 끝(P-11) 뒤 다른 기기 앱 안내(없앰 2026-11-10, ADR 0008: 데스크톱 앱이 없어 안내할 다른 앱이 없음)
