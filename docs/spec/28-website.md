# 웹사이트

앱을 알리고 데스크톱 앱과 모바일 앱을 받게 하는 공개 웹사이트. 로그인 없이 누구나 봄. 주소는 sweetwo.kr(주소 구조 → 기술·운영 1장 ‘주소 구조’). 웹 앱은 없음(ADR 0001). 출시 전 확인 항목 → 출시 준비 5장. 앱 틀(상단 메뉴 줄·하단 독) 없이 사이트 상단 바, 본문, 하단만 씀.

## 흐름 요약

첫 화면 = 랜딩(L-01). PC는 다운로드 버튼 → 파일 받기 시작 + 설치 안내(L-02). 휴대폰은 스토어 버튼(App Store, Google Play) → 스토어 앱 페이지. 초대 링크는 L 화면이 아니라 아래 공통 ‘초대 링크’ 규칙을 따름.

| ID | 화면 | 패턴 | 필수 여부 | 분기 |
| --- | --- | --- | --- | --- |
| L-01 | 랜딩 (/) | 고유 | — | 다운로드 → L-02, 스토어 버튼 → App Store·Google Play, 전체 보기 → L-06, 하단 → L-05, L-06, 상태 페이지 |
| L-02 | 설치 안내 (/download?os=mac 또는 win) | 고유 | — | 휴대폰 앱 받기 → 스토어 |
| L-03 | 릴리스 노트 (/releases) | 고유 (목록) | — | 앱 S-19 “새 기능 보기”, 업데이트 뒤 첫 실행 토스트에서 진입 |
| L-05 | 약관과 개인정보처리방침 (/terms, /privacy) | 고유 | — | 이전 버전 → 그 시행일 본문 |
| L-06 | 고객센터 (/help) | 고유 (목록) | — | 찾는 답이 없어요 → 문의 메일(help@sweetwo.kr) |

## 공통

**주소**

- sweetwo.kr = 웹사이트(L 화면), 어드민은 지금처럼 별도 도메인. 웹 앱 주소는 없음
- 스토어: App Store, Google Play 앱 페이지 주소는 `apps/site/src/lib/site.ts` 한 곳에. 버튼은 각 스토어 공식 배지(“App Store에서 받기”, “Google Play에서 받기”)
- 다운로드 고정 주소: download.sweetwo.kr/latest/mac, download.sweetwo.kr/latest/win. CloudFront가 최신 정식 파일로 보냄. Mac은 universal dmg 1개, Windows는 x64만(ARM은 이후)
- 상태 페이지: status.sweetwo.kr(Better Stack)
- 페이지 제목은 “{페이지 이름} - sweeTwo”, 랜딩만 “sweeTwo | 함께 구워 더 달콤한 자산파이”. 페이지마다 메타 설명 1줄, 랜딩 메타 설명은 “함께 구워 더 달콤한 자산파이” 다음에 기능 설명 1문장

**초대 링크 (sweetwo.kr/i/{코드})**

- 앱이 깔린 기기: 링크를 앱이 바로 엶(iOS 유니버설 링크, Android 앱 링크, 데스크톱은 sweetwo:// 딥링크). 앱의 A-07 → P-01(코드 채워짐)
- 앱이 없는 휴대폰: 웹사이트 초대 페이지 “sweeTwo에 초대받았어요” / 보조 “앱을 설치한 뒤 이 코드를 입력해 주세요” + 코드 6자(크게, ‘복사’) + 스토어 버튼(기기에 맞는 하나) [확인 필요]. 설치 뒤 앱의 O-01 ‘초대받았어요’ → P-01에 코드 직접 입력
- 앱이 없는 PC: 같은 초대 페이지 + 다운로드 버튼(L-02) + “휴대폰 앱도 있어요”(스토어 버튼 2개)
- 데스크톱은 브라우저에서 앱 설치 여부를 확실히 알 수 없어 이 브라우저 기록(L-02에서 받았거나 앱으로 연 적 있음)이 있으면 “sweeTwo 앱으로 열까요?” + “앱으로 열기”. 앱이 열리지 않으면 같은 초대 페이지
- 만료, 사용된 코드 처리는 앱의 P-01 규칙 그대로(→ 배우자 합류). 초대 페이지는 코드 유효 여부를 확인하지 않음(로그인 없이 코드를 검증하지 않음)

**디자인**

- 글꼴 SUIT, 워드마크 Damion, 아이콘 Phosphor. 주 버튼은 앱과 같은 기본 버튼, 브랜드 오렌지는 작은 점과 글자에만(→ 브랜드 3장)
- 반응형: 넓은 창 2단(본문 최대 폭 1200px), 좁은 창 1단
- 다크 모드는 기기 설정. 3D 그림과 앱 화면 이미지는 다크에서도 흰 카드 위
- 앱 화면 이미지는 라이트 캡처, 이름과 금액은 예시 값. 캡처 속 이름은 기획서 예시 이름(찬우, 예빈)이 아닌 흔한 이름 한 쌍으로 따로 정함 [확인 필요]

**측정과 쿠키**

- 이벤트: site\_landing\_viewed, site\_download\_clicked(os, 위치), site\_store\_clicked(store, placement: top/hero/bottom), site\_install\_guide\_viewed(os), site\_faq\_opened. 정의 → 성공 지표 4-8
- UTM 값은 웹사이트 이벤트에만 남김(→ 성공 지표 4-2)
- 설치 출처: L-02가 download\_id를 발급해 이 브라우저에 저장, 설치 후 첫 실행의 브라우저 로그인(A-03)이 딥링크에 실어 앱으로 넘김 → app\_first\_launch(download\_id). 설치 파일 이름·웹 세션 매칭은 쓰지 않음(→ 성공 지표)
- 쿠키 없는 측정(PostHog)이라 동의 배너 없음. 법무 확인 필요

**구현**

- Astro 정적 사이트(확정), 저장소 apps/site, Cloudflare Workers 정적 자산(ADR 0002) → 기술·운영 1장
- 공유 이미지 1200×630(흰 바탕, 워드마크 + 심볼 symbol.png(파이 차트)) → 브랜드 4장

상태와 예외

- 지원하지 않는 OS(macOS 11 이하, Windows 32비트, Windows 7, 8): 다운로드 버튼 대신 “이 컴퓨터에서는 앱을 쓸 수 없어요. 휴대폰 앱으로 시작할 수 있어요” [확인 필요] + 스토어 배지 2개. “다른 OS용 받기”는 그대로
- 휴대폰: 기기 스토어 배지 주 버튼 + “Mac이나 Windows에서도 같은 계정으로 쓸 수 있어요” 1줄 [확인 필요]
- 지원하지 않는 휴대폰(iOS 16 미만, Android 8 미만 [확인 필요]): 스토어가 설치를 막으므로 사이트는 따로 판정하지 않음
- OS를 알 수 없음: 스토어 배지 2개 + “다른 OS용 받기”. macOS 버전은 브라우저가 알려 주지 않을 때가 많아 11 이하 판정은 알 수 있을 때만
- 프리미엄 가격 영역은 유료화 전까지 없음

## L-02 설치 안내 (/download?os=mac 또는 win)

> 화면 그림: L-02 설치 안내, Mac 기준과 Windows 단계, 보안 경고 펼친 모습 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

다운로드 버튼을 누르면 파일 받기를 시작하고 이 화면으로 옴. 모바일 앱에서 보낸 ‘데스크톱 앱 받기 링크’(배우자 합류 P-11 뒤 안내 메일)도 이 화면으로 와서 OS에 맞는 파일 받기를 바로 시작.

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 제목 | “다운로드를 시작했어요” / 보조 “받기가 시작되지 않으면 다시 받기를 눌러 주세요” + “다시 받기” | 다시 받기 = 같은 고정 주소를 다시 요청 |
| 2 | 설치 3단계 | Mac: 1 “dmg 파일을 열어요” 2 “sweeTwo를 응용 프로그램 폴더로 끌어 놓아요” 3 “처음 열 때 ‘열기’를 눌러요” / Windows: 1 “설치 파일을 실행해요” 2 “설치를 눌러요” 3 “시작 메뉴에서 sweeTwo를 열어요” | os 값에 맞는 하나만. 번호 원 + 1줄 |
| 3 | 보안 경고 안내 | 접기 1개 “보안 경고가 뜨나요?” / 펼치면 Mac “‘확인되지 않은 개발자’ 경고가 뜨면 시스템 설정의 개인정보 보호 및 보안에서 ‘그래도 열기’를 눌러 주세요”, Windows “SmartScreen 창이 뜨면 ‘추가 정보’를 누른 뒤 ‘실행’을 눌러 주세요” + “sweeTwo는 서명과 공증을 마친 앱이라 보통은 이 경고가 뜨지 않아요” | 기본은 접힘. os 값에 맞는 안내만. 서명과 공증 → 기술·운영 5장 |
| 4 | 설치 뒤 | “휴대폰 앱과 같은 계정으로 로그인하면 기록이 그대로 있어요” [확인 필요] | — |
| 5 | 휴대폰 앱 | “휴대폰 앱도 있어요” + 스토어 배지 2개 | → App Store, Google Play |

상태와 예외

- os 값이 없거나 틀림: 접속 OS로 정함. 그래도 모르면 자동 받기 없이 “Mac용 다운로드” “Windows용 다운로드” 두 버튼
- 휴대폰이나 지원하지 않는 OS로 들어옴: 자동 받기 없음, L-01과 같은 안내 + 스토어 배지
- 새로고침하면 받기를 다시 시작하지 않음(다시 받기로만)
