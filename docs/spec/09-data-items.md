# 데이터 항목

개발 기준 데이터 정의. 저장하는 항목과 필드, 공통 저장 규칙, 화면 선택지의 분류 기준을 정함. 계산 규칙은 계산·배분과 월 사이클, 우리 둘 상태와 권한은 커플·권한을 따름. 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`, 저금 항목 → `docs/adr/0007-goal-into-saving-line.md`, 2026-11-13 v2.2 새 테이블·열 → `docs/adr/0009-save-together-plan.md`, 7장.

- 이 문서의 이름과 필드는 기획 수준. 테이블·열 이름, 타입, 나누는 방식은 구현에서 정함(→ 기술·운영). DB 타입은 `supabase gen types` 결과만 씀
- 없앤 기능의 테이블은 스키마 규칙(추가만, 지우기는 2단계)대로 정리

## 2. 저금 항목 필드

2026-11-08 ‘목표’를 저금 항목으로 줄임(ADR 0007). DB는 예전 목표 테이블을 저금 항목 행으로 그대로 씀(스키마 추가만 규칙, → DEV_GUIDE). 새 코드는 템플릿·형태·우선순위·예전 이미 모은 금액(other_held)·사진·목표 기록을 쓰지 않음. 2026-11-09 만들 때만 넣는 ‘시작할 때 모은 금액’(start_saved)을 새로 둠.

| 항목 | 형식 | 설명 |
| --- | --- | --- |
| 이름 | 텍스트 | 최대 20자(W-11a) |
| 목표 금액 | 금액, 빈 값 가능 | 선택(W-11c) |
| 기한 | 년·월, 빈 값 가능 | 선택, 목표 금액이 있을 때만(W-11d) |
| 시작할 때 모은 금액 | 금액, 0원 기본 | 선택, 만들 때만(W-11c ‘이미 모은 금액이 있어요’, 2026-11-09). 목표 금액보다 적게, 나중에 못 고침 |
| 모은 금액 | 계산값 | 저장하지 않음 = 시작할 때 모은 금액 + 이 항목 저금 줄을 체크한 금액 합(→ 계산·배분 4장) |
| 주인 | 사람 또는 우리 둘 | 각자 모드 = 만든 사람, 합쳐서 모드 = 우리 둘. 관리 방식을 바꿀 때 바뀜(→ 월급 탭 ‘다시 계산되는 때’) |
| 공개 범위 | 선택 | 2026-11-13 없앰: 새 코드에서 읽지 않음(2단계로 지움). 저금 공개는 S-13 ① ‘내 월급 계획’ 하나(→ 08 6장) |
| 묶음 | id, 빈 값 가능 | 같이 모으기 묶음(`goal.bundle_id`, 각자 계열만, 2026-11-13) |
| 상태 | 선택 | 모으는 중 / 달성 / 그만 모음(→ 월급 탭 ‘달성과 그만 모음’). 달성 시각과 축하를 본 사람은 저장(축하 화면 1회) |

- 기본 항목(비상금)은 없음
- 연결 해제가 확정되면 주인이 있는 저금(각자 계열)과 내역은 주인 혼자 공간으로 옮기고, 공동 저금(합쳐서)·묶음은 지움(2026-11-13, → 08 7장)

| 금액 | 만든 시점 월급 계획 금액. 월급 계획이 바뀌면 체크 안 한 줄만 새 금액 |
| 실제 금액 | ‘다른 금액으로 보냈어요’(W-02a)에서 넣은 값. 없으면 금액과 같음 |
| 상태 | 열림 / 체크 / 못 함(화면 ‘건너뜀’, 2026-11-13). 못 함 = ‘이번 달은 건너뛸게요’ 또는 기준일이 지나 닫힘 |
| 자동 | `auto` bool, `auto_due` date(그 사이클의 나가는 날), 대기 → 나가는 날 0시 체크(자동 확인) (2026-11-13) |
| 늦은 확인 | `late` bool: 다음 사이클 끝까지 확인한 줄(2026-11-13) |
| 체크한 사람 | 각자면 늘 주인, 합쳐서면 체크한 사람(2026-11-03 대신 체크 없앰) |
| 체크한 시각 | KST |

- 이미 모은 금액 + 저금 줄 확인 상태와 실제 금액 + 저금 움직임(`goal_move`: 돈 들어왔어요, 바로잡기, 잔액 맞추기, 쓸 곳 메모, 날짜 없는 사람의 자동 저금)이 저금 모은 금액의 기록(2026-11-13, → 06 4장)
- 지난 사이클 확인 목록은 다음 사이클 끝까지 늦은 확인만 되고 그 뒤 읽기 전용

## 4. 공통 규칙

- 모든 엔티티: id, 우리 둘 공간 id, 만든 사람·시각, 고친 사람·시각, 삭제 시각·삭제한 사람(휴지통). 휴지통 30일 보관 뒤 자동 영구 삭제(→ 화면 설계 › 설정 ‘휴지통’)
- 금액: 원 단위 정수 저장, 화면에서만 만 원 단위 표시. 입력 최대 999억 원(99,999,999,999원). 합계가 넘으면 “999억+”, 음수는 “−”(→ 화면 설계 › 공통 6장)
- 날짜·시각: 한국 시간(KST) 기준, 기기 시간대는 무시(알림 시각·방해 금지 시간 포함). 음력은 원본(월·일·윤달) + 해당 연도 양력 날짜 함께 저장
- 음력 변환: korean-lunar-calendar(npm, MIT, 한국천문연구원 기준표)로 core 패키지에서 클라이언트와 서버가 같은 계산(설·추석 포함). 천문연구원 자료와 대조 테스트. 양력 2050년 12월 31일까지 지원, 그 뒤 연도는 입력 불가. 윤달이 끼는 해에는 평달·윤달 중 사용자 선택. 윤달 날짜가 그해 없으면 평달 같은 날, 음력 30일이 그 달에 없으면(작은달) 그 달 말일
- 공휴일: 공공데이터포털 ‘한국천문연구원 특일 정보’ API. 서버가 매년 12월에 다음 해를 받고 매주 1회 다시 받아 임시공휴일 반영, 공휴일 테이블에 저장. 앱은 테이블만 읽음. 어드민 AD-19에서 직접 추가·수정(→ 기술·운영 1장). 쓰임: 캘린더 공휴일 표시, 월급날이 주말·공휴일이면 직전 영업일로 앞당겨 표시(→ 핵심 규칙 › 월 사이클 1장)
- ‘잘 모르겠어요’로 넣은 값은 ‘추정’ 표시 저장
- 자산·부채 금액 변경 시 이력(값, 시각, 고친 사람) 저장, 순자산 그래프와 ‘지난달보다’에 사용
- 자산·부채 모든 항목에 명의(나/파트너/공동)·공개 범위·마지막 갱신일 저장. 만기일 있는 항목은 D-60 미리 알림
- 저금 항목 모은 금액과 자산은 따로 셈. 모은 금액은 순자산에 더하지 않음(→ 계산·배분 6장) [확인 필요]
- 바로 고친 값은 활동 기록에 전·후 값을 남겨 ‘되돌리기’에 씀(→ 핵심 규칙 › 커플·권한)

### 6-1. 금액 구간 칩

‘잘 모르겠어요’ 입력용 구간 칩 5개. 저장값 = 구간 중간값(첫 구간 = 상한의 1/2, 끝 구간 = 하한) + ‘추정’.

### 6-2. 자산

그룹 칩 먼저, 그룹을 고르면 세부 항목. 모든 그룹에 ‘기타(직접 입력)’. 정책 상품 이름은 바뀌므로 앱에 고정하지 않고 어드민에서 고치는 데이터로(→ 화면 설계 › 어드민 화면 AD-19). 어드민에서 고치는 묶음은 예금·적금, 청약, 투자, 연금: 기본 항목은 이름 바꾸기·숨기기, 새 칩은 기본 항목 하나를 골라 그 항목과 같은 질문을 함. ‘기타(직접 입력)’는 늘 마지막.
