# 데이터 항목

개발 기준 데이터 정의. 저장하는 항목과 필드, 공통 저장 규칙, 화면 선택지의 분류 기준을 정함. 계산 규칙은 계산·배분과 월 사이클, 우리 둘 상태와 권한은 커플·권한을 따름. 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`, 저금 항목 → `docs/adr/0007-goal-into-saving-line.md`.

- 이 문서의 이름과 필드는 기획 수준. 테이블·열 이름, 타입, 나누는 방식은 구현에서 정함(→ 기술·운영). DB 타입은 `supabase gen types` 결과만 씀
- 없앤 기능의 테이블은 스키마 규칙(추가만, 지우기는 2단계)대로 정리

## 1. 엔티티

| 알림 | 보낼·보낸 알림 | 종류, 받는 사람, 예정 시각, 채널(OS 알림/모바일 푸시/이메일/인앱), 보낸 시각, 읽음, 상한 포함 여부(→ 화면 설계 › 알림) | — |

## 2. 저금 항목 필드

2026-11-08 ‘목표’를 저금 항목으로 줄임(ADR 0007). DB는 예전 목표 테이블을 저금 항목 행으로 그대로 씀(스키마 추가만 규칙, → DEV_GUIDE). 새 코드는 템플릿·형태·우선순위·예전 이미 모은 돈(other_held)·사진·목표 기록을 쓰지 않음. 2026-11-09 만들 때만 넣는 ‘시작할 때 모은 돈’(start_saved)을 새로 둠.

| 항목 | 형식 | 설명 |
| --- | --- | --- |
| 이름 | 텍스트 | 최대 20자(W-11a) |
| 목표 금액 | 금액, 빈 값 가능 | 선택(W-11c) |
| 기한 | 년·월, 빈 값 가능 | 선택, 목표 금액이 있을 때만(W-11d) |
| 시작할 때 모은 돈 | 금액, 0원 기본 | 선택, 만들 때만(W-11c ‘이미 모은 돈이 있어요’, 2026-11-09). 목표 금액보다 적게, 나중에 못 고침 |
| 모은 돈 | 계산값 | 저장하지 않음 = 시작할 때 모은 돈 + 이 항목 저금 줄을 체크한 금액 합(→ 계산·배분 4장) |
| 주인 | 사람 또는 우리 둘 | 각자 모드 = 만든 사람, 합쳐서 모드 = 우리 둘. 관리 방식을 바꿀 때 바뀜(→ 월급 탭 ‘다시 계산되는 때’) |
| 공개 범위 | 선택 | 주인이 있는 항목만. 모두 보여 주기(기본) / 금액만 보여 주기(→ 커플·권한 6장) |
| 상태 | 선택 | 모으는 중 / 달성 / 그만 모음(→ 월급 탭 ‘달성과 그만 모음’). 달성 시각과 축하를 본 사람은 저장(축하 화면 1회) |

- 기본 항목(비상금)은 없음
- 연결 해제가 확정되면 저금 항목 모두 지워짐(공동 공간 데이터 전부 삭제)

## 3. 월급 계획과 체크리스트 필드

**월급 계획 줄**

| 항목 | 설명 |
| --- | --- |
| 종류 | 저금 / 쓰는 돈. 남는 돈은 저장하지 않고 계산 |
| 쓰는 돈 구분 | 고정지출 / 생활비 / 용돈 / 직접 추가. 고정지출·생활비·용돈은 지우지 못함(0원) |
| 저금 항목 id | 저금 줄만. 저금 항목 1개 |
| 사람 | 용돈 줄만(합쳐서면 사람마다 1줄) |
| 이름 | 직접 추가한 줄만(예: “부모님 용돈”). 나머지는 종류·저금 항목에서 정해짐 |
| 금액 | 원 단위 정수, 1만 원 단위 입력, 0원 가능 |
| 순서 | 묶음 안 순서. 저금 묶음은 만든 순서 |

**월급 체크리스트**

| 항목 | 설명 |
| --- | --- |
| 주인 | 사람(각자) / 우리 둘 공간(합쳐서). 월급 계획과 같음 |
| 이름 | ‘{기준일의 월}월 월급’ |
| 기간 | 기준일 0시 ~ 다음 기준일 전날 자정(→ 핵심 규칙 › 월 사이클) |
| 상태 | 진행 중 / 다 했어요 / 끝남(→ 핵심 규칙 › 월 사이클 5장) |
| 첫 사이클 여부 | 온보딩 결과 직후 만든 것 |

**체크리스트 줄**

| 항목 | 설명 |
| --- | --- |
| 월급 계획 줄 id | 복사해 온 줄 |
| 종류·저금 항목 id·사람·이름 | 만든 시점 월급 계획 줄을 복사 |
| 금액 | 만든 시점 월급 계획 금액. 월급 계획이 바뀌면 체크 안 한 줄만 새 금액 |
| 실제 금액 | ‘다른 금액으로 보냈어요’(W-02a)에서 넣은 값. 없으면 금액과 같음 |
| 상태 | 열림 / 체크 / 못 함. 못 함 = ‘이번 달은 못 했어요’ 또는 기준일이 지나 닫힘 |
| 체크한 사람 | 각자면 늘 주인, 합쳐서면 체크한 사람(2026-11-03 대신 체크 없앰) |
| 체크한 시각 | KST |

- 시작할 때 모은 돈 + 저금 줄 체크 상태와 실제 금액이 곧 저금 항목 모은 돈의 기록(따로 기록을 남기지 않음, ADR 0007)
- 지난 사이클 체크리스트는 읽기 전용

## 4. 공통 규칙

- 모든 엔티티: id, 우리 둘 공간 id, 만든 사람·시각, 고친 사람·시각, 삭제 시각·삭제한 사람(휴지통). 휴지통 30일 보관 뒤 자동 영구 삭제(→ 화면 설계 › 설정 ‘휴지통’)
- 금액: 원 단위 정수 저장, 화면에서만 만 원 단위 표시. 입력 최대 999억 원(99,999,999,999원). 합계가 넘으면 “999억+”, 음수는 “−”(→ 화면 설계 › 공통 6장)
- 날짜·시각: 한국 시간(KST) 기준, 기기 시간대는 무시(알림 시각·방해 금지 시간 포함). 음력은 원본(월·일·윤달) + 해당 연도 양력 날짜 함께 저장
- 음력 변환: korean-lunar-calendar(npm, MIT, 한국천문연구원 기준표)로 core 패키지에서 클라이언트와 서버가 같은 계산(설·추석 포함). 천문연구원 자료와 대조 테스트. 양력 2050년 12월 31일까지 지원, 그 뒤 연도는 입력 불가. 윤달이 끼는 해에는 평달·윤달 중 사용자 선택. 윤달 날짜가 그해 없으면 평달 같은 날, 음력 30일이 그 달에 없으면(작은달) 그 달 말일
- 공휴일: 공공데이터포털 ‘한국천문연구원 특일 정보’ API. 서버가 매년 12월에 다음 해를 받고 매주 1회 다시 받아 임시공휴일 반영, 공휴일 테이블에 저장. 앱은 테이블만 읽음. 어드민 AD-19에서 직접 추가·수정(→ 기술·운영 1장). 쓰임: 캘린더 공휴일 표시, 월급날이 주말·공휴일이면 직전 영업일로 앞당겨 표시(→ 핵심 규칙 › 월 사이클 1장)
- ‘잘 모르겠어요’로 넣은 값은 ‘추정’ 표시 저장
- 자산·부채 금액 변경 시 이력(값, 시각, 고친 사람) 저장, 순자산 그래프와 ‘지난달보다’에 사용
- 자산·부채 모든 항목에 명의(나/파트너/공동)·공개 범위·마지막 갱신일 저장. 만기일 있는 항목은 D-60 미리 알림
- 저금 항목 모은 돈과 자산은 따로 셈. 모은 돈은 순자산에 더하지 않음(→ 계산·배분 6장) [확인 필요]
- 바로 고친 값은 활동 기록에 전·후 값을 남겨 ‘되돌리기’에 씀(→ 핵심 규칙 › 커플·권한)

**삭제 연결 처리**

| 지우는 항목 | 처리 | 연결된 것 |
| --- | --- | --- |
| 고정지출·생활비·용돈 줄 | 지우기 없음, 0원으로 | — |
| 저금 항목 | 휴지통 | 월급 계획 저금 줄 빠짐. 이번 사이클 체크한 줄은 기록으로 남음 |
| 직접 추가한 쓰는 돈 줄 | 바로 지움 + ‘되돌리기’ | 이번 사이클 체크 안 한 줄은 빠지고, 체크한 줄은 기록으로 남음 [확인 필요] |
| 자산 | 휴지통 | 과거 순자산 기록 유지 |
| 부채 | 휴지통 | 과거 순자산 기록 유지 |
| 챙길 날 | 휴지통 | — |

- 연결 해제 확정: 우리 둘 공간의 모든 항목(저금 항목, 월급 계획·줄, 체크리스트·줄, 자산·부채와 금액 이력, 챙길 날, 활동 기록, 알림, 닫은 할 일, 휴지통)을 한 번에 지움. 휴지통을 거치지 않고 복구용 보관본으로 옮겨 30일 뒤 영구 삭제. 사용자·로그인 기기·동의 기록은 남음(→ 커플·권한 7장, 보안·개인정보 4장)
- ‘같이 휴지통’은 부모 항목을 되살리면 함께 되살아남. 저금 항목을 되살리면 월급 계획에 0원 저금 줄이 다시 생김 [확인 필요]
- 되살릴 때 연결 대상이 없으면(이미 영구 삭제) 연결 없이 되살리고 Toast “연결된 항목이 없어 따로 되살렸어요”

## 5. 기타 상태

| 대상 | 상태 | 바뀌는 조건 |
| --- | --- | --- |
| 체크리스트 줄 | 열림 → 체크 / 못 함 | 체크, 체크 풀기(체크 → 열림), ‘이번 달은 못 했어요’, 다음 기준일 0시 |
| 파트너 초대 | 발급 → 사용됨 / 만료 | 7일 뒤 만료, 다시 발급 가능 |

- 체크리스트 상태 → 핵심 규칙 › 월 사이클 5장 / 저금 항목 상태 → 월급 탭 ‘달성과 그만 모음’ / 우리 둘 상태 → 핵심 규칙 › 커플·권한

## 6. 선택지 기준

### 6-1. 금액 구간 칩

‘잘 모르겠어요’ 입력용 구간 칩 5개. 저장값 = 구간 중간값(첫 구간 = 상한의 1/2, 끝 구간 = 하한) + ‘추정’.

| 금액 종류 | 구간 (만 원) | 저장값 (만 원) |
| --- | --- | --- |
| (없음) | 2026-11-08 목표 템플릿 질문을 없애 지금 쓰는 곳 없음(ADR 0007). 예전 목표 금액 공통·여행 1인 경비 구간은 git 기록 | — |

- 분석 이벤트의 월 수입 구간(입력 칩 아님): 200 미만 / 200~300 / 300~400 / 400~500 / 500 이상(만 원)

### 6-2. 자산

그룹 칩 먼저, 그룹을 고르면 세부 항목. 모든 그룹에 ‘기타(직접 입력)’. 정책 상품 이름은 바뀌므로 앱에 고정하지 않고 어드민에서 고치는 데이터로(→ 화면 설계 › 어드민 화면 AD-19). 어드민에서 고치는 묶음은 예금·적금, 청약, 투자, 연금: 기본 항목은 이름 바꾸기·숨기기, 새 칩은 기본 항목 하나를 골라 그 항목과 같은 질문을 함. ‘기타(직접 입력)’는 늘 마지막.

| 그룹 | 항목 | 추가로 묻는 것 |
| --- | --- | --- |
| 현금성 | 입출금 통장, 파킹통장·CMA, 현금, 외화 예금 | 외화는 통화·금액(원화 환산은 직접 입력) |
| 예금·적금 | 정기예금, 적금, 정책형 적금 | 만기일, 월 납입액, 금리(선택) |
| 청약 | 주택청약종합저축 | 월 납입액(선택) |
| 투자 | 국내 주식, 해외 주식, ETF, 펀드, 채권, ISA 계좌, 금·실물, 가상자산 | 평가금액, 넣은 원금(선택) |
| 연금 | 연금저축(펀드·보험), IRP, 퇴직연금(DC형), 개인연금보험 | 적립금, 월 납입액(선택) |
| 저축성 보험 | 저축보험, 변액보험 | 해지환급금(모르면 납입 총액), 만기 |
| 부동산 | 전·월세 보증금, 보유 주택, 분양권(납부한 계약금·중도금) | 계약 만기일 / 시세(직접 입력), 넣은 원금(보유 주택·분양권, 선택) |
| 기타 | 자동차(시세), 빌려준 돈, 기타 | 돌려받을 날(빌려준 돈) |

- 특정 종목·상품 추천 없음

### 6-3. 부채

| 그룹 | 항목 | 추가로 묻는 것 |
| --- | --- | --- |
| 주택 | 전세자금대출, 주택담보대출, 중도금·잔금 대출 | 월 상환액, 금리, 만기일 (모두 선택, 월 상환액이 먼저) |
| 신용 | 신용대출, 마이너스통장, 카드론·현금서비스, 리볼빙 | 금리, 월 상환액. 마이너스통장은 사용액 |
| 할부 | 자동차 할부, 큰 금액 카드 할부 | 남은 회차, 월 납부액 |
