# 어드민 화면

## 흐름 요약

웹 전용 내부 도구(2단계 인증 + WAF IP 허용). 대시보드(AD-01) → 상단 검색으로 회원·부부 찾기(AD-02) → 상세(AD-03, L0) → 필요할 때만 AD-04에서 L1 사유 입력·L2 동의 요청. 모든 조회·조치는 감사 로그(AD-17)에 남음.

| AD-ID | 화면 | MVP 여부 |
| --- | --- | --- |
| AD-01 | 대시보드 | 필수(경보·실패 건수·미처리 문의만) |
| AD-02 | 회원·부부 검색 | 필수 |
| AD-03 | 회원·부부 상세 | 필수 |
| AD-04 | 개인정보 열람 요청 | 필수 |
| AD-05 | 계정 조치 | 필수 |
| AD-06 | 문의 처리 | 필수(간단 버전: 목록, 상세, 답변 쓰기, 상태) |
| AD-07 | 답변 템플릿 | 이후(MVP는 AD-06 답변 칸에 직접 작성) |
| AD-08 | 구독·결제 | 이후(유료화 시점, 프리미엄 판매 시작과 함께) |
| AD-09 | 쿠폰·체험 | 이후(유료화 시점, 프리미엄 판매 시작과 함께) |
| AD-10 | 공지 | 필수(약관 개정 고지·1등급 장애 고지 이메일 포함) |
| AD-11 | 알림 캠페인 | 이후(첫 3개 사이클 코호트 확인 후, 그 전 마케팅 발송 없음) |
| AD-12 | 목표 템플릿 | 이후(출시 초기는 앱 배포로 변경) |

| AD-14 | 가이드·도움말 | 필수(버전 번호·시행일·재동의 요구만, 본문은 코드 배포) |
| AD-15 | 약관·개인정보 처리방침 | 필수 |
| AD-16 | 앱 버전·점검 | 필수 |
| AD-17 | 감사 로그 | 필수 |
| AD-18 | 관리자 계정 관리 | 필수 |
| AD-19 | 계산·기준 데이터(대출 평균 금리, 공공 통계, 공휴일) | 필수(분기마다 갱신) |
| AD-20 | 문서(기획서, 디자인, 개발 가이드 읽기 전용) | 필수 |

## 어드민 기본 틀, AD-02 회원 검색

> 화면 그림: 어드민 기본 틀, AD-02 회원 검색 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | 좌측 메뉴 | 대시보드 / 회원 / 문의 / 구독·결제 / 발송 / 콘텐츠 / 시스템 | 역할에 권한 없는 메뉴는 숨김(→ 어드민 2장) |
| 2 | 통합 검색 | “이메일, 사용자 ID, 문의 번호로 찾기” | 이메일·사용자 ID·부부 공간 ID·문의 번호·주문번호 정확히 일치만(이름·호칭·부분 일치 없음). 1건이면 AD-03으로 바로 |
| 3 | 계정 | “cs01” + 작은 이름표 ‘CS’ / “로그아웃” | 관리자 ID·역할. 30분 무활동 만료 |
| 4 | 결과 표 | 사용자 ID, 이메일, 가입일, 부부 상태, 구독 | 이메일 앞 3자 외 마스킹(“cha\*\*\*@gmail.com”). 행 클릭 → AD-03 |
| 5 | 내려받기 | “내려받기” | L0 열만, 사유 입력 후. 파일에 관리자 ID 표시 |

- 기준 폭 1440, 최소 1280. 데스크톱 웹만
- 검색도 감사 로그

예외·오류

- IP 허용 목록 밖: 로그인 화면 전에 차단
- 세션 만료·다른 곳에서 로그인: 로그인 화면, 재로그인 후 보던 화면. 30분 무활동은 브라우저를 닫았다 열어도 이어서 셈
- 로그인 링크: 보낸 뒤 60초 동안 버튼을 막고 “{n}초 뒤에 다시 받을 수 있어요” [확인 필요]. 너무 자주 누름: “조금 뒤에 다시 눌러 주세요” [확인 필요]. 보낼 수 없는 주소: “이 이메일로는 로그인 링크를 보낼 수 없어요” [확인 필요]. 메일 링크는 새 탭에서 열려도 로그인이 이어짐
- 권한 없는 화면 주소로 접근: “권한이 없어요” + 대시보드로
- 결과 없음: “일치하는 회원이 없어요”

- 삭제 유예 중: 상단 띠 “삭제 유예 중, 23일 남음”, 복구 버튼 없음
- 해제 대기: 부부 상태만 표시, 개입 버튼 없음

## AD-04 개인정보 열람 요청

> 화면 그림: AD-04 개인정보 열람 요청 (그림은 기획서 페이지 사본에 있어요. 구현할 때 이 문서의 요소 표가 기준이에요.)

| 번호 | 요소 | 내용·문구 | 동작·규칙 |
| --- | --- | --- | --- |
| 1 | L1 사유 | 사유 선택 + 문의 번호 | 문의 번호 없으면 ‘보기’ 비활성 |
| 2 | L1 범위 | 칩 ‘이메일 전체’ ‘접속 기록’ ‘결제 내역’ | ‘보기’ → AD-03에 30분 표시 후 다시 가림 |
| 3 | L2 범위 | 화면·항목 종류 칩 | 여러 개 선택. 사용자가 앱에서 보는 범위만(배우자 금액만 보여 주기·숨기기 그대로). 메모·가족 정보·사진은 칩 없음 |
| 4 | 금액 원값 | “금액 원값 요청” | 기본은 구간(성공 지표 5장). 체크 시 화면 1개만, 최고 관리자 승인 후 사용자에게 요청 |
| 5 | 주 버튼 | “동의 요청 보내기” | 재인증 → 문의한 사용자 본인에게만 S-19b 요청, 본인 동의만으로 열람. 동의되면 배우자에게 열람 사실 알림. 상태: 대기 → 동의(24시간) / 거절 |

예외·오류

- 사용자 거절: 열람 불가, 문의는 스크린샷 등으로 진행
- 사용자가 ‘지금 그만 보게 하기’ 또는 24시간 경과: 즉시 닫힘, 사용자에게 “문의 처리를 위해 {범위}를 확인했어요” 알림
- 원값 승인 거절: 구간으로만 요청

## AD-10·11 공지·알림 발송

| 번호 | 요소 | 내용·문구 | 동작·규칙 |

| 4 | 대상 수 | 이름표 “대상” “제외” 작게 + “3,214명” “412명” 진하게 + 제외 사유별 수(수신 동의 없음·메일 월 상한 도달·방해 금지 시간) | 조건 바꿀 때마다 다시 계산 |
| 5 | 상한 경고 | “1,020명은 이번 발송으로 월 상한 도달” | 메일만 월 6회 상한, OS 알림·인앱 알림 센터는 상한 없음(사용자가 S-14에서 종류별로 끔)(→ 화면 설계 › 알림), 도달자는 다음 메일 발송부터 제외. 광고성 캠페인은 이 상한과 별도로 월 1회 |
| 6 | 미리보기 | OS 알림 / 이메일 / 공지 | 채널별 실제 모양. 공지는 목록 + 홈 상단 띠 |
| 7 | 테스트·승인 | “테스트 발송” / “승인 요청” | 테스트는 내부 계정만. 최고 관리자 승인(작성자 본인 불가) + 재인증 후 예약, 발송 전 취소 가능 |

예외·오류

- 대상 0명: ‘승인 요청’ 비활성
- 방해 금지 시간(밤 10시\~아침 8시) 예약: 저장 불가
- 승인 뒤 대상 변동: 발송 시점에 동의·상한 다시 반영
