# 부부·권한

두 사람이 각자 계정으로 부부 공간 하나를 씀. 제안·승인 없이 누구나 바로 고치고, 상대에게는 알림과 활동 기록이 감. 권한 검사·공개 범위 필터는 서버에서 처리. 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`.

## 1. 부부 상태

| 상태 | 들어가는 조건 | 동작 |
| --- | --- | --- |
| 미합류 | 배우자 초대 전·합류 전. 혼자 쓰기에서 설정으로 새로 초대해도 미합류로 | 홈 할 일 ‘초대하기’, 초대 리마인드. 분배표는 내 월급만으로(관리 방식과 상관없이). 바꾸면 바로 적용, 알림 없음 |
| 연결 | 배우자 합류 완료. 해제 대기 중 요청자가 취소해도 복귀 | 2장 관리 방식, 4장 ‘바로 고치고 알림’ 규칙 적용 |
| 해제 대기 | 한 사람이 연결 해제 요청(S-12) | 체크리스트 체크·월말 확인·목표·자산 기록은 계속 가능. 분배표 고치기 비활성, 관리 방식·기준일 바꾸기도 비활성 [확인 필요]. 기준일이 오면 지난 분배표 그대로 체크리스트 생성(→ 핵심 규칙 › 월 사이클 5장). 공개 범위는 그대로 |
| 혼자 쓰기 | 해제 확정(현재 사이클 종료), 상대가 계정 삭제, 또는 내가 계정 삭제를 취소하고 복구 | 초대 리마인드 없음, 분배표는 내 월급만, 바꾸면 바로 적용(알림 없음). 관리 방식 줄 숨김 [확인 필요] |

## 2. 월급 관리 방식

온보딩 O-30에서 시작한 사람이 한 번 고름. 기본 ‘각자’. 분배표·체크리스트 규칙 → 월급 체크리스트.

| 방식 | 분배표 | 체크리스트 | 수입 | 기준일 |
| --- | --- | --- | --- | --- |
| 각자 | 사람마다 하나. 저금 줄은 같은 공동 목표를 가리킴 | 사람마다 하나. 배우자 것은 보기만 + ‘대신 체크’ | 그 사람 실수령 | 사람마다 자기 월급날 |
| 합쳐서 | 하나(공동). 용돈은 사람마다 1줄 | 하나. 누구나 체크 | 두 사람 실수령 합 | 두 사람 월급날 중 늦은 날(설정 S-11에서 바꿈) |

- 배우자 합류 전: 어느 방식이든 내 월급만으로 분배표를 만듦
- 배우자 합류 때(→ 배우자 합류)
  - 합류한 사람이 방식을 확인(P-04). 바꾸면 둘 다에게 적용 + 상대 알림
  - 각자: 합류한 사람이 자기 분배표를 만듦
  - 합쳐서: 공동 분배표에 합류한 사람 용돈 줄이 더해지고, 늘어난 수입으로 저금 금액을 다시 채움
- 연결 뒤 바꾸기: 설정 S-11에서 누구나. 둘 다에게 적용 + 상대 알림, 다음 월급날부터 새 방식(이번 달 체크리스트는 그대로). 바꿔도 목표의 모은 돈은 그대로. 분배표 합치기·나누기 → 월급 체크리스트 ‘다시 계산되는 때’ [확인 필요]
- 목표는 방식과 상관없이 늘 같이 씀

## 3. 연결

- 초대: 링크 또는 6자리 코드, 유효기간 7일(만료 후 재발급 가능). 초대 상태 = 발급 → 사용됨 / 만료. 합류 완료(P-11) 때 ‘사용됨’. 잘못된 코드 5회면 10분 입력 제한. 리마인드는 만료 3일 전, 1일 전 2회, 만료되면 초대한 사람에게 새 코드 안내
- 초대하는 곳: 온보딩 O-06, 홈 할 일 한 줄, 설정 S-12
- 부부 공간 1개당 구성원 최대 2명
- 배우자 정보(이름, 월급, 월급날)는 배우자가 합류할 때 직접 입력. 시작한 사람이 대신 입력하지 않음
- 초대한 사람이 아직 온보딩 중이면(목표·분배표 없음) 합류자는 이름·월급까지만 답하고 홈 대기, 초대한 사람이 온보딩을 마치면 알림(→ 배우자 합류 ‘시작한 사람이 아직 온보딩 중’)
- 상대 명의 자산·부채: 배우자 합류 전에만 대신 입력 가능, 작은 회색 알약 ‘대신 입력’ 표시(→ 우리 자산 F-03d). 합류하면 P-02b 확인 후 소유가 배우자에게 넘어가 배우자가 수정·삭제. 합류 뒤에는 상대 명의 새로 만들기 불가
- 연결 전 혼자 입력한 데이터는 연결 시 공개 범위를 한 번 확인한 뒤 합침
- 혼자 시작한 기록이 있는 합류자: 내 명의 사실값(월급·월급날·자산·부채)만 옮김. 내 공간의 목표·분배표·체크리스트는 안 옮김, 원래 공간은 30일 보관 후 삭제(그동안 내보내기 가능)

## 4. 바로 고치고 알림

제안·승인·함께 정하기는 없음. 고칠 수 있는 사람이 고치면 바로 적용.

| 항목 | 고친 사람 | 상대 |
| --- | --- | --- |
| 바로 적용 | 저장 즉시 반영. Toast “{무엇}을 바꿨어요” [확인 필요] + ‘되돌리기’(6초). 예: 분배표 “분배표를 바꿨어요”(→ 월급 체크리스트 W-01) | 알림 + 활동 기록(알림 센터 배우자 활동) |
| 되돌리기 | Toast의 ‘되돌리기’ = 바꾸기 전 값으로. 상대에게 간 알림은 그대로 두고 활동 기록에 “되돌렸어요” 한 줄 [확인 필요] | — |
| Toast가 지난 뒤 | 다시 고치면 됨(그것도 새 변경으로 알림) | 상대도 다시 고칠 수 있음 |

- 바로 알림이 가는 변경(푸시·인앱): 분배표, 관리 방식, 체크리스트 만드는 날, 월급(실수령·월급날), 목표 추가·삭제·금액·기한·우선순위·달성, 대신 체크, 휴지통에서 되살리기 [확인 필요]
- 그 밖의 변경(자산 금액, 챙길 날 등): 활동 기록에만 남기고 주 1회 요약 [확인 필요]. 알림 종류·문구 → 화면 설계 › 알림
- 활동 기록: 누가, 언제, 무엇을 전 → 후로. 공개 범위 밖(비공개 항목) 변경은 남기지 않음
- 목표 삭제·보류: 묻지 않고 바로 실행 + Toast ‘되돌리기’, 상대 알림. 삭제는 휴지통으로(30일)
- 같은 값을 두 사람이 거의 동시에 고침: 나중에 저장된 값이 남고, 먼저 고친 사람에게 “예빈님이 방금 바꿨어요” [확인 필요]. 체크는 먼저 저장된 체크 유지(→ 월급 체크리스트 W-02). 오프라인 충돌 → 기술·운영 › 동기화
- 미합류·혼자 쓰기: 상대가 없으니 알림·활동 기록 없음, Toast ‘되돌리기’만

## 5. 권한

| 동작 | 한 사람 | 상대 |
| --- | --- | --- |
| 내 명의 자산·부채 수정 | 가능 | 불가(공개 범위대로 보기만) |
| 공동 항목(공동 명의 자산·부채, 챙길 날) 수정 | 가능 | 가능(4장 알림) |
| 목표 추가·수정·삭제·우선순위 | 가능 | 가능(4장 알림) |
| 내 월급(실수령·월급날) | 본인만 | 보기만 |
| 분배표(각자) | 내 분배표 | 배우자 분배표도 고칠 수 있음(바로 저장 + 상대 알림) |
| 분배표(합쳐서) | 가능 | 가능 |
| 체크리스트(각자) | 내 것 체크 | 배우자 것은 ‘대신 체크’(체크한 사람 기록) |
| 체크리스트(합쳐서) | 누구나 체크 | 누구나 체크 |
| 월말 확인 ‘이번 달은 못 했어요’ | 체크 권한과 같음 | 체크 권한과 같음 |
| 관리 방식, 체크리스트 만드는 날, 주말·공휴일 앞당겨 표시 | 가능(부부 공통 값) | 가능(4장 알림) |

- 권한 밖 저장(상대 명의 항목 수정, 합류 뒤 상대 명의 새로 만들기, 해제 대기 중 분배표 고치기 등)은 서버가 거절
- 데스크톱 앱과 모바일 앱의 권한은 같음

## 6. 공개 범위 (S-13)

| 단계 | 배우자에게 보이는 것 | 기본 적용 대상 |
| --- | --- | --- |
| 전체 공개 | 항목명·금액·상세 | 공동 명의 항목, 목표, 챙길 날 |
| 합계만 | 금액만 합계에 반영, 항목명 비공개 | 개인 명의 자산·부채 |
| 비공개 | 보이지 않음, 합계에도 미반영 | 서프라이즈 항목 |

- 월급(실수령·월급날)과 분배표·체크리스트는 공개 범위 없이 늘 같이 봄(각자 방식에서도 배우자 것은 보기 가능)
- 서프라이즈 항목(배우자 생일 챙길 날 등): 작성자만 봄, 배우자 화면에는 나타나지 않음 [확인 필요]
- 필터는 서버에서 적용, 배우자 기기에는 공개 범위에 맞는 값만 전송

## 7. 연결 해제 (S-12)

1. 해제 요청자가 ‘자산 정리 안’을 만들어 상대에게 보냄
2. 상대 동의, 또는 상대가 ‘다르게 정리하기’ 1회(요청자가 동의하면 그 안)
3. 합의 없으면 14일 후 기본안 적용. 적용 2일 전 양쪽에 알림 1회
4. 확정 시 현재 사이클 종료, 각자 ‘혼자 쓰기’

자산 정리 안

| 대상 | 기본안 | 확정 뒤 |
| --- | --- | --- |
| 공동 명의 자산 | 반반 [확인 필요] | 정한 몫이 각자 명의 자산으로 |
| 공동 명의 부채 | 반반 [확인 필요] | 정한 몫이 각자 명의 부채로 |
| 목표(모은 돈) | 반반 [확인 필요] | 각자 공간에 같은 목표가 생기고 정한 몫이 모은 돈으로 |

- 각자 명의 자산·부채는 정리 대상이 아님(명의자에게 남음)
- 목표의 모은 돈은 순자산에 따로 더하지 않으므로(실제 돈은 통장에 있음) 자산과 목표를 함께 나누면 같은 돈을 두 번 나누게 될 수 있음. 목표 몫을 금액으로 나눌지, 목표만 각자 이어 갈지 [확인 필요]
- 각자 방식이었으면 기본안을 각자 체크한 저금 합계 비율로 할지 [확인 필요]
- 정리할 대상이 없으면(공동 명의 항목·목표 없음) 자산 정리 안 없이 확인만
- 분배표: 각자 방식이면 각자 자기 분배표 그대로. 합쳐서였으면 공동 분배표를 각자 복사하고 수입은 내 월급만, 상대 용돈 줄은 빠짐. 남는 돈이 모자라면 W-01에서 고치라는 안내 [확인 필요]
- 요청자는 상대 응답 전까지 취소 가능, 취소하면 연결 상태로 돌아가고 분배표 고치기 다시 가능
- 해제 전 데이터 내보내기 제공. 데이터가 누구에게 남는지 → 보안·개인정보

## 8. 다시 연결, 계정 삭제

- 30일 재연결: 해제 확정 뒤 30일 동안만 설정 S-12에 “다시 연결하기”. 누르면 상대에게 요청 알림 → 상대 수락 화면 S-12g(“다시 연결할게요” / “괜찮아요”) → 수락하면 해제 전 공동 데이터(목표, 분배표, 지난 체크리스트, 공동 항목, 챙길 날) 복구
  - “괜찮아요”면 요청 종료, 30일 안이면 다시 요청 가능. 열린 요청은 30일이 지나면 만료
  - 해제 뒤 각자 바뀐 값은 각자 명의 기준 유지, 공개 범위 한 번 확인
  - 30일이 지나면 각자 사본으로 분리 확정, 복구 불가. 필드 → 핵심 규칙 › 데이터 항목 ‘연결 해제’
- 계정 삭제 유예 중 복구: 삭제 요청 때 연결은 끊김. 30일 안 다시 로그인해 복구하면 ‘혼자 쓰기’로 돌아오고, 그때부터 30일 안 위 재연결 가능. 상대에게 ‘계정 복구’ 알림 1종(→ 화면 설계 › 알림)
- 계정 삭제 규칙 → 보안·개인정보 3장, 화면 → 설정 S-18

## 9. 없앤 것

- 제안·승인·함께 정하기와 그 적용일 규칙, 규칙 확정 전 기본값, 분담 방식·분담 비율, 배우자 수입 추정과 수입 대신 입력, 배우자 용돈 가정, 예비부부 단계와 결혼일 전환
- 부부 단계(신혼 첫해, 2~3년차, 이후)를 가이드 체크리스트(설정 S-01)에 계속 쓸지, 쓰면 무엇으로 정할지 [확인 필요]. 결혼일 질문은 없앰
