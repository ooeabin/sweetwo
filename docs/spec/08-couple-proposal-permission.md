# 부부·제안·권한

두 사람이 각자 계정으로 부부 공간 하나를 씀. 사실값은 바로 바뀌고, 배분 결정은 ‘제안’ 하나로 바뀜(구분 → 핵심 규칙 › 계산·배분 1장). 권한 검사·공개 범위 필터는 서버에서 처리.

## 1. 부부 상태

| 상태 | 들어가는 조건 | 동작 |
| --- | --- | --- |
| 미합류 | 배우자 초대 전·합류 전. 혼자 쓰기에서 설정으로 새로 초대해도 미합류로 | ‘임시’ 배지, 초대 리마인드, 배우자 용돈·분담 가정(→ 월 사이클 3장), 배분 결정 바로 적용, 사실값 알림 없음 |
| 연결 | 배우자 합류. 해제 대기 중 요청자가 취소해도 복귀 | 제안·알림 규칙 적용 |
| 해제 대기 | 한 사람이 연결 해제 요청(S-12) | 제안 동결(보내기·응답·적용 멈춤). 월급 나누기·기록·월말 정리 가능, 월말 정리의 다음 달 조정(W-04h)은 건너뜀. 기준일이 오면 지난 플랜 연장. 공개 범위는 그대로 |
| 혼자 쓰기 | 해제 확정(현재 사이클 종료), 상대가 계정 삭제, 또는 내가 계정 삭제를 취소하고 복구 | 초대 리마인드·‘임시’ 배지 없음, 분담·용돈 가정 없음(내 용돈만), 배분 결정 제안 없이 즉시 적용 + 안 나눈 돈 재계산 |

## 2. 연결

- 초대: 링크 또는 6자리 코드, 유효기간 7일(만료 후 재발급 가능). 초대 상태 = 발급 → 사용됨 / 만료. 합류 완료(P-11) 때 ‘사용됨’. 잘못된 코드 5회면 10분 입력 제한. 리마인드는 만료 3일 전, 1일 전 2회, 만료되면 초대한 사람에게 새 코드 안내. 초대한 사람이 아직 온보딩 중(플랜 없음)이면 합류자는 내 정보까지만 답하고 P-11 대기, 첫 플랜이 나오면 알림(→ 배우자 합류 P-11 대기)
- 부부 공간 1개당 구성원 최대 2명
- 배우자 정보는 배우자 본인 입력이 기본. 먼저 시작한 사람은 배우자 수입을 대략 구간으로만 입력(‘추정’). 배우자 합류 전에만 ‘제가 대신 입력할게요’ 가능, 합류하면 배우자 본인이 고침
- 상대 명의 자산·부채: 배우자 합류 전에만 대신 입력 가능, 작은 회색 알약 ‘대신 입력’ 표시. 합류하면 소유가 배우자에게 넘어가 배우자가 수정·삭제. 합류 뒤에는 상대 명의 새로 만들기 불가
- 연결 전 혼자 입력한 데이터는 연결 시 공개 범위를 한 번 확인한 뒤 합침
- 혼자 시작한 기록이 있는 합류자: 내 명의 사실값(수입·월급날·자산·부채·용돈)만 옮김. 내 공간의 목표·플랜·월말 기록은 안 옮김, 원래 공간은 30일 보관 후 삭제(그동안 내보내기 가능)
- 초대한 사람이 미리 적은 내 항목은 P-02b 사전 입력 확인에서 합류자가 고름
- 미합류 동안 바로 적용된 변경은 합류 시 P-10에서 목록으로만 보여줌. 배우자 용돈은 합류(P-07) 때 본인이 입력(제안)

## 3. 연결 해제 (S-12)

1. 해제 요청자가 자산 정리 안(기본: 분담 비율)을 만들어 상대에게 보냄
2. 상대 동의, 또는 상대가 ‘다르게 정리하기’ 1회(요청자가 동의하면 그 안)
3. 합의 없으면 14일 후 기본안(분담 비율) 적용. 적용 2일 전 양쪽에 알림 1회
4. 확정 시 현재 사이클 종료, 각자 ‘혼자 쓰기’

- 요청자는 상대 응답 전까지 취소 가능, 취소 시 연장 중이던 플랜 정상 재개
- 해제 전 데이터 내보내기 제공. 데이터가 누구에게 남는지(양가 가족 정보·공동 기록 사본·예비부부 결혼 비용 요약 등) → 보안·개인정보
- 30일 재연결: 해제 확정 뒤 30일 동안만 설정 S-12에 “다시 연결하기”. 누르면 상대에게 요청 알림 → 상대 수락 화면 S-12g(“찬우님이 다시 연결하자고 해요”, “다시 연결할게요” / “괜찮아요”) → 수락하면 해제 전 공동 데이터(목표·플랜·월말 정리·제안 기록·공동 항목) 복구. “괜찮아요”면 요청 종료, 30일 안이면 다시 요청 가능. 열린 요청은 30일이 지나면 만료. 해제 뒤 각자 바뀐 값은 각자 명의 기준 유지, 공개 범위 한 번 확인. 30일이 지나면 각자 사본으로 분리 확정, 복구 불가. 필드 → 핵심 규칙 › 데이터 항목 ‘연결 해제’
- 계정 삭제 유예 중 복구: 삭제 요청 때 연결은 끊김. 30일 안 다시 로그인해 복구하면 ‘혼자 쓰기’로 돌아오고, 그때부터 30일 안 위 재연결 가능. 상대에게 ‘계정 복구’ 알림 1종(→ 화면 설계 › 알림)

## 4. 공개 범위

| 단계 | 배우자에게 보이는 것 | 기본 적용 대상 |
| --- | --- | --- |
| 전체 공개 | 항목명·금액·상세 | 공동 소유 항목, 목표, 양가 일정 |
| 합계만 | 금액만 합계에 반영, 항목명 비공개 | 개인 소유 자산·부채 |
| 비공개 | 보이지 않음, 합계에도 미반영 | 서프라이즈 항목 |

- 서프라이즈 항목(배우자 생일 등): 예산·기록은 작성자만 보고, 배우자 합계에는 ‘비밀 항목’으로만 표시. 지출은 ‘각자 돈’으로만 기록(공동 통장·목표 잔액에 안 드러나게)
- 재정 진단은 ‘비공개’ 항목 제외 후 계산, 리포트에 그 사실 표시
- 필터는 서버에서 적용, 배우자 기기에는 공개 범위에 맞는 값만 전송

## 5. 권한

| 동작 | 한 사람 | 상대 |
| --- | --- | --- |
| 내 명의 항목 수정 | 가능 | 불가 |
| 공동 항목 수정 | 가능 | 가능(변경 알림) |
| 사실값 변경 | 즉시 반영 | 알림만(H-08 활동 + 주 1회 요약, 수입 변경은 즉시) |
| 배분 결정 변경 | 제안 | 좋아요 / 다르게 해볼래요 / 반대 |
| 이번 달만 바꾸기(W-01) | 즉시 적용, 되돌리기 가능 | 알림만 |
| 월말 정리 | 가능(한 사람이 해도 완료) | 가능 |
| 배우자 몫 월급 나누기 | 대신 체크 가능(체크한 사람 기록, 앱·웹) | — |

- 권한 밖 저장(상대 명의 항목 수정, 합류 뒤 상대 명의 새로 만들기, 해제 대기 중 제안 등)은 서버가 거절
- 반응형 웹 권한은 앱과 같음

## 6. 제안

### 6-1. 대상

- 배분 결정만: 용돈(내 용돈만, 상대 용돈은 제안 대상 아님), 분담 방식, 공동 목표 추가·삭제·우선순위·금액·기한·보류·다시 모으기·담당, 기준일, 생활비 예산, 양가 비용 예산, 결혼 비용 예산, 혼자 정리한 월말 정리의 다음 달 조정
- 담당 ‘나’·‘배우자’ 목표도 공동 저축 가능 금액을 쓰면 제안
- 목표 삭제·보류: 묻지 않고 바로 실행 + Toast “되돌리기”. 배우자와 연결된 상태면 바로 바뀌지 않고 제안으로 보냄

### 6-2. 보내기·응답

| 항목 | 규칙 |
| --- | --- |
| 보내기 | 바꾼 값 저장 = 제안 생성. 확인 없이 바로 보냄. 상대가 열기 전까지 ‘보내기 취소’(없던 일로), 연 뒤 적용 전까지 ‘철회’ |
| 도착 | 상대에게 알림 1회 + 상대 이번 달 할 일(H-04) 맨 위 ‘받은 제안’ → 제안 확인(G-08: 전·후 값, 월 배분 영향). 문구 “좋아요면 바로, 반대 없으면 {날짜}부터 적용돼요”. 확인 요청 알림 별도 없음 |
| 좋아요 | 즉시 확정 + 이번 사이클 안 나눈 돈 재계산 |
| 다르게 해볼래요 | 같은 편집 화면에서 수정 제안, 이전 제안을 대체해 상대에게 감. 용돈 제안엔 없음(좋아요 / 반대만) |
| 반대 | 보류. 월말 정리 ‘다음 달 조정’(W-04h)에서 함께 다룸 |
| 무응답 | 적용일에 적용(6-3). ‘함께 정하기’ 항목은 적용 안 함 |
| 항목당 1개 | 항목당 열린 제안 1개. 같은 항목 새 제안은 이전 제안 대체, 상대 제안에는 ‘다르게 해볼래요’로만 |
| 철회 | 제안자는 적용 전 언제든 철회 |
| 되돌리기 | 적용 후에도 누구나 ‘되돌리기’ 제안(같은 규칙) |
| 월말 정리 제안 | 혼자 정리(W-04h)하면 바뀐 값 전체가 묶음 1건(전·후 목록). ‘모두 좋아요’ = 즉시 확정, 항목별 반대 가능(반대가 생기면 라벨 “나머지 {n}개 좋아요”). 문구 “반대 없으면 {기준일}부터 적용돼요” |

### 6-3. 적용일

- 평소 제안(72시간 규칙): 적용일 = 제안 후 72시간이 지난 첫 기준일 0시
- 월말 정리 제안: 72시간 규칙 없이 기준일 전날 23시 59분까지 반대 없으면 다음 기준일 적용
- 적용 2일 전 ‘제안 적용 예정’ 알림 1회(반대 안 한 제안이 있을 때)
- 상대가 “좋아요” 또는 “반대”로 응답하면 제안자에게 결과 알림 1회. ‘다르게 해볼래요’는 ‘제안 도착’ 알림으로 감
- 기준일 적용 직전 적용될 제안을 묶어 다시 계산. 저축 가능 금액이 부족해지면 적용 멈춤(보류) + 양쪽 알림
- 적용된 값은 그달 월 플랜에 반영(플랜은 기준일 0시 그 시점 값으로 생성)
- 알림 상한(메일만 월 6회)에 들어가는지 → 화면 설계 › 알림

### 6-4. 함께 정하기

- 같은 항목·같은 제안 묶음에서 반대 2회, 또는 ‘다르게 해볼래요’ 2회 왕복 → ‘함께 정하기’ 표시(상태가 아닌 표시). 문구 “다음 월말 정리에서 함께 정해요”
- 횟수는 묶음이 적용·철회·만료되면 0으로 초기화
- 무응답이면 적용 안 함(지난 값 유지). 둘이 함께 확정(함께 모드 또는 양쪽 ‘좋아요’)해야 바뀌고, 확정 시 표시 해제

### 6-5. 상태

| 상태 | 조건 |
| --- | --- |
| 제안 중 | 만든 뒤 적용 전 |
| 적용 | ‘좋아요’ 받으면 즉시, 무응답이면 적용일 0시 |
| 보류 | 상대가 반대, 또는 적용 직전 재계산에서 저축 가능 금액 부족 |
| 철회 | 제안자가 취소 |
| 만료 | 보류 후 다음 월말 정리까지 해결 안 됨 |
| 되돌림 | 적용 후 되돌리기 제안이 적용됨 |

### 6-6. 예외

- 배우자 미합류 → 바로 적용. 합류 시 P-10에서 그동안 적용된 것 목록만
- 연결 해제 후 ‘혼자 쓰기’ → 제안 없이 즉시 적용(미합류와 구분)
- 연결 해제 대기 중 → 1장 ‘해제 대기’ 행
- 예식 30일 이내 결혼 비용 예산 → 바로 적용, 상대에게 알림만
- 함께 모드 월말 정리에서 바꾼 값 → 제안 없이 바로 확정
- ‘이번 달만 바꾸기’(W-01)·W-03c ‘내 용돈에서’·보충 줄 → 제안 아님, 즉시 적용 + 상대 알림

### 6-7. 동시에 일어날 때

- 같은 항목에 제안이 동시에 생기면 서버 도착 순서로 앞 제안 유지, 나중 것은 앞 제안에 대한 ‘다르게 해볼래요’로 합침(왕복 1회로 셈). 나중 제안자 문구 “{이름}님이 먼저 제안해서, 내 제안은 ‘다르게 해볼래요’로 보냈어요”
- 제안 기준 값(수입·고정지출 등)이 그 사이 바뀌면 전·후 값과 월 배분 영향을 다시 계산. 응답 화면 “내용이 바뀌었어요” + 다시 계산한 값
- 응답·철회는 서버 도착 순서 우선. 철회 뒤 도착한 응답은 무효(“{이름}님이 이 제안을 거둬들였어요”), 응답 뒤 도착한 철회는 거절(“이미 {이름}님이 답했어요”)
- 적용(기준일 0시) 이후 도착한 ‘반대’는 되돌리기 제안으로 안내: “이미 적용됐어요. 되돌리기를 제안할까요?”. 마감 판단은 서버 도착 시각 기준

## 7. 규칙 확정 전 기본값

배우자 합류·결혼일 전환 직후 용돈·분담이 확정되기 전에는 기본값으로 플랜 생성, 규칙 확정 시 안 나눈 돈 재계산.

- 분담 = 이미 고른 방식 유지(O-52, 없으면 반반)
- 배우자 용돈 = 내 용돈과 같은 금액(예비 단계 값이 있으면 그 값)
- 내 용돈 미입력(O-52 ‘나중에 하기’)이면 50만 원

- 전환 시작: 예식 후 첫 기준일(최소 예식 + 7일)에 알림과 함께. 알림은 예식일 확정 후에만(예정 월 ‘추정’ 상태면 없음)
- 직접 시작: ‘결혼했어요’ 진입점 = H-P1 카드 + 설정 부부 정보
- 예식일 미정이면 예정 월 말일이 지나면 H-P1 카드 “예식을 올렸나요?” \[결혼했어요 → H-T\] / \[미뤄졌어요 → 새 예정 월 입력\]
- 두 사람 중 한 명이 진행. 돈 나누는 규칙(H-T3)은 배우자에게 제안으로 감, 확정 전엔 7장 기본값
- ‘나중에 할게요’면 예비부부 상태 유지, 이번 달 맨 위에 ‘결혼 후 설정 마무리’
- 전환 때 생기는 목표·플랜 처리 → 핵심 규칙 › 계산·배분 11장
