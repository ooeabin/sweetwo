# 부부·권한

두 사람이 각자 계정으로 부부 공간 하나를 씀. 제안·승인 없이 누구나 바로 고치고, 상대에게는 알림과 활동 기록이 감. 권한 검사·공개 범위 필터는 서버에서 처리. 결정 이유 → `docs/adr/0003-replan-goal-checklist.md`.

## 1. 부부 상태

| 상태 | 들어가는 조건 | 동작 |
| --- | --- | --- |
| 미합류 | 배우자 초대 전·합류 전. 혼자 쓰기에서 설정으로 새로 초대해도 미합류로 | 홈 할 일 ‘초대하기’, 초대 리마인드. 분배표는 내 월급만으로(관리 방식과 상관없이). 바꾸면 바로 적용, 알림 없음 |
| 연결 | 배우자 합류 완료. 해제 대기 중 요청자가 취소해도 복귀 | 2장 관리 방식, 4장 ‘바로 고치고 알림’ 규칙 적용 |
| 해제 대기 | 한 사람이 연결 해제 요청(S-12). 상대가 확인하거나 요청 + 14일이 지나면 확정, 요청자가 취소하면 연결로 | 체크리스트 체크·월말 확인·목표 넣기·빼기·자산 기록은 계속 가능. 분배표 고치기, 관리 방식 바꾸기, 체크리스트 만드는 날 바꾸기는 비활성. 기준일이 오면 지난 분배표 그대로 체크리스트 생성(→ 핵심 규칙 › 월 사이클 5장). 공개 범위는 그대로 |
| 혼자 쓰기 | 해제 확정, 상대가 계정 삭제, 또는 내가 계정 삭제를 취소하고 복구 | 초대 리마인드 없음, 분배표는 내 월급만, 바꾸면 바로 적용(알림 없음). 관리 방식 줄 숨김 [확인 필요]. 해제 확정으로 들어오면 빈 공간에서 온보딩 O-11부터 다시 시작(→ 7장) |

## 2. 월급 관리 방식

온보딩 O-30에서 시작한 사람이 한 번 고름. 기본 ‘각자’. 분배표·체크리스트 규칙 → 월급 체크리스트.

| 방식 | 분배표 | 체크리스트 | 수입 | 기준일 |
| --- | --- | --- | --- | --- |
| 각자 | 사람마다 하나. 우리 목표 저금 줄은 두 사람 분배표에 1줄씩, 내 목표는 주인 분배표에만 | 사람마다 하나. 배우자 것은 보기만 + ‘대신 체크’ | 그 사람 실수령 | 사람마다 자기 월급날 |
| 합쳐서 | 하나(공동). 용돈은 사람마다 1줄. 내 목표 줄은 주인 이름을 붙여 1줄 | 하나. 누구나 체크 | 두 사람 실수령 합 | 두 사람 월급날 중 늦은 날(설정 S-11에서 바꿈) |

- 배우자 합류 전: 어느 방식이든 내 월급만으로 분배표를 만듦
- 배우자 합류 때(→ 배우자 합류)
  - 합류한 사람이 방식을 확인(P-04). 바꾸면 둘 다에게 적용 + 상대 알림
  - 각자: 합류한 사람이 자기 분배표를 만듦
  - 합쳐서: 공동 분배표에 합류한 사람 용돈 줄이 더해지고, 늘어난 수입으로 저금 금액을 다시 채움
- 연결 뒤 바꾸기: 설정 S-11에서 누구나. 둘 다에게 적용 + 상대 알림. 바꾸면 바로 새 분배표 확인 화면(W-01), 체크리스트는 다음 월급날부터 새 방식(이번 달 체크리스트는 그대로). 바꿔도 목표의 모은 돈은 그대로
  - 각자 → 합쳐서: 같은 목표 줄은 금액을 더해 1줄, 고정지출·생활비는 더해서 한 줄씩, 용돈은 사람마다 1줄 그대로, 내 목표 줄은 주인 이름을 붙인 줄로
  - 합쳐서 → 각자: 저금·고정지출·생활비 줄을 두 사람 수입 비율로 나눔(1만 원 단위, 남는 차이는 기준일 사람 쪽), 용돈은 각자 자기 분배표로, 내 목표 줄은 주인 분배표로
  - 자세한 처리 → 월급 체크리스트 ‘다시 계산되는 때’
- 목표는 방식과 상관없이 같이 봄. 종류는 우리 목표(둘이 같이 모음) / 내 목표(주인 혼자 모음) 두 가지, 비상금은 우리 목표(→ 목표 ‘목표 종류’)

## 3. 연결

- 초대: 링크 또는 6자리 코드, 유효기간 7일(만료 후 재발급 가능). 초대 상태 = 발급 → 사용됨 / 만료. 합류 완료(P-11) 때 ‘사용됨’. 잘못된 코드 5회면 10분 입력 제한. 리마인드는 만료 3일 전, 1일 전 2회, 만료되면 초대한 사람에게 새 코드 안내
- 초대하는 곳: 온보딩 O-06, 홈 할 일 한 줄, 설정 S-12
- 부부 공간 1개당 구성원 최대 2명
- 배우자 정보(이름, 월급, 월급날)는 배우자가 합류할 때 직접 입력. 시작한 사람이 대신 입력하지 않음
- 초대한 사람이 아직 온보딩 중이면(목표·분배표 없음) 합류자는 이름·월급까지만 답하고 홈 대기, 초대한 사람이 온보딩을 마치면 알림(→ 배우자 합류 ‘시작한 사람이 아직 온보딩 중’)
- 상대 명의 자산·부채: 배우자 합류 전에만 대신 입력 가능, 작은 회색 알약 ‘대신 입력’ 표시(→ 우리 자산 F-03d). 합류하면 P-02b 확인 후 소유가 배우자에게 넘어가 배우자가 수정·삭제. 합류 뒤에는 상대 명의 새로 만들기 불가
- 연결 전 혼자 입력한 데이터는 연결 시 공개 범위를 한 번 확인한 뒤 합침
- 혼자 시작한 기록이 있는 합류자: 내 명의 사실값(월급·월급날·자산·부채)만 옮김. 내 공간의 목표·분배표·체크리스트는 안 옮김, 원래 공간은 30일 보관 후 삭제(그동안 내보내기 가능)

## 4. 바로 고치고 알림

제안·승인·함께 정하기는 없음. 고칠 수 있는 사람이 고치면 바로 적용.

| 항목 | 고친 사람 | 상대 |
| --- | --- | --- |
| 바로 적용 | 저장 즉시 반영. Toast “{무엇}을 바꿨어요” [확인 필요] + ‘되돌리기’(6초). 예: 분배표 “분배표를 바꿨어요”(→ 월급 체크리스트 W-01) | 알림 + 활동 기록(알림 센터 배우자 활동) |
| 되돌리기 | Toast의 ‘되돌리기’ = 바꾸기 전 값으로. 상대에게 간 알림은 그대로 두고 활동 기록에 “되돌렸어요” 한 줄 [확인 필요] | — |
| Toast가 지난 뒤 | 다시 고치면 됨(그것도 새 변경으로 알림) | 상대도 다시 고칠 수 있음 |

- 묶기: 같은 사람이 10분 안에 바꾼 것은 푸시 1번으로 묶음(알림 센터 항목도 1개). 그 10분 안에 ‘되돌리기’로 취소한 변경은 알리지 않음
- 바로 알림이 가는 변경(푸시·인앱): 분배표 금액, 관리 방식, 우리 목표 금액·기한·삭제, 대신 체크, 목표 달성
- 주간 요약에만 가는 변경(활동 기록 + 월요일 요약, 푸시 없음): 자산 금액 수정, 목표 이름·사진·순서, 챙길 날 추가·메모
- 위 두 목록에 없는 변경(체크리스트 만드는 날, 월급, 우리 목표 추가·보류, 넣기·빼기·꺼내 쓰기, 목표 종류 바꾸기, 휴지통에서 되살리기 등)이 어느 쪽인지 [확인 필요]
- 내 목표 변경은 배우자에게 알리지 않고 활동 기록에도 남기지 않음. 내 목표 달성만 배우자에게 알림 [확인 필요]. 알림 종류·문구 → 화면 설계 › 알림
- 활동 기록: 누가, 언제, 무엇을 전 → 후로. 공개 범위 밖(비공개 항목) 변경은 남기지 않음
- 목표 삭제·보류: 묻지 않고 바로 실행 + Toast ‘되돌리기’, 상대 알림(내 목표는 알림 없음). 삭제는 휴지통으로(30일)
- 같은 값을 두 사람이 거의 동시에 고침: 나중에 저장된 값이 남고, 먼저 고친 사람에게 “예빈님이 방금 바꿨어요” [확인 필요]. 체크는 먼저 저장된 체크 유지(→ 월급 체크리스트 W-02). 오프라인 충돌 → 기술·운영 › 동기화
- 미합류·혼자 쓰기: 상대가 없으니 알림·활동 기록 없음, Toast ‘되돌리기’만

| 체크리스트(각자) | 내 것 체크 | 배우자 것은 ‘대신 체크’(체크한 사람 기록) |
| 체크리스트(합쳐서) | 누구나 체크 | 누구나 체크 |
| 월말 확인 ‘이번 달은 못 했어요’ | 체크 권한과 같음 | 체크 권한과 같음 |
| 관리 방식, 체크리스트 만드는 날, 주말·공휴일 앞당겨 표시 | 가능(부부 공통 값) | 가능(4장 알림) |

- 권한 밖 저장(상대 명의 항목 수정, 상대 내 목표 수정, 합류 뒤 상대 명의 새로 만들기, 해제 대기 중 분배표 고치기 등)은 서버가 거절
- 내 목표 저금 줄 금액은 주인만 고침. 배우자 분배표(각자)에서 그 줄은 잠금, 합쳐서 공동 분배표의 주인 이름 붙은 줄도 같음 [확인 필요]. 체크는 체크리스트 권한대로
- 데스크톱 앱과 모바일 앱의 권한은 같음

## 6. 공개 범위 (S-13)

| 단계 | 배우자에게 보이는 것 | 기본 적용 대상 |
| --- | --- | --- |
| 전체 공개 | 항목명·금액·상세 | 공동 명의 항목, 우리 목표, 내 목표, 챙길 날 |
| 합계만 | 금액만 합계에 반영, 항목명 비공개. 내 목표는 이름 대신 “개인 목표” + 금액 합계만 | 개인 명의 자산·부채 |
| 비공개 | 보이지 않음, 합계에도 미반영 | 서프라이즈 항목 |

- 월급(실수령·월급날)과 분배표·체크리스트는 공개 범위 없이 늘 같이 봄(각자 방식에서도 배우자 것은 보기 가능)
- 공개 범위를 고를 수 있는 목표는 내 목표뿐(주인이 고름, 기본 전체 공개). 내 목표는 ‘전체 공개’ / ‘합계만’ 두 가지만, 비공개 없음. 우리 목표는 늘 전체 공개
- ‘합계만’ 내 목표는 배우자 화면의 분배표·체크리스트 저금 줄 이름도 “개인 목표”(금액은 보임, 분배표가 늘 같이 보이므로)
- 서프라이즈 항목(배우자 생일 챙길 날 등): 작성자만 봄, 배우자 화면에는 나타나지 않음 [확인 필요]
- 필터는 서버에서 적용, 배우자 기기에는 공개 범위에 맞는 값만 전송

## 7. 연결 해제 (S-12)

2026-10-26 결정: 같이 쓰던 데이터는 나누지 않고 모두 지움. 자산을 나누는 안, 기본 비율, 상대가 다르게 정하는 단계는 없음(→ `docs/adr/0003-replan-goal-checklist.md` 11장).

1. 요청: 한 사람이 S-12 → S-12a 안내(지워지는 것 + ‘먼저 내보내기’ → S-18) → S-12c “연결 해제” 입력 후 요청. 상대에게 알림(상한 밖) + 홈 할 일 맨 위
2. 확정: 상대가 S-12d에서 확인하거나, 요청 + 14일이 지나면 서버가 확정. 상대가 거절하는 단계는 없음
3. 취소: 요청자는 확정 전까지 S-12 ‘요청 취소’. 연결 상태로 돌아가고 분배표 고치기 다시 가능, 상대 알림
4. 대기 중(해제 대기): 체크는 계속, 분배표·관리 방식·체크리스트 만드는 날 고치기 비활성(→ 1장)

## 8. 다시 연결, 계정 삭제

- 30일 재연결: 해제 확정 뒤 30일 동안만 설정 S-12에 “다시 연결하기”. 누르면 상대에게 요청 알림 → 상대 수락 화면 S-12g(“다시 연결할게요” / “괜찮아요”) → 수락하면 서버가 보관한 해제 전 부부 공간 데이터(목표, 분배표, 지난 체크리스트, 자산·부채, 챙길 날, 활동·알림 기록) 복구 [확인 필요]
  - “괜찮아요”면 요청 종료, 30일 안이면 다시 요청 가능. 열린 요청은 30일이 지나면 만료
  - 해제 뒤 혼자 쓰기에서 새로 만든 데이터(새 온보딩의 목표·분배표, 새로 적은 자산)를 복구한 공간에 합칠지 버릴지 [확인 필요]. 복구 뒤 공개 범위 한 번 확인
  - 30일이 지나면 보관 데이터 영구 삭제, 복구 불가. 필드 → 핵심 규칙 › 데이터 항목 ‘연결 해제’
- 계정 삭제 유예 중 복구: 삭제 요청 때 연결은 끊김. 30일 안 다시 로그인해 복구하면 ‘혼자 쓰기’로 돌아오고, 그때부터 30일 안 위 재연결 가능. 상대에게 ‘계정 복구’ 알림 1종(→ 화면 설계 › 알림)
- 계정 삭제 규칙 → 보안·개인정보 3장, 화면 → 설정 S-18

## 9. 없앤 것

- 제안·승인·함께 정하기와 그 적용일 규칙, 규칙 확정 전 기본값, 분담 방식·분담 비율, 배우자 수입 추정과 수입 대신 입력, 배우자 용돈 가정, 예비부부 단계와 결혼일 전환
- 연결 해제 때 공동 명의 자산·부채·목표를 몫으로 나누던 단계(기본 비율, 상대가 다르게 정하기, 기한 전 알림), 화면 S-12b·S-12e·S-12f(2026-10-26, 7장)
- 결혼 단계(예비, 신혼 첫해, 2~3년차, 이후)는 묻지 않고 결혼 상태(O-11)와 결혼한 날·예정일(O-12)로 계산. 정의는 → 핵심 규칙 › 계산·배분 7-1(2026-10-26 결혼한 날 질문을 다시 넣음). 단계가 바뀌어도 화면 모드나 전환 흐름은 없음. 가이드 체크리스트(설정 S-01)에도 이 단계를 쓸지 [확인 필요]
