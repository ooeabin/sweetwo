# 어드민

웹 전용 내부 운영 도구의 원칙·역할·권한·계정 보안·운영 시나리오. 화면별 구성·문구는 → 어드민 화면. 접근 로그·보관 기간·법정 보관은 → 보안·개인정보, 지표 정의는 → 성공 지표, 버전 정책은 → 동기화 6장.

## 1. 목적·원칙

| 원칙 | 기준 |
| --- | --- |
| 웹 전용 내부 도구 | 사용자 앱과 분리된 도메인·서버 권한, 검색 노출 차단. 데스크톱 앱·모바일 미지원 |
| 금융 데이터 기본 비노출 | 금액·잔액·수입·항목명·메모·가족 정보·사진은 목록·상세 어디에도 기본 표시 안 함. 상태·개수·날짜 같은 구조 정보만 표시 |
| 열람은 3단계 | L0 기본(메타데이터, 이메일 마스킹) / L1 사유 입력(이메일 전체·접속 기록·결제 내역) / L2 사용자 동의(금액 구간·항목명, 동의한 범위·기한만). 화면은 → 어드민 화면 AD-04 |
| 항상 열람 불가 | 메모, 양가 가족 정보, 사진, 서프라이즈·숨기기 항목. L2 동의로도 열리지 않음 |
| 모든 열람·조치는 감사 로그 | 누가·언제·무엇을·왜. 보관 1년(보안·개인정보 2장 ‘관리자 접근’), 결제·분쟁 처리 기록은 법정 기간(보안·개인정보 3-3) |
| 사용자 데이터 직접 수정 금지 | 자산·목표·월급 분배표·체크리스트·부부 연결 값은 어드민에서 편집 화면 없음. 고칠 일은 사용자 본인이 앱에서 하도록 안내 |
| 예외 절차만 허용 | 서버 작업 재실행(월급날 체크리스트 생성 실패 등), 백업 복원은 어드민 화면이 아닌 콘솔 런북(→ 개발 가이드)으로, 개발 담당 + 최고 관리자 2인 승인, 부부 공간 단위, 사용자 요청 기록 필수. 값 단위 편집은 예외 절차로도 안 함 |
| 부부 사이 판단에 개입 안 함 | 연결 해제·서로 고친 값 다툼은 앱 규칙(→ 핵심 규칙 › 부부·권한)대로만. 운영자는 절차 안내만 |

## 2. 관리자 역할·권한

| 역할 | 하는 일 | 사용자 데이터 열람 |
| --- | --- | --- |
| 최고 관리자 | 관리자 계정·권한, 발송·약관·버전 최종 승인, 예외 절차 승인 | L1까지, L2는 승인만(직접 열람 안 함) |
| 운영 | 공지·알림 캠페인 작성, 콘텐츠 관리, 앱 버전·점검 설정 | L0 |
| CS | 문의 처리, 계정 조치, 환불 실행, L2 열람 요청 | L1, L2(사용자 동의 시) |
| 분석 (읽기 전용) | 대시보드 조회, 지표 점검 | 집계만. 개별 회원 화면 접근 불가 |

조회 = 화면 보기, 수정 = 콘텐츠·설정 작성, 실행 = 사용자에게 영향이 가는 조치(발송·환불·로그인 수단 이전 등), 승인 = 실행 전 2인 확인.

## 3. 관리자 계정 보안

| 항목 | 기준 |
| --- | --- |
| 로그인 | 사내 SSO 필수. SSO 도입 전에는 회사 이메일 + 2단계 인증(인증 앱 OTP) 필수, 문자 인증 불가 |
| 접속 위치 | IP 허용 목록(사무실·회사 VPN)만. 목록 밖 접속은 로그인 화면 전에 차단 |
| 세션 | 30분 무활동 시 만료, 최대 8시간 후 재로그인. 계정당 동시 세션 1개 |
| 재인증 | L2 열람, 환불, 발송 실행, 권한 변경 직전 2단계 인증 다시 요청 |
| 계정 발급 | 개인별 계정만(공용 계정 금지), 역할은 업무에 필요한 최소 1개부터 |
| 권한 부여·회수 | 요청 → 최고 관리자 승인 → 적용, 전 과정 감사 로그. 퇴사·이동 당일 회수, 90일 미접속 계정 자동 잠금 |
| 정기 점검 | 분기 1회 계정·역할 목록 점검(최고 관리자), 결과 기록. 월 1회 L1·L2 열람 기록 점검 |
| 내려받기 | 회원 목록 엑셀 내려받기는 L0 항목만, 사유 입력 + 감사 로그 + 파일에 내려받은 관리자 ID 표시 |
| 화면 보호 | 회원 상세 화면은 복사 방지 |

## 4. 메뉴 구조

메뉴: 대시보드 / 회원 (조회·열람 요청·계정 조치) / 문의 / 구독·결제 / 발송 (공지·알림 캠페인) / 콘텐츠 (목표 템플릿·챙길 날·가이드·약관 버전·계산·기준 데이터) / 시스템 (앱 버전·감사 로그·관리자 계정). FAQ·가이드·약관 본문, 릴리스 노트, 연간 고정 지출 그림은 저장소에서 코드 배포로 관리(어드민 편집 없음). 화면별 기능·문구·출시 범위는 → 어드민 화면.

## 5. 운영 시나리오

**“배우자 연결이 안 돼요”**

1. AD-02 이메일로 문의자 찾기 → AD-03 초대 코드 상태 확인
2. 만료(7일 경과): S-12에서 초대 코드 재발급 안내
3. 배우자가 이미 다른 부부 공간 소속(공간당 최대 2명): 배우자 본인이 그 공간을 정리해야 한다고 안내, 운영자가 연결·해제 처리 안 함
4. 사용됨인데 연결 안 보임: 두 계정의 동기화 상태·앱 버전 확인 → 최소 지원 버전 미만이면 업데이트 안내, 그 외는 개발 확인 요청(문의 번호 첨부)

**환불 요청**

1. AD-08에서 결제자 본인인지 확인(결제는 결제한 사람만 조회·환불 요청 가능)
2. 이용약관 환불 기준 확인 → 기준 안이면 CS 실행, 밖이면 최고 관리자 승인
3. 환불 실행 → 해당 부부 공간 프리미엄 종료 시점 안내(배우자도 함께 무료로 전환)
4. 답변 템플릿으로 완료 안내, 처리 기록은 법정 보관

**계정 삭제 후 복구 요청**

1. AD-03에서 삭제 유예 여부·남은 일수 확인
2. 30일 안: “같은 계정으로 다시 로그인하면 계정 삭제를 취소할 수 있어요” 안내. 운영자 조치 없음
3. 30일 지남: 복구 불가 안내. 서버 백업에서 개별 계정 복원 안 함(백업 30일 자연 소멸, 보안·개인정보 3-3)
4. 연결 상태에서 삭제했던 경우 상대는 이미 ‘혼자 쓰기’. 30일 안 복구했으면 복구한 사람도 ‘혼자 쓰기’이고 30일 안 S-12 “다시 연결하기”로 재연결 안내, 그 뒤면 새 가입 후 초대(S-12)

**“소셜 계정을 잃어버려 로그인할 수 없어요”**

1. AD-02로 문의자 찾기 → AD-03 로그인 수단 확인. 먼저 해당 제공자(카카오·구글·애플)의 계정 복구 안내
2. 복구 불가면 본인 확인: 가입 이메일로 보낸 확인 메일 회신 + 금액이 아닌 계정 정보(가입 시기·이름(애칭)·부부 상태) 일치
3. 확인되면 사용자가 새 소셜 계정으로 로그인 → AD-05에서 기존 계정에 새 로그인 수단 연결·이전 수단 해제(최고 관리자 승인). 전체 기기 로그아웃 + 가입 이메일로 완료 알림
4. 확인 안 되면 이전 안 함, 새 가입 안내. 모든 단계 감사 로그

**약관 개정**

1. 저장소 마크다운에 전문 반영(코드 배포) → AD-15 새 버전 등록(버전 번호, 시행일, 재동의 요구 여부) → 법률 검토 확인 → 최고 관리자 승인
2. 시행 전 고지: AD-10 필독 공지 + AD-10 이메일(서비스 고지라 마케팅 동의 무관, 상한 밖). 고지 기간은 법률 검토 결과 따름(통상 7일, 불리한 변경 30일)
3. 시행일 이후 첫 실행 때 재동의 화면(재동의 필요 버전만)
4. AD-15 동의 현황으로 미동의 사용자 수 확인

**“배우자가 연결을 끊어서 데이터가 사라졌어요”**

1. 개입 안 함 원칙 안내: 연결 해제는 앱 절차(요청 → 상대 확인 또는 14일 뒤 확정, S-12)로만 진행. 확정되면 같이 쓰던 데이터는 나누지 않고 모두 지워짐(→ 핵심 규칙 › 부부·권한 7장). 운영자는 지운 데이터를 열람하거나 따로 돌려줄 수 없음
2. 해제 확정 전이면 S-12a·S-12d ‘먼저 내보내기’(S-18)로 받을 수 있다고 안내. 확정 후 30일 안이면 두 사람이 다시 연결해야 복구된다고 안내(S-12 “다시 연결하기”), 30일이 지나면 복구 불가

**1등급 장애 뒤 고지**

1. 복구 후 AD-10으로 영향받은 부부에게 장애 고지 메일 + 앱 공지 띠(서비스 메일이라 메일 상한 밖, 마케팅 동의 무관)
2. 시간·영향·현재 상태만 적고 금액·항목명은 넣지 않음(문구 → 화면 설계 › 알림 ‘장애 고지’)

## 6. 출시 범위

화면별 출시 범위는 → 어드민 화면 요약 표, 제품 전체 MVP는 → 제품 개요 MVP. 환불 기준 등 미정 사항은 → 사업 계획 › 결정 필요.
