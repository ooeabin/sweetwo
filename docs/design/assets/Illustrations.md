#### 움직이는 그림 그림체 기준(2026-11-09)

2026-11-09 사용자 레퍼런스: 포인트 받기 축하 화면(평면 동전 + 물방울 조각이 퍼지는 모양). 레퍼런스 그림은 저장소에 넣지 않음.

- 주인공: 평면 2D 물건 하나를 가운데에(자리에 따라 동전, 저금통, 하트, 달력 등). 외곽선 없음. 평면 채움 + 같은 색의 밝은 단계로 대각선 광택 띠 하나(살짝 입체감). 3D 렌더 없음, 광택 띠 말고 그라데이션 없음.
- 색: 물건은 브랜드 오렌지 계열(`brand` 바탕, 광택 띠는 그보다 밝은 단계, 물건 위 기호는 `brand-ink`). 조각은 브랜드 계열 2~3단계 + 강조색 많아야 하나(레퍼런스는 파란 물방울 하나, 우리는 `ink`나 `goal` 모래색 중 하나). 다크 모드는 브랜드 다크 값.
- 조각: 끝이 가는 물방울·꽃잎 모양 6~8개가 물건 둘레로 퍼짐. 거리, 크기, 기울기는 제각각, 몇 개는 반투명.
- 움직임:
  - 물건이 톡 나타남: 크기 0 → 1.08 → 1, 약 300ms, 살짝 넘쳤다 돌아오는 ease-out. 동전처럼 생긴 물건은 Y축으로 한 바퀴(약 600ms) 돌아도 됨.
  - 조각은 가운데에서 바깥으로 터지며 나타나고, 조금 흘러가다 자리 잡음. 전체 약 1.2초.
  - 한 번 재생하고 마지막 장면에서 멈춤. 반복 없음.
  - ‘동작 줄이기’면 마지막 장면만.
- 크기와 형식: DESIGN.md ‘움직이는 그림’ 규칙 그대로(96px 이상 주인공 자리, 화면당 1개). 조각이 들어가게 캔버스는 물건 크기의 약 2배, 바탕 투명. 형식은 지금 규칙대로 한 번 재생하는 움직이는 WebP(`packages/ui/src/assets/motion/`, 같은 이름의 정지 WebP와 짝).
- 바탕: 레퍼런스는 주인공 뒤에 옅은 민트 → 흰색 그라데이션이 있음. 우리는 2026-11-09 사용자 승인으로 축하 화면 배경 규칙(DESIGN.md ‘색’ 예외, CLAUDE.md 브랜드 색)을 따름: 화면 위 40~50%만 `brand-soft`(위) → `surface`(아래) 세로 그라데이션, 경계 없음, 다크는 다크 값, 위 글자는 `ink`. 클래스 `hg-celebrate-bg`(화면 틀에 붙임). 그림이 들어올 때 붙이고 지금은 어느 화면에도 붙이지 않음.
- 배경을 쓸 화면(움직이는 그림 자리가 있는 축하·보상 화면만): W-12 다 모았어요(`celebrate`), W-02 끝 월급 체크 다 했어요(`celebrate`), O-60 준비 끝(`done-check`), P-11 합류 완료(`scene-clap`). 움직이는 그림 자리가 있어도 축하가 아닌 P-01 초대받은 첫 화면, S-18 처리 중, F-04b 팔았어요는 쓰지 않음.

### 3. 코드에 붙이기

- 정지 그림: 파일만 넣으면 됨(`Illustration`, `hasIllustration`).
- 상태 이모지: AuthLayout에 `art`(이모지 이름) 받기 → 96px 그림, 아이콘 원 대신. 지금 `icon`은 그림이 없을 때 대신 씀.
- 움직이는 그림: 새 ui 컴포넌트 `MotionArt`(움직이는 webp + 정지 webp). ‘동작 줄이기’면 정지 그림, 화면당 1개, 64px 미만에서는 정지. 1번 재생은 움직이는 webp를 반복 없이(loop 1) 만들어서.
- 문서: Illustrations 표(새 그림 설명), DESIGN.md ‘그림’, 컴포넌트 md(AuthLayout, Celebration, EmptyState, GoalPick), 기획서 화면 표에서 그림 문구가 바뀌면 그 화면 ID 부분.

### 4. 확인

- 56px·40px에서 알아보이는지, 다크 바탕에서 가장자리 지저분함 없는지, 세트로 늘어놓았을 때 빛 방향·채도가 같은지.
- 휴대폰(좁은 창)·태블릿(넓은 창) 캡처로 화면마다 확인, 용량 합계(정지 30장 + 움직임 8개) 앱 번들 한도 안.
