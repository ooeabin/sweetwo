# QuestionLayout

한 화면 한 질문 틀. 온보딩·배우자 합류·결혼일 전환·목표 추가·월말 확인이 모두 이 틀.

- 소비자가 주는 것: 진행 칸 수와 현재 칸, 질문 제목, 보조 1줄(선택), 입력 영역, 주 버튼 글자.
- 주 버튼 자리는 대답 성격이면 회색 보조(`primary.variant: 'secondary'`, 2026-11-03): O-21 목표를 하나도 안 골랐을 때 “나중에 고를게요”. 크기와 자리는 주 버튼과 같음.
- 되돌릴 수 없는 삭제(S-18b 계정 삭제, 2026-11-04)는 `primary.variant: 'danger'`(빨간 버튼, 크기와 자리는 주 버튼과 같음). 누르면 확인 대화상자(Modal)를 먼저 띄우고, 대화상자가 열려 있는 동안 Esc는 대화상자만 닫음(뒤로 가기 없음).
- 질문이 아니어도 아래 꽉 찬 주 버튼이 필요한 짧은 입력 화면도 이 틀을 씀(2026-11-04 S-11b 알림 이메일, S-19a 문의하기).
- 주 버튼 옆 회색 보조(`secondary`, `hg-q__second`, 2026-11-03): 왼쪽에 회색 ‘취소’ 같은 대답 버튼, 좁은 창에서는 주 버튼과 반씩. P-01 ‘이미 시작한 기록이 있어요’.
- 좁은 창(모바일 앱): 위에 진행 막대(ProgressSteps, 글자 없음)를 열 너비 그대로, 그 아래 뒤로 꺾쇠(왼쪽 끝을 열 가장자리에 맞춤). 가운데 480px 한 열.
- 넓은 창(데스크톱 앱, 창 최소 960px라 데스크톱은 늘 이 모양. 레퍼런스 Meetup, Calendly, Perplexity):
  - 위 바 `hg-qbar`(64px, 위에 붙음): 왼쪽 워드마크(24px), 가운데 진행(360px), 오른쪽 비움. 진행은 온보딩이면 “목표” + 칸 막대(`hg-segs`: 챕터 안 질문마다 1칸, 연 질문까지 `brand`, 칸 높이 4px, 사이 4px), 그 밖은 ProgressSteps.
  - 헤더 꺾쇠(`hg-q__nav`)는 숨김.
  - 아래 바 `hg-q__foot`(아래에 붙음, 위에 `hairline-soft` 선 1줄을 창 너비로): 왼쪽 “‹ 이전”(고스트 버튼 `hg-q__prev`), 오른쪽 ‘나중에 할게요’ 링크 → “Enter 키를 눌러도 돼요”(13px `stone`, `hg-q__hint`, 주 버튼이 있을 때만) → 주 버튼(글자 길이만큼, 최소 120px). 버튼 자리는 열(480px, 넓은 결과 960px)의 양 끝.
  - Q1(주 버튼 없음)도 아래 바에 ‘이전’만. 좁은 창에서는 이 바를 숨김(`is-backonly`).
  - 온보딩은 `chapter`를 주면 ProgressSteps 대신 ChapterBar: 뒤로와 “목표”가 한 줄, 그 아래 챕터 안 막대(brand).
- 뒤로(‘<’)가 없는 화면도 좁은 창에서 그 자리(36px)를 비워 두어 제목 높이를 맞춤(`hg-q__back-space`, 2026-11-02). PIN(LockScreen) 제목도 같은 높이.
- 제목 `hg-q__title`(24px 700, 레퍼런스 질문 화면 크기, 낱말 중간에서 끊지 않음 `keep-all`), 보조 1줄 `hg-q__help`. 제목 묶음과 입력 사이 40px(`space-6` 간격 + `space-4`). 입력(AmountInput, Field 등)은 열 너비를 꽉 채워 주 버튼과 양옆을 맞춤.
- 약관 동의(A-05) 좁은 창: 동의 묶음(`hg-consent`)은 제목 바로 아래부터(카카오톡, 현대카드처럼, 2026-11-02). 주 버튼만 화면 아래 끝.
- 아래 `hg-q__foot`: ‘나중에 할게요’ 링크(허용된 곳만) + 주 버튼. 좁은 창은 주 버튼이 열 너비를 꽉 채움(O-01, A-02 버튼 묶음과 같음). 좁은 창 주 버튼은 내용이 짧든 길든 늘 화면 아래 끝에서 16px(틀 아래 여백 없이 바 여백만), 넓은 창은 위 아래 바.
- 주 버튼은 틀의 아래 끝. 질문마다 내용 길이가 달라도 버튼은 같은 자리.
  - 좁은 창(768px 미만): 틀이 화면 높이를 채우고 주 버튼은 화면 아래 끝. 내용이 길면 스크롤하는 동안 아래에 고정(`position: sticky`).
  - 넓은 창: 아래 바가 창 아래 끝에 붙고, 내용이 길면 스크롤하는 동안에도 아래에 남음.
- 안내 화면 `hg-q--center`: 입력 없이 제목, 보조, 버튼만 있는 화면(합류 대기, 파트 시작 안내, 첫 미션, 분석 중 등). 제목과 보조를 가운데 정렬하고 세로 가운데에 둠. 제목 묶음이 열(좁은 창은 화면) 세로 가운데이고 버튼은 아래 끝(O-01 시작, A-02 로그인 좁은 창과 같은 배치). 진행 막대와 뒤로는 위에 그대로.
  - 입력 영역(children)이 없으면 저절로 이 배치. 입력은 없지만 짧은 표시(진행 막대 등)가 있는 화면은 `center`로 켬.
  - 입력이 있는 질문 화면은 제목을 위쪽 왼쪽에 그대로 둠(버튼만 아래 끝).
- Enter = 다음, Esc = 뒤로.

## 결과 화면

- 같은 틀의 넓은 모양 `hg-q--wide`(960px, `wide`): 예전 온보딩 결과(O-61\~67, 재기획으로 없앰)에서 쓰던 모양. 지금 쓰는 화면 없음.
- 본문은 `hg-q__cols` 2열: 왼쪽 결론·조정, 오른쪽 근거·목록. 768px 미만은 1열, 주 버튼 하단 고정(위와 같음).
- 결론 문장(제목) 먼저, 숫자 카드(`hg-cards` + `hg-card`)는 아래. 금액은 만 원 단위.
- 버튼 위 요약(`summary`, `hg-q__sum`): 주 버튼 바로 위 한 줄(16px 600 `ink`, 보조는 `hg-help`). 아래 바와 같이 붙어 있어 목록이 길어도 보임. 바뀌면 화면 읽기가 읽음(`aria-live`). 쓰는 곳: W-01 ‘남는 돈’. 좁은 창에서는 요약이 있는 아래 바 위에 `hairline-soft` 선을 둬 목록이 그 밑으로 지나가는 게 보임(2026-11-02).
- 제목 위 주인공 자리(`hero`, `hg-q__hero`): 그림이나 완료 표시(DoneMark). 가운데 배치(`center`)와 같이 쓰면 hero + 제목 묶음이 세로 가운데. 쓰는 곳: O-60 준비 끝(DoneMark + 해 둔 것 목록 `hg-intro-steps`), F-04b 팔았어요, W-02 끝.
- 아래로 내리는 묶음(`hg-q__end`, 2026-11-05): 가운데 배치에서 요약 판(InfoPlate) 같은 것을 버튼 바로 위로. 그림 + 제목은 그 위 남은 자리의 세로 가운데. 쓰는 곳: W-02 끝(폭죽 → 제목 가운데, 저금 요약과 배우자 진행은 아래). 가운데 배치 안 띠(`hg-banner`)는 글자 왼쪽 정렬
- 안내 화면 단계 목록(`hg-intro-steps`, O-10): 가운데 배치 제목 아래 회색 판(`plate`, `radius-xl`) 위 아이콘 원(40px 흰 원) + 한 줄(16px 500)씩 3줄. 배민 커넥트, GCOO 시작 화면처럼(2026-11-02).
- 버튼 위 안내(`note`, 2026-11-03): 아래 고정 영역 맨 위에 가운데 정렬 한 줄(`hg-q__note`, 13px `slate`). 요약(`summary`)과 달리 선 없음. 쓰는 곳: S-11e, G-02p ‘올린 사진은 …’.
- 좁은 창 아래 고정 영역 위 흐림(2026-11-03): 목록이 버튼 영역 밑으로 지나갈 때 잘려 겹쳐 보이지 않게 위쪽 24px을 바탕색으로 흐리게(`::after` 그라데이션). 요약 줄 위 선은 없앰.
