# AuthLayout

로그인, 가입 화면 틀(`hg-auth`). A-01 실행, O-01 시작, A-02 로그인 방법, A-03 브라우저 대기, A-08 세션 만료. 질문 하나를 받는 A-04, A-05, A-06 설정은 QuestionLayout.

- 소비자가 주는 것: 장면 자리(선택, SceneMedia, 지금은 비어 있음), 상태 그림 자리(선택), 제목, 보조 1줄(선택), 안내 띠(선택), 버튼 묶음, 뒤로(선택), 아래 안내 1줄(선택).
- 가운데 한 열, 글자 가운데 정렬. 제목 `hg-auth__title`(`title-1` 22px/30px 700, 2026-11-10 24에서. 히어로 캐치프레이즈는 20px 그대로, 줄바꿈 `\n` 그대로, 낱말 중간에서 끊지 않음 `keep-all`), 보조 `hg-auth__help`.
- 글자 링크(`hg-btn--link`, ‘업데이트 없이 보기만 할게요’ 등)는 오렌지가 아니라 `slate`(2026-11-09 다른 화면 글자 버튼은 `ink-2`). O-01 ‘코드 입력하기’만 `ink` 700 밑줄(당근 ‘로그인’ 링크처럼 눈에 띄게).
- 상태 그림 `art`(2026-11-05): Illustrations 이름을 주면 제목 위 96px `hg-auth__art`(원 판 없음, ‘동작 줄이기’가 아니면 한 번 톡 커짐). 그림 파일이 아직 없으면(2D 그림 ‘나중 과제’) 같은 크기·모양의 회색 빈 자리(`hg-artslot`: `surface-alt` + 안쪽 1px `hairline-soft`, 96px 둥근 네모 `radius-lg`, `aria-hidden`). 그림은 나중에 만들어 그 자리에 넣음.
  - 2026-11-10 사용자 결정: 같은 날 오전에 붙였던 Phosphor 아이콘 원(`hg-auth__icon`, AuthLayout `icon`·`busy`)을 없애고 모든 상태 화면을 회색 빈 자리로 되돌림. 작은 UI 아이콘(안내 띠의 ⓘ, 버튼 안 마크)은 Phosphor 그대로.
  - 이름: A-01 업데이트 `status-update`, 점검 `status-maintenance`, 오프라인(로그인 전) `status-offline`, 실행 오류 `status-error`, A-02 계정 삭제 취소 `status-restore`, A-03 브라우저 대기 `status-wait`(2026-11-10 새, 도는 아이콘 대신), 브라우저 열기 실패 `status-error`, A-06 Face ID `status-faceid`, Touch ID·지문 `status-fingerprint`, A-08 세션 만료 `status-lock`, 새 기기 `status-newdevice`, A-07 합류 불가(QuestionLayout `hero`에 같은 96px 자리) `status-invite-blocked`(만료·잘못된 코드·제한·이미 연결 등 한 장, 2026-11-10 새), A-07 불러오기 실패 `status-error`(오프라인 `status-offline`). 목록과 크기는 Illustrations ‘나중 과제’ 1번. 상태 화면 머리에 워드마크는 두지 않음.
- 안내 띠 `hg-auth__alert`(2026-11-02 당근 안내 상자): `plate` 바탕, `radius-lg`, 안쪽 12px 16px, `info` 16px `ink-2`(첫 줄에 맞춤) + 13px `ink-2` 글자, 최대 360px, `role="status"`. 버튼 묶음 바로 위. 상황이 풀릴 때까지 남는 안내만: 오프라인, 다시 로그인해 주세요(요청 불일치), PIN 5번 틀림, PIN을 잊었어요 뒤 “다시 로그인하면 새 PIN을 정할 수 있어요”, A-01 판단이 10초 넘음 “연결이 느려요” + 글자 버튼 ‘다시 시도’(스플래시 아래). 2026-11-10 ‘업데이트를 받지 못했어요’ 띠는 없앰(기획서에 없음, 버튼이 ‘다시 시도’로 바뀌는 것만).
- 버튼 위 알약 토스트 `hg-auth__toast`(포켓CU): 결과만 알리는 안내(로그인 취소, 제공자 오류, 시간 초과)는 버튼 묶음 위 16px에 `ink` 알약(14px 500)으로 4초 떴다 사라짐. 자리를 차지하지 않아 화면이 흔들리지 않음. 아래 버튼을 가리지 않으려고 전역 Toast 대신 씀.
- 두 갈래 질문(A-06 Face ID 켜기): 버튼 두 개를 가로로(`hg-auth__actions--row`, 보조 ‘나중에 할게요’ 1 : 주 2). 현대카드 ‘다음에 | 설정’.
- 버튼 묶음 `hg-auth__actions`: 세로로 쌓고 최대 360px. 버튼은 꽉 차게(`hg-btn--block`). 상태 화면의 ‘다시 시도’는 모두 주 버튼(2026-11-10, 화면마다 색이 다르던 것).
- A-03 로그인 중인 방법 `hg-auth__provider`(2026-11-10, `media` 자리): 그림 자리와 제목 사이에 제공자 마크 20px + “카카오로 로그인”(14px 600 `ink`). 좁은 창에서 그림 자리 + 이 줄 + 제목이 한 묶음으로 세로 가운데.
- A-01 스플래시 `hg-auth--splash`(2026-11-10): 워드마크 40px를 화면 한가운데(가로·세로)에. 0.3초 넘으면 그 아래 40px에 진행 막대(88×4px `hg-skel`), 10초 넘으면 ‘연결이 느려요’ 띠는 화면 아래(아래 32px + 안전 영역). 막대와 띠는 자리를 차지하지 않아(`position: absolute`) 워드마크가 움직이지 않음. 그림 자리 없음.
- 워드마크는 번들 안 data: URL(`logo-cherry.svg?inline`, 2026-11-10)이라 오프라인·첫 그리기에도 네트워크 없이 보임.
- 뒤로 `hg-auth__back`: 왼쪽 위(안전 영역 안쪽). 좁은 창과 태블릿(터치)은 IconButton `chevron-left`(뒤로 버튼은 `hg-back` 하나로 통일(2026-11-10: 40px 누르는 자리, `chevron-left` 24px `ink`, 좁은 창에서 아이콘 칸 왼쪽이 화면 왼쪽 16px. IconButton.md ‘뒤로’)), 마우스·트랙패드가 있는 넓은 화면(`(min-width: 768px) and (hover: hover) and (pointer: fine)`, 개발 브라우저)은 고스트 버튼 “‹ 이전”(`backLabel`, A-02는 “‹ 처음으로”). 이 글자 뒤로는 질문 화면 넓은 창 위 바(64px)와 같은 줄: 위 12px, 왼쪽 24px(2026-11-10).
- 안전 영역(2026-11-10): `hg-auth` 안쪽 여백에 `env(safe-area-inset-*)`를 더함(노치, 홈 막대, 가로 화면 옆). 잠금 화면(`hg-lock`)도 같음.
- 좁은 창(768px 미만)과 태블릿(터치, `(hover: none)` 또는 `(pointer: coarse)`, 2026-11-10): 같은 배치(가운데 휴대폰 너비 열). 상태 화면은 그림 자리 + 제목을 묶어 세로 가운데, 버튼 묶음(위 안내 띠 포함)은 아래 끝으로. 머리 자리에 아바타(`hg-avatar`)를 두면 아바타+제목을 묶어 세로 가운데로(A-02 초대로 들어왔을 때).
- 태블릿(터치) 크기(2026-11-11): 2026-11-11 태블릿(터치) 한 단계 크게: 열 480px(로그인 버튼 묶음·안내 띠 360 → 480), 제목 24/32(휴대폰 22/30 그대로), 본문·보조·캡션·버튼 글자 한 단계 위(15 → 16, 13 → 14, 12 → 13, 14 → 15), 입력 칸 56px·17px, 선택지 카드 72px, 빠른 금액 칩 48px, 주 버튼 56px, 휠 글자 20·22px(줄 높이 44px 그대로), 세로 간격 한 단계 넓게(질문 묶음 사이 32px, 제목과 입력 사이 48px), 제목 묶음은 진행 막대 아래 10vh(24~120px) 띄워 화면 위 3분의 1쯤에. PIN·잠금은 제목 위 14vh(72~128px). 휴대폰(768px 미만)과 마우스 넓은 창은 그대로(`bundle.css` ‘태블릿(터치)’ 묶음). 히어로(O-01·A-02)의 20px 문구는 그대로.
- 입력이 있는 화면(P-01 코드 직접 입력)은 입력 칸(`hg-field`)과 주 버튼을 함께 버튼 묶음 안에 둔다(좁은 창에서 같이 아래로).
- 소셜 버튼 왼쪽에 제공자 마크 `ProviderMark`(`hg-btn__mark`, 20px)를 글자 앞에 둔다.
  - 카카오는 공식 노란 브랜드 버튼 `hg-btn--kakao`(바탕 `#fee500` + 글자 `rgba(0,0,0,.85)`, 라이트·다크 모두 노랑). 마크는 말풍선 심볼로 `currentColor`(버튼의 어두운 글자색)를 따른다.
  - 구글은 `hg-btn--secondary`(테두리), 마크는 4색 G(고유색 그대로). 애플은 채움 `hg-btn--apple`(2026-11-10, 라이트 검정 바탕 + 흰 글자·마크, 다크 반대, 마크는 `currentColor`).
  - 제공자 색(카카오 노랑, 구글 4색)은 워드마크 SVG처럼 토큰 예외다. 그 밖의 버튼은 디자인 토큰만 쓴다(→ 개발 가이드 ‘OAuth 앱과 리다이렉트’).
- 히어로 배치 `hg-auth--hero`(AuthLayout `className`): 워드마크 40px + 캐치프레이즈 제목 한 줄(20px 700) + 보조 2줄(`hg-auth__help` 14px/20px `slate`, 2026-11-10 15px에서, A-02 초대 문구일 때는 없음)을 한 묶음으로, 좁은 창(768px 미만)은 위에서 화면 높이 30%(최소 64px)에 고정해 O-01과 A-02에서 같은 높이(버튼 수가 달라도 튀지 않게), 버튼은 아래 끝(2026-11-02 당근 시작 화면처럼). 768px 이상(태블릿 터치·마우스 모두, 2026-11-10): 버튼을 아래 끝에 두면 태블릿 세로에서 문구와 버튼 사이가 400px 넘게 비어, 워드마크 + 문구 + 버튼을 한 묶음으로. 워드마크는 화면 가운데 − 176px(`space-22` × 2, 최소 64px)에 고정해 O-01과 A-02가 같은 높이, 버튼은 문구 아래 64px(간격 24 + 40, 버튼 위 토스트·말풍선 자리). A-02 초대(아바타 머리, `hg-auth--login`만)도 같은 높이·간격. 오프라인 띠는 버튼 바로 위 같은 자리. O-01은 보조 버튼 없이 주 버튼 아래 한 줄 `hg-auth__alt`(13px `slate` “초대를 받았나요?” + 글자 링크 ‘코드 입력하기’). O-01 시작·A-02 로그인이 같은 배치로 쓴다. O-01도 그림 자리 없이 A-02와 같은 워드마크 히어로(2026-11-10 워드마크 위 `scene-start` 빈 자리 없앰).
- A-02 로그인 전용 `hg-auth--login`(히어로와 함께 건다): 소셜 버튼은 마크를 버튼 왼쪽에 고정하고 글자는 가운데·굵기 700. 구글(`hg-btn--secondary`)은 로그인에서 회색 채움 대신 중간 회색 테두리 버튼(바탕 투명)으로 둔다. 카카오 마크는 살짝 키운다(24px, 다른 마크는 20px). ‘최근 사용’은 버튼 안 배지(`hg-tag`)가 아니라 해당 버튼 위 오른쪽 말풍선 `hg-auth__recent`(꼬리 아래)로 둔다. 소셜 버튼 왼쪽 마크는 이 변형에서만 왼쪽 고정이고, 기본(다른 화면)은 글자 앞에 두는 평소 배치 그대로.
